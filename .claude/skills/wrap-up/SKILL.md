# wrap-up

1. `git status`/`git diff`로 이번 변경 범위를 3줄로 요약한다.
2. 다른 에이전트가 고친 코드는 실행하기 전에 변경분을 먼저 읽는다(특히 프로세스를 끝내거나 파일을 지우는 코드). 그다음 `AGENTS.md`의 검증 명령으로 테스트한다.
3. `/code-review`를 변경분에 실행하고, 확실한 문제만 고친다(범위를 넓히지 않는다).
4. 문서 일치를 확인한다: 바뀐 동작이 README·AGENTS.md·관련 스킬·`DECISIONS.md`(있으면)와 맞는지 보고 어긋난 문장만 고친다.
5. 사용자가 앱에서 눌러 볼 것을 번호 목록으로 준다. 화면 변경이면 임시 서버(`node browser-fixture.js`, 4322 포트, 임시 데이터) 주소와 함께 준다.
6. 운영 반영 상태를 구분해 알린다: 화면 파일은 저장 즉시 반영됨 / `server.js` 등 서버 코드는 운영 서버 재시작 후 반영 / `automation/` 스크립트는 설치본 복사 후 반영.
7. 커밋·푸시·재시작은 하지 않는다. 대신 커밋 단위 제안과 메시지 초안(무엇을·왜·보류한 것)을 보여 주고 사용자의 요청을 기다린다.
