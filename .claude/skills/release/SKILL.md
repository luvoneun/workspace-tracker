# release

자세한 규칙은 AGENTS.md(만드는 방식 — 배포 전)·`docs/배포-점검.md`·`release.sh`가 기준이다. 여기에는 순서와 문체만 적는다.

1. **바뀐 것 모으기** — `git describe --tags --abbrev=0`로 지난 태그를 찾고 `git log <태그>..HEAD --oneline`을 읽는다. 커밋 수가 많으면 기능 단위로 묶는다(구현·시험·문서 커밋은 하나로).
2. **버전 번호** — 새 기능이 있으면 둘째 자리(1.6.1 → 1.7.0), 고침만 있으면 셋째 자리. 추천 하나를 말한다.
3. **소식 쓰기(`소식.md` 맨 위, `## vX.Y.Z · 날짜`)** — 3~5줄.
   - 쓰는 사람이 화면에서 느끼는 변화만. 코드·시험·구조 이야기는 뺀다.
   - 한 줄에 하나, 짧게. 설명·조건·이유는 빼고 "무엇을 누르면 무엇이 된다"까지만(사용자 선호: "더 간단하게").
   - 해야 할 일이 있으면 그 줄 끝에 같이(예: "… — 설정 › 연동에서 다시 연결해 주세요"). 없으면 적지 않는다.
   - 해요체. 실제 이름·회사 정보 없음(공개 저장소).
   - 먼저 사용자에게 보여 주고 고칠 곳을 받은 뒤 커밋한다.
4. **배포 점검 고르기** — `docs/배포-점검.md`에서 이번 변경에 닿는 항목만 3~5개 골라 "사용자가 직접 볼 것"으로 준다(새 계정·동료 맥에서 하는 항목은 조율이 대신 못 한다고 밝힌다). 실제 지라·실제 데이터로 확인 못 한 것은 그렇게 적는다.
5. **부하 확인** — `uptime`의 load average가 5를 넘으면 시험이 시간 초과로 실패하기 쉽다. 다른 세션·무거운 프로그램이 도는지 보고, 높으면 기다리거나 사용자에게 알린다(시험을 건너뛰는 길은 쓰지 않는다).
6. **릴리스** — 소식을 커밋한 뒤 `bash release.sh X.Y.Z`(푸시 없이)를 백그라운드로 돌린다. 시험·VERSION·커밋·태그까지 이 맥 안에서만 일어난다. 실패하면 실패한 시험 이름을 보고, 시간 초과뿐이면 부하 탓인지 단독 재실행으로 구분해 알린다.
7. **푸시** — 사용자가 "푸시해"라고 할 때만 `git push origin main --tags`. 앱 알림·받은함 '봤어요'는 푸시 승인이 아니다. 푸시 뒤 `git ls-remote --tags origin`으로 태그가 올라갔는지 확인하고, 받은함에 `report`(tell)로 한 줄, 장부에 한 줄.
8. **배포 뒤** — 1~2시간 동료 반응을 보라고 한 줄 알리고, 문제가 생기면 `docs/배포-점검.md` 맨 아래 "배포 뒤 고장 났을 때"를 따른다(이미 푸시한 태그는 다시 쓰지 않고 새 번호로).
