# review-request

규칙의 기준은 AGENTS.md(만드는 방식 — 구현·검수)와 조율 점검표다. 여기에는 순서와 중점 틀만 적는다.

## 1. 검수 크기 고르기
- **직접 diff 읽기(서브에이전트 없이):** 파일 3개 이하·수십 줄, 또는 이미 한 번 검수한 뒤의 고침분. `git diff main...<가지>`에서 안전장치 함수(request·showNotice·pushUndo·recordUndoFor·toggleTask·fadeOutAndRun·isClientFile·RECOVERY_NEEDED·uiRenderOrHold) 정의 hunk가 없는지 확인한다.
- **Opus 읽기 검수(`reviewer` 에이전트, model opus):** 그 밖의 화면·입력·데이터 쓰기 변경.
- **Codex 읽기 전용(`codex review --base main` — 프롬프트를 같이 주면 거절되니 붙이지 않는다):** 서버·스크립트·안전장치·업무 데이터 쓰기·외부 서비스 쓰기(지라 등)가 있을 때만. 샌드박스의 `listen EPERM` 실패는 코드 문제가 아니다.

## 2. 검수 지시문 틀
복사본 경로·가지·커밋·바뀐 파일을 적고, **"위험 순위를 먼저 적어라"**, 이전 검수에서 확인된 것은 반복하지 말고 **이번에 새로 만든 위험**에 집중하라고 쓴다. 변경 종류에 맞는 중점을 골라 붙인다.
- **업무 데이터 쓰기:** 부분 쓰기 0(한 트랜잭션)·중복 저장·실패 시 글 보존·되돌리기 기록·충돌(409)·지라 등 되돌릴 수 없는 쓰기 전 대조.
- **입력칸·클릭:** 한글 조합(compositionstart/end, isComposing)·다시 그리기로 칸이 새로 만들어지는지(`uiRenderOrHold` 밖인지)·초점·첫 클릭이 사라지는지(누름과 뗌 사이 시간이 있는 실제 순서)·저장 중 잠금이 풀리는지·안쪽 도구 버튼이 먹는지.
- **움직임:** 자동 갱신·폴링·창 처음 열기·탭 복귀 때 움직이지 않는지·움직임 줄이기(규칙 명시도까지)·숨은 탭·그림자 복사본(비밀 칸 값)·성능(강제 레이아웃 횟수).
- **외부 쓰기(지라 등):** 계정 id·토큰이 주소·로그·파일로 새는지·요청 하나에 쓰기 1번·권한 오류 문구·반영 여부를 모를 때 처리.
- 공통: 시험이 실제로 잡는지(빈 시험·글자 대조만·같은 틱 흉내), 구현자가 알린 "발견했지만 안 건드린 것"에서 사용자에게 보일 것, 같은 파일을 건드리는 다른 가지와의 충돌.
끝에 "막아야 함 / 고치면 좋음 / 참고", "딱 3개만 한다면", "발견했지만 안 건드린 것"을 달라고 한다. 코드는 고치지 말라고 한다.

## 3. 결과를 구현 세션에 보내기
- 한 메시지로 묶는다: **막아야 함**(반드시) → **고치면 좋음**(작으면 같이, 크면 '다음 후보'로 보고) → **안 고침**(이유 한 줄). 각 줄에 파일:줄과 재현 조건을 그대로 옮긴다.
- 사람 동작에 달린 지적(클릭·입력·움직임)은 "실제 마우스 속도·실제 한글 조합으로 먼저 재현해 보고에 적어"를 붙인다.
- 같은 파일을 바꾸는 다른 가지가 먼저 합쳐지면 `git rebase main` 시점을 같이 알린다.
- 고침 보고가 오면 고침분 diff를 직접 읽거나(작으면) 같은 틀로 재검수(크면)한 뒤 합치기 글(`node tools/merge-prompt.js …`)로 넘긴다. `--summary`에는 백틱을 쓰지 않는다.
