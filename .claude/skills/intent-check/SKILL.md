# intent-check

대상은 `$ARGUMENTS`다. 코드는 고치지 않는다.

1. 이 기능이 왜 있고 누가 어떤 상황에서 쓰는지, 이해한 대로 3줄로 말한다.
2. 근거와 추측을 구분한다. 근거는 강한 순서로 찾는다: 테스트 이름 → 코드 옆 주석 → `DECISIONS.md`(있으면) → 커밋 메시지(`git log -S<키워드>`) → README·스킬 설명. 근거 없이 짐작한 부분은 "추측"이라고 쓴다.
3. 이 변경으로 뒤집힐 수 있는 기존 결정(`DECISIONS.md`, 테스트로 고정된 요구사항)을 나열한다.
4. 사용자에게 확인할 질문을 3개 이내로, 예/아니오나 선택지로 답할 수 있게 만든다.
5. 사용자가 맞다고 확인하면 그때 계획을 세운다. 계획에는 닿는 파일, 동작이 바뀌는 변경과 구조만 바뀌는 변경의 구분, 검증 방법(테스트·4322 임시 서버에서 확인)을 넣는다.
6. 작업이 끝나면 배경을 커밋 메시지와 해당 코드 주석에 남긴다. 뒤집히면 안 되는 결정은 `DECISIONS.md`에 한 줄과 테스트로 남긴다.
