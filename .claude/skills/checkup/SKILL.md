# checkup

1. `AGENTS.md`를 먼저 읽는다(있으면 `DECISIONS.md`도). 이 점검은 읽기 전용이다: 파일을 고치거나 서버·스크립트를 실행하거나 커밋하거나 HTTP 요청을 보내지 않는다. 실제 업무 데이터(`tracker/*.md`, `tracker/.*`)는 열지 않는다.
2. 범위: `$ARGUMENTS`가 있으면 그 범위, 없으면 `git log`로 지난 점검 이후 커밋(모르면 최근 10개)을 본다.
3. 다음을 찾는다: 중복·죽은 코드나 기존 구조를 거스른 추가, README·AGENTS.md·스킬·에이전트 설명과 실제 동작이 어긋난 곳, 테스트 없는 새 동작, `DECISIONS.md`의 결정과 어긋나는 변경, `.claude/skills`·`.claude/agents` 파일이 40줄을 넘거나 AGENTS.md 내용을 복사한 곳.
4. 발견마다 적는다: `파일:줄` 근거(확인 못 했으면 "추측"이라고 표시), 분류(지금 실제 문제 / 규모가 커지면 문제 / 이론상 문제), 고치는 비용(작음·중간·큼), 안 고치면 생기는 일 한 줄. 개인용 도구에 과한 대책은 제안하지 않는다.
5. 범위가 넓으면 `reviewer` 에이전트에게 나눠 맡기고, 보고받은 핵심 주장은 직접 코드에서 다시 확인한 뒤 전한다.
6. 출력 순서: 결론 3~5줄 → 반드시 할 것 / 나중에 할 것 / 하지 않아도 될 것 → "딱 3개만 한다면"(순서와 노력) → 확인했는데 괜찮았던 것. 결론을 먼저 말하고 전문용어는 풀어서 설명한다.
