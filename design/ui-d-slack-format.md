# 슬랙 복사 형식 — 사용자 확정 (2026-09-22)

사용자가 실제로 슬랙에 올리는 보고 글의 구조(구역 `완료`/`예정` → 프로젝트 이름 한 줄 → 항목들, 필요하면 `이슈 : …` 부연, 프로젝트 없는 잡무와 `*메모`는 끝에)를 살리되, 워크스페이스 데이터에 맞춰 더 보기 좋게. 사용자 승인: "슬랙 복사 형식은 너 말에 동의. 구역 정하는 것도 좋다. 기본값은 완료/진행 중/예정. 글머리 추천 방식대로."

## 구조 (위에서 아래)
1. 첫 줄 제목: `9월 3주차 (9/21~9/27)` — 굵게, 이모지 없음.
2. 구역(상태) — 굵게, **대괄호로 감싸서**(`[완료]` `[진행중]` `[결정]` `[확인 대기]` `[예정]`, 2026-09-23 사용자 확정 — `진행 중`만 붙여 쓴다), 이 순서로, 고른 구역만, 내용이 없는 구역은 생략:
   | 화면·서버의 heading | 슬랙 구역 이름 |
   |---|---|
   | 완료한 일 (+ 확인 완료) | `완료` |
   | 진행중 | `진행 중` |
   | 새로 정해진 것 | `결정` |
   | 확인 대기 | `확인 대기` |
   | 다음 주 계획 | `예정` |
   `확인 완료`는 `완료` 구역 안에서 다른 항목과 같이 프로젝트 아래에 들어간다.
3. 구역 안: 프로젝트 이름(굵게) 한 줄 → 그 프로젝트의 문장들을 글머리(`•`) 항목으로. 프로젝트 순서는 문서(화면)의 순서와 같게, **프로젝트 없는 것은 `기타`로 그 구역의 맨 끝**. 같은 구역·같은 프로젝트의 문장은 머리 하나 아래로 모은다.
4. 문장이 여러 줄이면 첫 줄이 항목, 둘째 줄부터는 들여 쓴 작은 글머리(`◦`) 부연.
5. `예정` 구역: 프로젝트가 지정된 계획 문장은 프로젝트 아래 항목으로, 프로젝트 없는 계획 문장은 구역 끝에 `* 문장` 메모 줄로.
6. 제외한 문장은 빠진다(기존 규칙). 수정 중인 문장이 있으면 복사를 막는 기존 규칙 유지.

## 복사 방식
- **서식 있는 복사 + 일반 글자**를 함께: `navigator.clipboard.write([new ClipboardItem({'text/html': …, 'text/plain': …})])`. HTML은 `<p><b>제목</b></p>`, 구역 `<p><b>완료</b></p>`, 프로젝트 `<p><b>가입 개선</b></p>`, 항목 `<ul><li>…<ul><li>부연</li></ul></li></ul>` — 슬랙 입력창에 붙이면 굵은 글씨와 글머리 목록이 된다. `ClipboardItem`이 없거나 실패하면 기존 `writeText`(일반 글자)로, 그것도 막히면 기존 대체 경로(미리보기 글자 선택 + 안내).
- 일반 글자 형식(서식 없는 곳에 붙일 때, 그리고 테스트가 고정할 형식):
  ```
  9월 3주차 (9/21~9/27)

  [완료]
  가입 개선
  • 가입 실패율 급증 원인 파악
  • 퍼널 데이터 정리해 대시보드 반영
      ◦ 이슈: …
  결제 리뉴얼
  • 결제 실패 알림 슬랙 채널 공지
  기타
  • 주간 회의 자료 준비

  [진행중]
  알림센터
  • 발송 실패 로그 확인

  [예정]
  알림센터
  • 웹/앱 검수 처리 기획 진행 및 논의
  * 과금 기획은 차차주 진행 예정
  ```
  (구역 사이 빈 줄 하나, 프로젝트 사이에는 빈 줄 없음, 부연은 공백 4칸 + `◦ `.)
- 미리보기 카드(`슬랙에 붙이면`)는 슬랙에 붙었을 때의 모습(굵은 제목·글머리·들여쓰기)을 그대로 그린다. HTML·일반 글자·미리보기는 **하나의 구조(블록) 함수에서 파생**해 어긋날 수 없게 한다.

## 슬랙에 넣을 구역 고르기
미리보기 카드 위(또는 머리)에 조용한 체크 칩 `완료 · 진행 중 · 결정 · 확인 대기 · 예정`. **기본값: 완료 · 진행 중 · 예정 켜짐**, 결정 · 확인 대기 꺼짐. 선택은 localStorage에 기억(try/catch, 주차와 무관하게 하나). 내용이 없는 구역의 칩은 흐리게(비활성). 칩을 바꾸면 미리보기와 복사 글자가 즉시 바뀐다. 문서(가운데) 화면은 영향을 받지 않는다(항상 전부 보임).

## 다음 주 계획(예정)에 프로젝트 지정
- 문서 끝 `다음 주 계획` 입력줄 왼쪽에 조용한 프로젝트 선택(기본 `프로젝트 없음`; 선택지는 앱의 프로젝트 선택과 같은 목록, 마지막으로 고른 값을 다음 입력에 유지). 추가한 문장은 문서에서 프로젝트 소제목 아래로 묶여 보이고, 프로젝트 없는 문장은 구역 끝에.
- 서버: `/api/report/change`의 `action:'add'`가 선택적 `group`(문자열, 1~60자, 줄바꿈 없음)을 받도록 확장 — 없으면 기존처럼 `직접 작성`. `report-drafts.js`의 add 분기와 그룹 표시/정렬, `report-drafts.test.js`에 테스트 추가(그룹 지정 add, 잘못된 group 거절, 기존 add 호환). 화면은 `group === '직접 작성'`(또는 비어 있음)을 "프로젝트 없음"으로 취급.
- 기존에 저장된 계획 문장(그룹 `직접 작성`)은 그대로 읽힌다. 더보기에 `프로젝트` 항목을 넣어 나중에 바꿀 수 있게 할지는 서버 변경이 더 필요하므로 이번에는 하지 않는다(삭제·다시 추가로 대체) — 보고에 명시.
- DECISIONS: "다음 주 계획은 사람이 직접 쓴다. 자동으로 채우지 않는다" 유지. 저장 경로는 `/api/report/change` 하나 유지.
