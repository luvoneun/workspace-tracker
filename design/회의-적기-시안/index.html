정한 것과 이유

  • 직접 적은 것은 Enter 순간 담김. 초안처럼 담기를 기다리지 않음. 사람이 직접 적은 글은 검토할 것이 없고, 지금도 한 건씩 바로 담김(/api/workflow/capture). 잘못 적었으면 ⌘Z나 줄의 ⋯ → 삭제.
  • AI 초안은 지금처럼 담기를 기다림. AI가 뽑은 것은 틀릴 수 있어서. 그래서 초안 줄에는 체크박스 대신 조용한 AI 글자가 서고(아직 내 항목이 아님), 담으면 체크박스가 생김.
  • 새 줄의 종류는 늘 할 일. 바꾸는 길은 둘 — 적은 뒤 줄의 할 일 ⌄, 또는 적을 때 맨 앞 한 글자: ? 확인 대기, ! 결정. 앞머리는 담을 때 떼어 냄. 종류 목록의 글쇠가 같은 글자라 따로 설명문이 없어도 배울 수 있음.
    약점 — 외워야 쓰는 기능임(안 외워도 줄에서 바꾸면 됨). 정말 ?나 !로 시작하는 글은 못 적음. Tab으로 종류를 돌리는 안은 자판으로 화면을 옮겨 다니는 길을 막아서 버렸음.
  • 할 일은 지금처럼 "나중에 할 일"로 담김(DECISIONS 13·22). 오늘로 올리기는 줄의 ⋯에서. 초안은 줄을 펼쳐 오늘 할 일을 고르면 접힌 줄에 오늘이 조용히 붙음.
  • 여러 줄 붙여 넣기 — 줄마다 한 건. 줄 앞의 - • 1. 같은 목록 표시는 떼어 냄. 빈 줄은 건너뜀.
  • 종류를 고른 뒤 초점은 입력줄로 돌아감(Esc로 닫으면 누른 글자로). 다시 누르지 않고 이어서 적게 하려는 것.

기존 결정·문서와 부딪히는 점

  • 담기 바 자리(A만) — DESIGN.md 681행 "발은 담기 바 … 오른쪽에 1차 N개 담기". A는 발을 입력줄이 쓰고 담기는 AI 초안 제목 옆 2차 버튼. B는 그대로.
  • 초안 묶음 모양(A·B) — DESIGN.md 681행 "문구가 주인공인 회색 채움 입력 + 종류 세그먼트 + 나중에/오늘 세그먼트 + 날짜 칸"과 README 243행. 한 줄 + 눌러서 펼침으로 바뀜. 빼기가 회색 글자 버튼이라는 결정(DECISIONS 16행)은 지킴.
  • 종류 소제목(A·B) — DESIGN.md 681행 "이 회의에서 나온 것은 종류 소제목으로 나눈다". 방금 적은 줄이 종류 묶음 속으로 튀어 들어가면 리듬이 깨져서, 시안은 시간순 한 목록 + 줄마다 종류 글자. 소제목을 살리려면 "방금 적은 것만 시간순, 다시 열면 소제목 속으로"가 대안.
  • 쫀득 모션의 범위 — DECISIONS 96행 "이 판만이고". 종류 목록·초안 펼침에도 쓰려면 이 줄을 넓혀야 함(모션 제안의 세기 3단계가 받아들여지면 함께 정리).
  • 시트의 발(A만) — DESIGN.md 669행 "≤520px 시트에서는 발도 본문 흐름 안". A의 입력줄은 시트에서도 붙박아야 함.
  • 지키는 것 — 글자 칸을 저장 중에 잠그지 않음(DECISIONS 104행), 입력 중 다시 그리기 미룸(105행), 조합 중 Enter 넘김, 할 일은 나중에 할 일로(13·22행), 카드 안에 카드 없음, 파랑은 선택·행동에만.
