# 줄 제목 누를 자리 — 시안 (2026-10-08)

왜: 줄 제목 글자(오늘 목록 `.d-title` 25px, 레일 `.d-mrow .ti`·`.d-wrow .ti` 20px, 회의 초안·프로젝트 그룹 `.ti` 18px, 새로 들어온 것 `.desc-editable` 25px)가 28px보다 작아 빗나간다. 두 줄 말줄임이라 여백을 넣으면 셋째 줄이 비치고 `::after`는 잘린다(DESIGN 「접근성 바닥 → 누르는 영역」의 「아직 28px이 안 되는 것」).

그림: 가짜 데이터(써 보기 데이터 + 긴 제목 두 줄), 라이트, 1440·520px. 파란 칠 = 그 자리를 누르면 제목을 누른 것과 같은 일이 된다(`elementFromPoint`로 2px마다 찍어 칠함). 1440은 위 전·아래 후, 520은 왼쪽 전·오른쪽 후. 앱 코드는 바꾸지 않았다(찍을 때만 CSS·글자 칸 감싸기를 얹음).

| 후보 | 무엇을 누르면 무엇이 되나 | 그림 |
|---|---|---|
| **A · 제목 판을 줄 높이로 (추천)** | 동작은 지금 그대로(오늘: 상세 열기 · 새로 들어온 것: 고치기 · 레일: 열기). 누르는 판만 세로로 커진다 — 제목 버튼이 줄 높이를 차지하고 두 줄 말줄임은 안쪽 글자 칸이 맡는다. 레일은 판을 줄 여백 안에서 위 6·아래 2(확인 대기)·위아래 4(회의)px 넓힘 | `A-1440.png` `A-520.png` |
| B · 줄 빈 곳 누르면 제목 동작 | 줄 아무 데나(체크·버튼·원문 빼고) 누르면 제목 누름과 같다. 좁은 화면(520px 이하) 오늘 목록이 이미 이렇게 동작(`uiRowTapOpens`) — 넓은 화면·다른 줄도 같게 | `B-1440.png` `B-520.png` |
| C · 그대로 두고 예외로 적기 | 아무것도 안 바꿈. DESIGN에 「줄 제목 글자 버튼은 28px 예외」 한 줄 | `C-1440.png` `C-520.png` |

## 누를 자리 숫자 (elementFromPoint, 제목 가운데를 지나는 세로 줄의 가장 작은 값)

| 자리 | 지금(=C) | A | B |
|---|---|---|---|
| 오늘 목록 `.d-title` (1440) | 25 | 54 | 54 |
| 새로 들어온 것 `.ti` (1440) | 25 | 53 | 54 |
| 레일 회의 `.d-mrow .ti` (1440) | 20 | 28 | 44 |
| 레일 확인 대기 `.d-wrow .ti` (1440) | 21 | 28 | 66 |
| 520px — 오늘 목록 / 새로 들어온 것 / 레일 회의 / 확인 대기 | 59 / 25 / 20 / 21 | 59 / 53 / 28 / 28 | 59 / 78 / 44 / 46 |

회의 초안 `.d-mrow2 .ti`·프로젝트 `.d-prow2 .ti`는 오늘 화면에 없어 재지 않았다 — A·B 모두 같은 방식을 그대로 적용한다.

## 약점 · 부딪히는 곳

- **A** — 제목을 그리는 곳 다섯(`app.js` 오늘 줄·새로 들어온 것, `waiting-ui.js`, `meetings-ui.js`, `projects-ui.js`)에 글자 칸 하나를 더 넣어야 한다(입력·클릭 파일 → 사람 속도 확인 붙음). 가로는 그대로라 아주 짧은 제목은 좁다. 제목 뒤 `· ● 프로젝트`가 글자 밑선 대신 가운데로 맞춘다(한 줄이면 차이 안 보임). 동작 관습·DECISIONS와 부딪히는 곳 없음.
- **B** — 동작이 바뀐다. ① 동작 관습 1-ⓒ「상세 카드 바깥 클릭은 닫기만」과 부딪힘: 카드가 열린 채 다른 줄 빈 곳을 누르면 지금은 닫히기만, B에서는 그 줄 상세로 바뀐다. ② 새로 들어온 것은 제목 동작이 「고치기」라 빈 곳을 잘못 눌러도 입력칸이 열린다. ③ 줄 글자를 끌어 복사하려다 열린다. ④ 손이 닿으면 뜨는 오른쪽 버튼(`내일`·`나중에`·⋯) 자리만 빠져 그림에 흰 구멍이 생긴다 — 눌리는 곳이 손 위치에 따라 달라짐.
- **C** — 빗나감이 그대로다. 「표시 줄이고 예외 없이」 원칙에 예외가 하나 는다.

추천 A: 동작을 안 바꾸고 숫자는 모두 28 이상. B는 좁은 화면과 같아지는 장점이 있지만 상세 카드 닫힘 규칙을 다시 정해야 한다.
