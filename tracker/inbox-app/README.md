# 개인 워크스페이스

`./start.sh` 또는 `node server.js`로 실행합니다. 주소는 http://localhost:4321/ 입니다.
외부 패키지 없이 Node.js 기본 모듈을 사용합니다.

## 날짜와 읽음 상태

- `scheduled:YYYY-MM-DD`: 실행 예정일. 오늘 또는 지난 예정일의 미완료 업무는 오늘 목록에 표시합니다.
- `scheduled:none`: 실행일을 정하지 않은 업무. 나중에 할 일에 표시합니다.
- `due:YYYY-MM-DD`: 마감일. 일정을 미루거나 화면을 조회해도 변경하지 않습니다. 확인 대기에서는 상대에게 회신을 받아야 하는 기한(`회신 기한`)이며, 결정·아이디어에는 날짜가 없습니다.
- 기존 `scheduled` 없는 업무는 `due`를 실행일로도 읽습니다. 기존 파일은 일괄 변환하지 않으며, 실행일 또는 마감일을 변경할 때 두 날짜를 분리합니다.
- 새 오늘 업무는 오늘 실행 예정으로 생성하며 마감일은 지정하지 않습니다.
- `completed:YYYY-MM-DD`: 로컬 날짜 기준 완료일. 기존 완료 기록은 `updated`로 대체해 읽습니다.
- `NEW`는 누르는 버튼이 아니라 표시입니다. 카드가 화면에 잠깐 머물면 `seen:true`를 조용히 기록하고 표시가 사라집니다. GET `/api/items`는 읽기 전용이라 목록을 불러오는 것만으로는 기록하지 않습니다.

자동 수집기가 실행 날짜를 정할 때는 `scheduled`를 사용하고, 실제 기한이 있는 경우에만 `due`를 함께 기록해야 합니다.
이전 버전에서 덮어쓴 과거 마감일은 자동으로 추정하거나 복원하지 않습니다.

## 요약과 삭제

- 확인 대기는 실제 업무 차단과 구분하기 위해 '확인 대기'로 표시합니다. 이전 '막혀있는 것' 제목도 읽을 수 있습니다.
- 삭제한 업무의 원문과 위치는 `tracker/.trash.json`에 보존합니다. 삭제는 확인창 없이 바로 실행하고, 알림의 `삭제 실행 취소`(닫기 전까지 유지)와 ⌘Z로 되돌립니다. 자동 영구 삭제는 하지 않습니다.

## 화면 구성

화면은 탭 넷입니다: `오늘` · `프로젝트` · `아이디어·결정` · `주간요약`. 헤더에는 날짜 칩, 탭, 새로고침, `검색`(⌘K), `설정`(톱니바퀴)이 있고 자동 수집이 지금 실패 중일 때만 조용한 경고가 함께 뜹니다. `아이디어·결정` 탭 이름 옆 숫자는 PRD에 아직 반영하지 않은 결정 수입니다. 화면 폭이 520px 이하이면 탭 줄이 헤더 둘째 줄로 내려갑니다.

## 오늘 탭

- 왼쪽 레일은 카드 세 장입니다: `오늘 미팅`(진행 중인 회의는 파란 글자와 연파랑 바탕, 끝난 회의는 흐리게, 검토할 초안이 있으면 `초안 N`), `리마인드`, `확인 대기`. 확인 대기 줄은 두 줄로 제목과 `상대 · N일째`(3일째부터 주의색)를 적고, 회신 기한이 지났거나 오늘이면 배지를, 다시 확인할 날이 왔으면 목록 맨 위로 올려 `오늘 다시 확인`을 붙입니다. 새 확인 대기는 카드 맨 아래 `+ 확인 대기 추가`로 넣습니다.
- 리마인드는 오늘 목록과 중복하지 않고, 나중에 할 일 중 마감이 임박한 높은 우선순위 항목과 기다리던 답변이 온 업무(`답변 왔어요`)를 간결하게 표시합니다.
- `새로 들어온 것` 줄에는 `오늘`·`나중에`·`완료`가 늘 보이고, 프로젝트·기한·우선순위·삭제는 ⋯ 안에 있습니다. 제목 오른쪽 끝의 `오늘 신규 N`을 누르면 오늘 들어온 항목만 검색 팔레트로 모아 봅니다.
- 오늘 할 일 머리줄은 제목 + 남은 개수 칩 + `19개 중 5개 끝냈어요`이고, 미룰 만한 업무가 있으면 그 뒤에 `2개 미룰까요?` 글자 링크가 붙어 머리줄 아래로 펼쳐집니다. 오른쪽에는 `나중에 할 일 N` 버튼과 ⋯ 메뉴(보기 `프로젝트별`/`마감·중요도순`, `여러 개 선택`)가 있습니다. 보기 선택은 브라우저에 저장됩니다.
- 오늘 할 일의 진행은 목록 카드 윗변을 따라 흐르는 가는 파란 선으로 보여 줍니다. 새 업무는 목록 첫 줄의 빠른 추가에서 바로 넣습니다.
- **계획·정리 모드는 없습니다.** 줄에 마우스를 올리거나 키보드 초점이 가면 오른쪽 끝에 동작이 겹쳐 뜹니다 — 오늘 업무는 `내일` `나중에`, 예정일이 지난 업무는 `오늘 할게요` `내일` `나중에`, 나중에 할 일은 `오늘로`. 기준은 시간이 아니라 실행 예정일입니다. 전날 내일로 옮긴 업무는 다음 날 지난 업무로 표시하지 않습니다.
- 나중에 보낸 업무는 머리줄의 `나중에 할 일 N`을 누르면 열리는 **서랍**에 모입니다. 서랍은 헤더 아래 오른쪽에 붙어 열리고 넓은 화면에서는 본문을 덮지 않고 밀어냅니다. 900px 이하에서는 아래에서 올라오는 전체 폭 시트가 됩니다.
- 줄에 붙는 상태말은 종류마다 작은 아이콘과 설명 툴팁이 함께 옵니다: 기한 `오늘까지`·`내일까지`·`9월 27일까지`·`기한 2일 지남`(달력), 밀림 `어제에서 밀림`·`5일째 밀림`(시계), 진행 `진행 중`·`3일째 진행 중`(시계), 우선순위 `긴급`·`중요`(깃발), 답변 `답변 기다리는 중`·`답변 왔어요`(말풍선), 확인 대기의 `회신 기한 1일 지남`(달력). 배경을 채운 배지는 급한 말 셋(`긴급`·`기한 N일 지남`·`오늘까지`)과 회의의 `초안 N`뿐이고 나머지는 회색·의미색 글자입니다. 우선순위 선택지는 `긴급 / 중요 / 보통 / 낮음`이며 저장하는 값은 그대로입니다.
- 원문이 있는 업무·확인 대기·결정은 제목 바로 뒤에 조용한 `원문` 링크를 늘 보여 주고(새 탭), 상세에서는 제목 아래 `슬랙 원문 열기`로 엽니다.
- 그룹 제목이 프로젝트가 아닌 자리(`진행 중` 그룹, `마감·중요도순` 보기, 서랍, 리마인드, 검색 결과)에서는 프로젝트를 제목 바로 뒤에 `· ● 이름`으로 적습니다. 색 점은 프로젝트 이름으로 정해지는 여섯 색 중 하나이며 같은 이름은 늘 같은 색입니다.
- 확인 대기를 체크하면 알림에 `결정으로 남기기`가 잠시 표시됩니다. 누르면 같은 내용·지라/그룹·슬랙 원문으로 정책/얼라인을 만들며, NEW로 표시하지 않습니다.
- 입력창 밖에서 ⌘Z(Ctrl+Z)는 되돌리기, ⌘⇧Z(Ctrl+Shift+Z)는 다시 실행입니다. 체크(완료·확인·PRD 반영), 실행 예정일 이동, 삭제, 결정으로 남기기, 일괄 정리가 대상이며 최근 30개까지 기억합니다. 새로고침하면 기록은 사라집니다.

키보드 사용자는 맨 앞의 `오늘 할 일로 건너뛰기` 링크로 왼쪽 레일을 건너뛸 수 있습니다(오늘 탭에서만 표시).

## 상세 — 누른 줄 옆에 뜨는 카드

- 업무·확인 대기·회의 정리는 부품 하나를 함께 씁니다. 줄의 본문을 누르면 **그 줄 옆에** 떠 있는 카드가 열립니다(업무·확인 대기 360px, 회의 정리 460px). 목록은 상세가 열려도 전체 폭을 그대로 쓰고, 누른 줄은 선택 강조로 표시됩니다. 카드가 길면 제목 줄과 아래 동작 줄은 붙박이고 가운데만 스크롤합니다. 목록을 스크롤하면 카드가 줄을 따라가고, 줄이 화면 밖으로 완전히 나가면 닫힙니다. 화면 폭이 520px 이하이면 아래에서 올라오는 시트가 됩니다.
- 상세의 값은 그 자리에서 고칩니다. `언제 할지`·`우선순위`는 값을 누르면 줄의 ⋯와 같은 고르개가 붙고, `기한`·`회신 기한`·`다시 확인할 날짜`는 날짜 칸, `누구에게`는 글자 칸, `프로젝트`는 선택 칸입니다. 제목도 눌러서 그 자리에서 고칩니다. **저장 버튼은 없습니다** — 고치면 바로 저장됩니다.
- 업무·확인 대기 카드는 바깥을 누르거나 Esc·✕·같은 줄 다시 누르기로 닫힙니다. **회의 정리 카드만 빈 곳을 눌러도 닫히지 않습니다**(✕·Esc·같은 회의 줄 다시 누르기·다른 줄 열기로 닫습니다) — 한참 붙들고 검토하는 면이라 자리를 잃으면 안 되기 때문입니다.
- 업무 상세의 답변 대기·결과 입력은 접혀 있습니다. 기록된 연결과 결과는 계속 표시하며 편집할 때 펼칩니다. 확인 요청 기록도 보조 영역에 접어 둡니다.

## 프로젝트 · 아이디어·결정 탭

- `프로젝트` 탭은 왼쪽이 프로젝트 목록, 오른쪽이 고른 프로젝트 하나입니다. 업무, 확인 대기, 결정, 아이디어와 관련 회의를 함께 봅니다. 목록 어디서든 프로젝트 이름(`· ● 이름`, 그룹 제목)을 누르면 이 탭의 그 프로젝트로 옵니다.
- `아이디어·결정` 탭은 두 열(아이디어 | 결정)이고 좁은 화면에서는 한 열로 쌓입니다. 두 열 모두 프로젝트 그룹 제목으로 묶습니다. 결정 줄에만 `PRD 반영` 체크가 있고, 반영 완료한 정책/얼라인은 카드 아래 `반영 완료`에서 최근 반영 순으로 보고 검색할 수 있습니다.

## 업무·회의 연결

- 오늘 미팅 옆 `전체 보기`를 누르면 ⌘K 팔레트가 `회의` 필터로 열립니다. 제목·시리즈 검색, `미해결만`·`검토 대기` 필터로 회의를 찾습니다. 회의 상세에서 만든 항목은 회차에 연결되며 실제 업무의 현재 상태를 표시합니다. `기존 항목 연결`은 같은 프로젝트의 기존 항목을 복제 없이 연결합니다.
- 오늘 미팅 카드에는 검토할 AI 초안이 있으면 `초안 N` 배지가 붙습니다. 회의 모아보기는 `검토 필요` 회의를 맨 위에 두고, 행마다 시간·제목·프로젝트와 상태 칩(`초안 N 검토`, 미완료 할 일·확인 대기·결정 수)을 보여 줍니다.
- 회의를 열면 티로 노트에서 AI가 분류한 초안이 회의 정리 카드 안에 나옵니다. 카드마다 종류(할 일·확인 대기·결정)를 버튼으로 바꾸고, 문구는 여러 줄로 전부 보이는 입력칸에서 고치거나 ✕로 뺍니다. 할 일 카드에는 `나중에 할 일 | 오늘 할 일`을 고를 수 있고(기본은 나중), 카드 아래에 고정된 `N개 담기`로 한꺼번에 담습니다. 카드에서 날짜도 정합니다: 할 일은 `마감일`, 확인 대기는 `회신 기한`(비어 있으면 `+ 마감일`/`+ 회신 기한`). 초안에 있던 마감은 바꾸거나 지울 수 있고, AI는 확인 대기 날짜를 채우지 않습니다. 직접 적어 담기(`직접 적어 담기`)는 검토할 초안이 있는 회의에서는 접혀 있고, 초안이 없으면 펼쳐져 있으며 같은 날짜 칸을 씁니다. AI가 문구 끝에 붙여 온 `(방향 확인 필요)` 표식은 떼어 내고 보여 주며 항목 문구로도 저장하지 않습니다. 초안 카드는 문구를 맨 위에 크게 보여 주고 종류·시점·날짜는 그 아래 작게 두며, 카드 왼쪽 띠와 아래 항목 목록의 종류 칩은 같은 색입니다(할 일 파랑 · 확인 대기 주황 · 결정 회색).
- 담은 직후 결과 카드는 한 줄로 종류별 개수를 알려 주고, 나중에 담긴 할 일 옆에 `오늘로` 버튼을 둡니다(할 일이 넷 이상이면 `모두 오늘로` 한 줄, 올리고 나면 `오늘 할 일 ✓`). 처음부터 오늘로 고른 할 일은 `오늘 할 일 ✓`로 보입니다. 카드 맨 아래 `다음: ○○ (초안 N) →` 링크가 초안이 남은 다음 회의를 열어 줍니다. `실행 취소`를 누르면 방금 담은 항목이 삭제 휴지통(`tracker/.trash.json`, 원문 보존)으로 옮겨지고 초안이 다시 검토 대기로 올라옵니다(고친 종류·문구·시점은 유지). `다음 검토` 버튼은 초안이 남은 다음 회의로 이어서 엽니다(자동으로 넘어가지는 않습니다).
- 서버 시작과 캘린더 파일 변경 시 관측한 오늘 회의를 `.workflow.json`에 보존합니다. 이미 덮어써져 남아 있지 않은 과거 일정은 복원하지 않습니다. 서버가 꺼져 있는 동안 지나간 일정도 수집할 수 없습니다.
- 같은 제목은 기본적으로 같은 시리즈입니다. 회의 상세에는 프로젝트·반복 회의 입력을 두지 않고, 프로젝트는 오늘 미팅 줄의 ⋯ → `프로젝트 연결`에서 바꿉니다. 이전 회차의 미해결 항목은 이동·복제하지 않고 연결된 원본으로 보여 줍니다.
- 확인 대기의 `다시 확인할 날짜`에서 재확인 날짜와 오늘 확인 요청 기록을 남깁니다. 마감일은 바뀌지 않습니다. 오늘 확인 요청을 기록한 항목은 당일 재확인 알림에서 제외됩니다.
- 업무 상세에서 기다리는 확인 대기를 연결합니다. 미해결이면 답변 대기, 해결되면 진행 가능으로 표시합니다. 미해결 업무는 나중 목록에서 오늘로 가져오는 추천에서 제외합니다.
- 완료 결과는 업무 상세의 `결과 한 줄`에 기록합니다. 보고 초안은 결과가 있으면 그 문구를 우선 사용하며, 이미 직접 고친 보고 문장은 덮어쓰지 않고 수정 제안으로만 보여 줍니다.
- 추가 메타데이터는 `tracker/.workflow.json`에 원본 ID로 연결해 저장합니다. 파일은 임시 파일 작성 후 교체하며, 조회 API는 읽기 전용입니다.

## 빠른 정리와 검색

- 오늘 할 일 머리줄의 ⋯ → `여러 개 선택`에서 오늘 목록과 나중에 할 일 서랍의 미완료 업무를 함께 고릅니다. 선택 모드에서는 완료 체크 왼쪽에 선택 칸이 한 칸 더 생기고, 화면 아래 막대에서 `전체 선택` · `오늘로` · `내일` · `나중에` · `날짜…` · `프로젝트…` · `완료로 표시` · `삭제` · `선택 끝내기`를 합니다. 아무것도 고르지 않았으면 바꾸는 버튼은 눌리지 않습니다. 마감일은 유지됩니다.
- 날짜·프로젝트·완료는 `/api/workflow/task-batch` 한 곳으로 갑니다. `change`는 한 번에 하나이고 `{scheduled}` · `{project}` · `{status:'done'}`만 받습니다(완료 취소는 줄마다 체크로 되돌리고, 완료일은 서버가 오늘로 적습니다). 일괄 변경은 모든 대상과 값을 검증한 뒤 저장하며, 알림의 실행 취소와 기존 ⌘Z/다시 실행으로 되돌립니다. 변경한 속성을 나중에 다시 편집했다면 취소가 해당 편집을 덮어쓰지 않도록 거절합니다. 서버 재시작 시 일괄 취소 기록은 만료됩니다.
- 일괄 삭제만 서버 경로가 따로 없습니다. 고른 순서대로 한 건씩 `/api/track/remove`로 휴지통에 보내고(원문 보존) 알림 하나의 `되돌리기`로 역순 복원합니다. 중간에 실패하면 멈추고 어디까지 지웠는지 알립니다.
- 헤더의 `검색`(⌘K)은 위에서 내려오는 팔레트 하나입니다. 완료 업무, 결과 한 줄, 결정, 확인 대기, 아이디어, 회의와 앱에 수집된 회의 초안 문구를 찾습니다(외부 티로 노트 전문은 찾지 않습니다). 종류 칩 `전체 · 할 일 · 확인 대기 · 결정 · 아이디어 · 회의`와 토글 칩 `완료 제외`, 회의일 때 `미해결만` · `검토 대기`가 있습니다. `전체 보기`(회의 모아보기)와 `오늘 신규 N`도 같은 팔레트를 필터만 다르게 엽니다. ↑↓로 옮기고 Enter로 열며 Esc로 닫습니다. 항목을 열었다가 뒤로 가면 검색어·필터·스크롤 자리가 그대로 남습니다.

## 주간보고

주간요약 탭은 업무 원본에서 보고 초안을 생성합니다. 프로젝트·상태와 공통 문구/회의/원본 링크를 기준으로 보수적으로 묶으며, 외부 AI 호출이나 결과 추측은 하지 않습니다. 완료·진행·결정은 구분하고, 결과 한 줄이 있으면 사용합니다.

화면은 세 칸입니다: 주차 목록 | 보고 문서 | 슬랙 미리보기(1120px 이하에서는 미리보기가 문서 아래로 내려옵니다). 문서는 `보고`와 `전체 업무 기록` 두 모드를 세그먼트로 오갑니다.

- 문장 수정은 원본 업무를 변경하지 않습니다. 새 관련 업무는 수정 제안으로 나타납니다.
- 근거 업무를 펼쳐 원본을 확인하고, 제외한 업무는 `전체 업무 기록`에서 복원합니다.
- `선택`으로 보고 항목을 묶을 수 있습니다. 서로 다른 완료 상태는 묶지 않습니다.
- 다음 주 계획은 사람이 직접 씁니다(자동으로 채우지 않습니다). 입력줄 왼쪽에서 문장마다 프로젝트를 고를 수 있고, 고른 문장은 문서에서 그 프로젝트 소제목 아래로 묶입니다. 서버에서는 `/api/report/change`의 `action:'add'`가 선택적 `group`(1~60자, 줄바꿈 없음)을 받습니다. 없으면 기존처럼 `직접 작성`으로 들어가고, 이미 저장된 계획 문장도 그대로 읽힙니다. 나중에 프로젝트를 바꾸려면 지우고 다시 넣습니다.

### 슬랙 복사

`슬랙용으로 복사`는 **구역 → 프로젝트 → 글머리 항목** 형식으로 씁니다.

- 첫 줄은 `9월 3주차 (9/21~9/27)` 제목이고, 그 아래 구역이 `완료` · `진행 중` · `결정` · `확인 대기` · `예정` 차례로 섭니다. 내용이 없는 구역은 빠집니다. 화면·서버가 모르는 소제목은 버리지 않고 **그 이름 그대로의 구역**이 되어 아는 구역들 뒤, `예정` 앞에 섭니다.
- 구역 안에서는 프로젝트 이름 한 줄 아래로 그 프로젝트의 문장을 `•` 항목으로 모읍니다. 프로젝트가 없는 문장은 구역 끝 `기타`로 갑니다. 문장이 여러 줄이면 둘째 줄부터 들여 쓴 `◦` 부연이 됩니다. `예정`에서 프로젝트를 고르지 않은 계획 문장은 구역 끝에 `* 문장` 메모 줄로 섭니다.
- 미리보기 카드 위의 칩으로 **슬랙에 넣을 구역**을 고릅니다. 기본은 `완료` · `진행 중` · `예정`이 켜져 있고 `결정` · `확인 대기`는 꺼져 있습니다. 처음 보는 구역은 켠 채로 시작하고, 사람이 끈 구역은 다음에도 꺼진 채로 둡니다. 선택은 브라우저에 기억합니다(주차와 무관하게 하나). 내용이 없는 구역의 칩은 누를 수 없습니다. 칩을 바꾸면 미리보기와 복사 글자가 함께 바뀝니다 — 가운데 문서는 영향을 받지 않고 늘 전부 보입니다.
- 복사는 **서식 있는 복사와 일반 글자를 함께** 넣습니다(`ClipboardItem`의 `text/html` + `text/plain`). 슬랙 입력창에 붙이면 굵은 글씨와 글머리 목록이 되고, 서식을 못 쓰는 곳에는 같은 내용이 일반 글자로 붙습니다. `ClipboardItem`을 쓸 수 없으면 일반 글자만, 그것도 막히면 미리보기 글자를 직접 고르도록 안내합니다. 제외한 항목과 근거 표시는 복사에 들어가지 않고, 수정 중인 문장이 있으면 복사를 막습니다.
- 기존 `weekly_reports.md`는 그대로 두고 새 편집은 `tracker/.report-drafts.json`에 저장합니다. 기존 숨김 항목은 복사에서 제외됩니다.
- 조회는 파일을 수정하지 않습니다. 저장 버전이 달라지면 충돌을 알리고 입력을 보존합니다. 과거의 진행 상태를 기록 없이 추정해 채우지 않습니다.

## 설정

헤더 오른쪽 톱니바퀴가 `설정`입니다(창 제목·aria 이름도 `설정`). `상태`와 `사용법` 두 칸이고, `상태`에는 자동 수집 결과가, `사용법`에는 도움말과 `다른 기기 접속 암호 복사`가 있습니다. 자동 수집이 **지금** 실패 중이면 톱니바퀴에 빨간 점이 붙습니다(해결된 과거 실패는 접어 둡니다).

## 시각 방향과 말투

화면의 확정된 시각 기준은 **`DESIGN.md`** 한 곳에 있습니다 — 토큰 값(라이트·다크), 타이포, 간격·모양·그림자, 레이아웃과 반응형 경계, 부품(버튼 세 등급·체크박스·배지·업무 줄·상세 카드·메뉴·팔레트·막대·서랍·주간요약), 모션, 접근성 바닥까지. 화면을 고치기 전에 그 문서를 먼저 봅니다.

- 색·간격·둥글기는 전부 `ui.css`의 `:root` 토큰으로만 적고 컴포넌트 규칙에는 색 값을 직접 쓰지 않습니다(스크롤바 제외). 글자 대비 4.5:1, 컨트롤 3:1, 누르는 자리 28px 이상을 지킵니다.
- 본문 글꼴은 앱에 넣은 Pretendard Variable(`/fonts/PretendardVariable.woff2`, SIL OFL 1.1 — `fonts/Pretendard-LICENSE.txt`)이고 서버가 직접 줍니다(외부에서 받아오지 않습니다). 없으면 시스템 한글 글꼴로 내려갑니다.
- 말을 거는 문장(알림·안내·빈 화면·오류·도움말)은 **해요체**입니다 — `완료했어요` · `내일로 미뤘어요` · `삭제했어요` · `저장했어요`. 버튼·메뉴·열 이름은 짧은 명사형을 그대로 씁니다 — `완료로 표시` · `내일` · `나중에` · `오늘로` · `삭제`.

## 저장 안전장치

쓰기에는 임시 파일 교체, `.backups/`의 직전 파일, 변경 파일별 복구 저널을 사용합니다. 복구할 파일이 외부에서 다시 수정됐으면 덮어쓰지 않고 저널을 보존합니다. 이는 장기 백업을 대체하지 않습니다.

### 업무 데이터 백업

`tracker/`의 업무 데이터는 코드 저장소에서 제외돼 있어서, `automation/backup-data.sh`가 하루 한 번(19:30) 별도의 비공개 Git 저장소에 커밋하고 올립니다. 백업용 저장 공간은 프로젝트 밖 `~/.local/share/workspace-automation/data-backup.git`에 있고, 올릴 파일은 그 안의 `info/exclude` 허용 목록으로 고정합니다(접속 암호·잠금·`.backups`는 제외). 결과는 `logs/data-backup.log`에 남습니다.

- 과거 상태 보기: `git --git-dir=~/.local/share/workspace-automation/data-backup.git log` 로 날짜를 찾고 `show <커밋>:tasks.md` 로 그날의 내용을 확인합니다.
- 새 맥에서 복구: 비공개 저장소를 받아 파일을 `tracker/`에 넣은 뒤, `git clone --bare`로 같은 위치에 저장 공간을 만들고 `core.bare false`와 `info/exclude` 허용 목록을 다시 설정한 다음 `setup.sh`를 실행합니다.

### 복구 필요 상태

되돌리기가 거절되거나(외부에서 바뀐 파일), 서버 시작 때 복구를 끝내지 못하면 저장을 멈춥니다. 서버와 조회는 그대로 동작하고, 저장 요청만 503과 안내 문구로 거절하며 화면 위에 같은 안내가 계속 표시됩니다(`GET /api/storage-status`). 회의 기록 자동 저장도 함께 멈춥니다. 앱은 아무 파일도 자동으로 지우거나 되돌리지 않습니다.

- 관련 파일: `tracker/.mutation-journal.json`(`{"changes":[{"file","before","after","intermediate"}]}` 형식이며 `before`는 변경 전 내용을 base64로 담습니다. 끝난 거래는 `{"committed":true}`), `tracker/.mutation.lock`(저장 중인 프로세스 번호), `<파일이 있는 폴더>/.backups/<파일명>.previous`(직전 내용).
- 저널의 `changes[].file`을 하나씩 열어 지금 파일과 `before`를 디코드한 내용(`base64 -d`), 그리고 `.previous` 백업을 비교합니다.
- 지금 파일이 맞으면 그대로 두고, 되돌리는 쪽이 맞으면 `before` 또는 `.previous` 내용을 직접 파일에 씁니다.
- 정리한 뒤 저널과 잠금 파일을 지우지 말고 다른 이름으로 옮겨 둡니다(예: `.mutation-journal.json.2026-09-20`).
- 서버를 다시 시작하면 복구를 다시 시도하고, 성공하면 저장이 풀립니다. 남은 파일은 확인 후 직접 정리합니다.

Slack 수집은 모든 페이지를 읽고 `import-record.js`로 앱의 검증·저장 API를 사용합니다. JSON은 명령줄 인자로 넘기며(`node tracker/inbox-app/import-record.js item '{…}'`), 인자를 주지 않으면 표준 입력도 그대로 받습니다. 일부 저장에 실패하면 수집 커서를 유지합니다. 수집 시도와 성공은 별도로 표시합니다. 수집 스크립트 변경 후 설치된 `~/.local/share/workspace-automation/slack-capture.sh`도 함께 갱신해야 합니다.

자동화 실행(`run-task.sh`)은 30분(`TASK_TIMEOUT_SECONDS`, 맥이 깨어 있는 시간 기준)이 넘으면 자식 프로세스까지 정리하고 `exit 124`로 끝냅니다. Slack 수집은 잠금 주인 프로세스가 살아 있는지 확인해서, 살아 있으면 건너뛰고 죽었으면 바로 회수합니다. 수집 실행은 파일 수정 도구 없이(Write·Edit 금지) `import-record.js`와 `fetch_slack_channel.sh` 두 명령만 쓸 수 있습니다.

다른 기기 접속에는 인증이 필요합니다. 로컬 앱의 설정 → 사용법 → `다른 기기 접속 암호 복사`에서 암호를 복사하고, 접속 시 사용자 이름은 `workspace`를 사용합니다. 암호는 `tracker/.access-token`에 보관되며 Git에서 제외됩니다. 원격 접속은 기존 Tailscale 또는 HTTPS 보호 환경에서 사용합니다. 앱 아이콘(`/icons/*.png`)과 `manifest.webmanifest`만 인증 없이 열립니다 — 아이폰이 홈 화면에 추가할 때 로그인 정보 없이 가져가기 때문입니다. 아이콘을 바꾼 뒤에는 홈 화면의 앱을 지우고 다시 추가해야 새 아이콘이 보입니다.
