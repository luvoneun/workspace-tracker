# 개인 워크스페이스

`./start.sh` 또는 `node server.js`로 실행합니다. 주소는 http://localhost:4321/ 입니다.
외부 패키지 없이 Node.js 기본 모듈을 사용합니다.

## 날짜와 읽음 상태

- `scheduled:YYYY-MM-DD`: 실행 예정일. 오늘 또는 지난 예정일의 미완료 업무는 오늘 목록에 표시합니다.
- `scheduled:none`: 실행일을 정하지 않은 업무. 나중에 할 일에 표시합니다.
- `due:YYYY-MM-DD`: 마감일. 일정을 미루거나 화면을 조회해도 변경하지 않습니다. 확인 대기에서는 상대에게 답을 받기로 한 날(`답변 받을 날`)이며, 결정·아이디어에는 날짜가 없습니다.
- 기존 `scheduled` 없는 업무는 `due`를 실행일로도 읽습니다. 기존 파일은 일괄 변환하지 않으며, 실행일 또는 마감일을 변경할 때 두 날짜를 분리합니다.
- 새 오늘 업무는 오늘 실행 예정으로 생성하며 마감일은 지정하지 않습니다.
- `completed:YYYY-MM-DD`: 로컬 날짜 기준 완료일. 기존 완료 기록은 `updated`로 대체해 읽습니다.
- `NEW`는 누르는 버튼이 아니라 표시입니다. 카드가 화면에 잠깐 머물면 `seen:true`를 조용히 기록하고 표시가 사라집니다. GET `/api/items`는 읽기 전용이라 목록을 불러오는 것만으로는 기록하지 않습니다.

자동 수집기가 실행 날짜를 정할 때는 `scheduled`를 사용하고, 실제 기한이 있는 경우에만 `due`를 함께 기록해야 합니다.
이전 버전에서 덮어쓴 과거 마감일은 자동으로 추정하거나 복원하지 않습니다.

## 요약과 삭제

- 확인 대기는 실제 업무 차단과 구분하기 위해 '확인 대기'로 표시합니다. 이전 '막혀있는 것' 제목도 읽을 수 있습니다.
- 삭제한 업무의 원문과 위치는 `tracker/.trash.json`에 보존합니다. 삭제는 확인창 없이 바로 실행하고, 알림의 `삭제 실행 취소`(닫기 전까지 유지)와 ⌘Z로 되돌립니다. 알림을 닫은 뒤에는 **설정 > `삭제한 항목`**에서 되살립니다(아래 `설정` 절). 자동 영구 삭제는 하지 않습니다.

## 화면 구성

화면은 탭 다섯입니다: `오늘` · `프로젝트` · `회의` · `아이디어·결정` · `주간요약`. 헤더에는 날짜 칩, 탭, 새로고침, `검색`(⌘K), `설정`(톱니바퀴)이 있고 자동 수집이 지금 실패 중일 때만 조용한 경고가 함께 뜹니다. 탭 이름 옆 숫자는 `회의`가 검토할 초안이 있는 회의 수, `아이디어·결정`이 PRD에 아직 반영하지 않은 결정 수입니다(0이면 숫자가 없습니다). 화면 폭이 520px 이하이면 탭 줄이 헤더 둘째 줄로 내려갑니다. 마지막으로 본 탭은 다시 열 때 복원하지만, 페이지를 열자마자 사람이 탭을 누르면 **그 선택이 먼저입니다**(앱이 다 켜지기 전에 누른 탭도 포함합니다).

## 오늘 탭

- 왼쪽 레일은 카드 세 장입니다: `오늘 미팅`(진행 중인 회의는 파란 글자와 연파랑 바탕, 끝난 회의는 흐리게, 검토할 초안이 있으면 `초안 N`), `리마인드`, `확인 대기`. 확인 대기 줄은 두 줄로 제목과 `상대 · N일째`(3일째부터 주의색)를 적고, 답변 받을 날이 지났거나 오늘이면 배지를, 다시 확인할 날이 왔으면 목록 맨 위로 올려 `오늘 다시 확인`을 붙입니다. 새 확인 대기는 카드 맨 아래 `+ 확인 대기 추가`로 넣습니다.
- 확인 대기 카드 머리의 ⋯에서 보기를 고릅니다(기억됩니다). 기본 `프로젝트별`은 프로젝트 소제목(색 점 + 이름 + 개수, 눌러서 프로젝트 탭) 아래로 줄을 묶고, 묶음은 가장 급한 줄이 있는 것이 위로 옵니다(묶음 안은 기존 정렬 그대로) — 프로젝트 없는 것은 `프로젝트 없음`으로 맨 아래입니다. `급한 순`은 예전처럼 한 목록이되 둘째 줄 맨 앞에 조용한 프로젝트 표기(색 점 + 이름)가 붙습니다.
- 리마인드는 오늘 목록과 중복하지 않고, 나중에 할 일 중 마감이 임박한 높은 우선순위 항목과 기다리던 답변이 온 업무(`답변 왔어요`)를 간결하게 표시합니다.
- **배포가 코앞인 프로젝트**도 같은 카드에 섭니다(맨 위 — 미룰 수 없는 바깥 일정이라 가장 급합니다). 대상은 *열린 항목(미완료 업무 + 미완료 확인 대기)이 하나라도 있는 프로젝트* 가운데, 연결된 지라 티켓의 **아직 배포되지 않은** 버전 중 가장 이른 배포일이 **3일 안이거나 이미 지난** 것입니다. 줄은 두 줄입니다: 프로젝트 이름, 그 아래 `v2.70.0 배포 3일 전`(오늘이면 `오늘 배포`, 내일 `내일 배포`, 지났으면 `배포일 2일 지남` — 3일 안은 주의색, 지났으면 급함 색 **글자**이고 배지가 아닙니다) + `열린 업무 2`. 누르면 프로젝트 탭의 그 프로젝트가 열립니다. 닫기·미루기는 없습니다 — 배포되거나 열린 항목이 없어지면 스스로 사라집니다. 같은 버전을 쓰는 프로젝트가 여럿이면 프로젝트마다 한 줄이고, 급한 순으로 **넷까지** 적은 뒤 나머지는 `외 N개`로만 알립니다(카드 머리의 개수는 안 보이는 줄까지 셉니다). 지라 키는 나오지 않습니다. 앱이 지라를 직접 읽지 못해 스냅샷 파일로 물러서 있으면(배포 버전 칸이 없으면) 이 줄은 아예 서지 않습니다.
- **안 가져온 미팅 노트는 리마인드에 오르지 않습니다.** 노트를 쓰지 않는 회의도 많아 매번 알리면 소음이었습니다. 어느 회의의 노트를 아직 안 가져왔는지는 회의 탭(머리의 `오늘 것 모두 가져오기 N`, 회의 카드의 `이 회의의 미팅 노트 가져오기`)에서 봅니다.
- **반응 필요**(본문 맨 위, `새로 들어온 것` 위)는 *내가 답해야 하는 것*을 모으는 구역입니다. 1차는 **지라 댓글**만 잇습니다. **0개이거나 지라에 연결돼 있지 않으면 구역 자체가 없습니다**(빈 말도 띄우지 않습니다 — 작동 여부는 설정 > 상태의 `반응 필요 · 지라 댓글` 줄에서 봅니다). 머리줄은 제목과 개수만입니다(`지라 댓글 · N분 전` 같은 문구는 평소엔 없습니다 — 다른 구역 제목과 같은 리듬입니다). 값이 묵어 이전 값을 쓰는 동안에만 `N시간 전 기준`이 붙습니다. 각 줄 맨 앞에는 조용한 출처 이름표(`지라`)가 붙어, 나중에 다른 출처가 늘어도 줄에서 바로 구분됩니다.
  - 대상은 *내가 담당·보고·지켜보는* 이슈 중 **최근 14일 안에 갱신된 것**이고, 그중 **내 마지막 댓글 뒤에 다른 사람 댓글이 있는 이슈**만 한 줄이 됩니다(내 댓글이 없으면 다른 사람 댓글 전부가 대상, 다른 사람 댓글이 하나도 없으면 줄이 없습니다). 완료된 티켓도 빼지 않습니다 — 끝난 티켓에도 질문이 달립니다.
  - 줄은 두 줄입니다: 프로젝트 색 점 + **요약** + 오른쪽에 `테스터A 외 1명 · 2시간 전`, 그 아래 마지막 댓글 미리보기(140자까지) + `· 댓글 N개`(2개 이상일 때만). 지라 상태는 이 줄에 적지 않습니다(반응 필요는 "누가 나를 불렀나"만 보는 자리입니다). 댓글이 나를 불렀으면(`@내 이름`) 그 줄이 맨 위로 올라오고 주의색 글자 `@멘션`이 붙습니다. 지라 키는 툴팁과 `열기` 링크에만 있습니다. 여덟 줄까지 보이고 나머지는 `외 N개 보기`입니다(다시 접는 길은 없고, 페이지를 새로 열면 접힙니다).
  - 줄에 마우스를 올리거나 초점이 가면 오른쪽에 `열기`(지라 새 탭) · `했어요` · `할 일로`가 뜹니다(390px에서는 늘 보입니다).
  - **스스로 사라집니다.** 내가 그 이슈에 댓글을 달면 다음 갱신에서 그 줄이 없어집니다. `했어요`는 그 줄을 지금 치우고(알림의 `되돌리기`로 되돌립니다, ⌘Z 대상은 아닙니다) **댓글이 더 달리면 다시 나타납니다** — 줄의 id가 `출처:키:마지막 댓글 번호`라서 값이 달라지기 때문입니다.
  - `할 일로`는 그 줄 아래에 확인 대기의 `후속 할 일`과 같은 입력칸을 엽니다(`댓글 답하기 — 요약`이 미리 채워지고 전체 선택됩니다). 프로젝트는 그 지라 티켓이고 `오늘`·`나중에`로 담습니다(Enter는 `오늘`, 한글 조합 중 Enter는 넘기고 Esc는 입력만 닫습니다). 업무를 만들면 그 줄도 함께 치워집니다 — 만든 업무는 ⌘Z로 지울 수 있지만 그 줄은 다시 올라오지 않습니다(댓글이 더 달리면 나타납니다).
  - **1차 한계**: 내가 담당·보고·지켜보지 않는 이슈에서 나를 부른 댓글은 못 봅니다. 14일보다 오래된 댓글도 빠집니다. 피그마 댓글·슬랙은 아직 잇지 않았습니다.
- `새로 들어온 것` 줄에는 `오늘`·`나중에`·`완료`가 늘 보이고, 기한·우선순위·삭제는 ⋯ 안에 있습니다. 프로젝트가 있으면 제목 뒤·`원문` 앞에 조용한 표기가 붙습니다(없으면 지어내지 않습니다). 제목 오른쪽 끝의 `오늘 신규 N`을 누르면 오늘 들어온 항목만 검색 팔레트로 모아 봅니다.
- 오늘 할 일 머리줄은 제목 + 남은 개수 칩 + `19개 중 5개 끝냈어요`이고, 미룰 만한 업무가 있으면 그 뒤에 `2개 미룰까요?` 글자 링크가 붙어 머리줄 아래로 펼쳐집니다. 오른쪽에는 `나중에 할 일 N` 버튼과 ⋯ 메뉴(보기 `프로젝트별`/`마감·중요도순`, `오늘 정리`, `여러 개 선택`)가 있습니다. 보기 선택은 브라우저에 저장됩니다.
- **오늘 정리**(머리줄 ⋯ → `오늘 정리`)는 하루를 마감하는 창입니다. 대상은 **오늘 할 일 목록의 미완료 업무**뿐입니다(`새로 들어온 것`·확인 대기·결정·나중에 할 일은 대상이 아닙니다). 남은 업무가 없으면 창을 열지 않고 `오늘 할 일을 모두 끝냈어요`만 알립니다.
  - 창은 설정과 같은 모달입니다. 머리에 `오늘 정리`와 날짜, 그 아래 `8개 중 3개 끝냈어요 · 남은 5개`, 접힌 `끝낸 것 N`(펼치면 오늘 완료한 업무를 조용한 글자로 보여 주기만 합니다, 0개면 소제목 자체가 없습니다), 그리고 `남은 것 N` 목록입니다. 줄은 제목 + `· ● 프로젝트` + 업무 줄과 같은 상태말(`진행 중`·`오늘까지`·`기한 N일 지남`, 있는 것만) + 오른쪽 세그먼트 `그대로 | 내일 | 나중에 | 완료`입니다. **기본은 전부 `그대로`입니다** — 앱이 무엇을 미룰지 추측하지 않습니다.
  - 아래 주 버튼은 고른 개수를 따라 `바꿀 게 없어요`(비활성) ↔ `정리 끝 — 내일 2 · 나중에 1 · 완료 1`로 바뀝니다. `취소`·Esc·✕는 아무것도 저장하지 않습니다. 키보드는 줄 사이 Tab, 세그먼트 안 ←→, Enter는 주 버튼입니다.
  - 저장은 `여러 개 선택` 막대와 **같은 길**(`/api/workflow/task-batch`)입니다. 갈래마다 한 번씩 **최대 세 번**, `완료`(`{status:'done'}`) → `내일`(`{scheduled: 내일}`) → `나중에`(`{scheduled: null}`) 차례로 보냅니다. 끝나면 목록을 다시 읽고 창이 닫히며 `오늘 정리했어요 · 내일 2 · 나중에 1 · 완료 1`을 알립니다.
  - 되돌리기는 **⌘Z 항목 하나**(`오늘 정리`)입니다 — 알림의 `실행 취소`도 같은 항목이고, 보낸 차례의 반대로 되돌립니다. 중간에 실패하면 그 갈래에서 멈추고 `완료 1개는 옮겼지만 내일 2개는 못 옮겼어요 · 다시 시도해 주세요`라고 알립니다. 성공한 갈래만 ⌘Z에 담기고, 창은 닫지 않고 못 보낸 줄만 고른 값 그대로 남습니다.
- 오늘 할 일의 진행은 목록 카드 윗변을 따라 흐르는 가는 파란 선으로 보여 줍니다. 새 업무는 목록 첫 줄의 빠른 추가에서 바로 넣습니다.
- **계획·정리 모드는 없습니다.** 줄에 마우스를 올리거나 키보드 초점이 가면 오른쪽 끝에 동작이 겹쳐 뜹니다 — 오늘 업무는 `내일` `나중에`, 예정일이 지난 업무는 `오늘 할게요` `내일` `나중에`, 나중에 할 일은 `오늘로`. 기준은 시간이 아니라 실행 예정일입니다. 전날 내일로 옮긴 업무는 다음 날 지난 업무로 표시하지 않습니다.
- 나중에 보낸 업무는 머리줄의 `나중에 할 일 N`을 누르면 열리는 **서랍**에 모입니다. 서랍은 헤더 아래 오른쪽에 붙어 열리고 넓은 화면에서는 본문을 덮지 않고 밀어냅니다. 900px 이하에서는 아래에서 올라오는 전체 폭 시트가 됩니다.
- **우선순위는 업무 체크박스 안의 위 화살표로 말합니다** — `중요`는 주황 한 겹, `긴급`은 빨강 두 겹이고 체크박스 테두리·바탕도 같은 색입니다(지라의 우선순위 아이콘과 같은 말입니다). 보통·낮음은 평소 체크박스 그대로입니다. 체크박스에 마우스를 올리거나 초점이 가면 화살표가 사라지고 평소 체크박스로 돌아가며, 체크하면 화살표 없이 파란 채움이 됩니다. 색만으로 말하지 않도록 체크박스의 툴팁(`중요한 업무예요` / `가장 먼저 해야 하는 업무예요`)과 이름표(`… — 중요 · 완료로 표시`)가 함께 알려 줍니다. 적용 대상은 업무 체크박스가 있는 모든 줄입니다 — 오늘 할 일, 나중에 할 일 서랍, `마감·중요도순` 보기, 프로젝트 탭의 `진행할 업무`. 확인 대기·결정의 체크박스, 완료한 줄, 새로 들어온 것은 그대로입니다.
- 업무 줄 오른쪽에는 **날짜 성격의 말만** 남습니다: **상태(밀림 · N일째 진행 중 · 답변 기다리는 중/답변 왔어요) → 기한** 순으로 **있는 것만** 오른쪽 끝에 붙습니다(기한이 맨 오른쪽). 값이 없으면 빈 자리를 남기지 않습니다. 줄이 두 줄로 쌓이는 좁은 화면(520px 이하)에서도 같은 순서로 이어 붙입니다. 완료한 줄·새로 들어온 것·레일·검색 결과·회의 줄은 예전 모양 그대로이고, 체크박스가 없는 미루기 제안 줄에서만 우선순위를 예전처럼 글자로 적습니다.
- 줄에 붙는 상태말은 종류마다 작은 아이콘과 설명 툴팁이 함께 옵니다: 기한 `오늘까지`·`내일까지`·`9월 27일까지`·`기한 2일 지남`(달력), 밀림 `어제에서 밀림`·`5일째 밀림`(시계), 진행 `진행 중`·`3일째 진행 중`(시계), 답변 `답변 기다리는 중`·`답변 왔어요`(말풍선), 확인 대기의 `1일 늦음`·`오늘 답변 예정`(달력, 툴팁이 `9월 20일 (일)까지 답변을 받기로 했어요`로 풀어 줍니다). 우선순위 `긴급`·`중요`는 업무 줄에서는 체크박스 안의 화살표로, 체크박스가 없는 자리(미루기 제안 줄·상세·메뉴)에서는 아이콘 없이 글자와 색으로 적습니다(긴급은 빨간 배지, 중요는 주황 글자). 배경을 채운 배지는 급한 말 셋(`긴급`·`기한 N일 지남`·`오늘까지`)과 회의의 `초안 N`뿐이고 나머지는 회색·의미색 글자입니다. 우선순위 선택지는 `긴급 / 중요 / 보통 / 낮음`이며 저장하는 값은 그대로입니다.
- 원문이 있는 업무·확인 대기·결정은 제목 바로 뒤에 조용한 `원문` 링크를 늘 보여 주고(새 탭), 상세에서는 제목 아래 `슬랙 원문 열기`로 엽니다.
- 그룹 제목이 프로젝트가 아닌 자리(`진행 중` 그룹, `마감·중요도순` 보기, 서랍, 리마인드, 검색 결과, 확인 대기의 `급한 순`, 새로 들어온 것)에서는 프로젝트를 제목 바로 뒤에 `· ● 이름`으로 적습니다. 지라 프로젝트는 **바깥 화면 어디서나(그룹 제목·프로젝트 탭·주간요약·회의·검색 결과 포함) 요약만** 보여 줍니다(모르면 키 그대로). 같은 요약을 가진 지라 이슈가 한 목록에 둘 이상이면 그때만 뒤에 키를 붙여 구분합니다(`요약 · KEY`). 지라 키가 그대로 보이는 자리는 셋뿐입니다: 항목 상세 카드의 프로젝트 값(요약 뒤에 조용한 회색 글자로 키), 프로젝트 탭 오른쪽의 `열린 항목 N` 줄(`열린 항목 2 · IO-48394`), 마우스를 올렸을 때의 title 툴팁. 프로젝트를 고르는 목록(업무·아이디어의 프로젝트 지정, 주간요약의 프로젝트 선택)은 `요약 · KEY`로 적고 요약 기준으로 정렬합니다. 검색(⌘K)은 키로도 계속 됩니다. 색 점은 프로젝트 이름으로 정해지는 여섯 색 중 하나이며(표기와 무관하게 원래 키로 고릅니다) 같은 이름은 늘 같은 색입니다.
- 확인 대기를 체크하면 알림은 `확인 완료로 표시했어요`만 알리고, 체크한 그 줄이 **`다음은?` 줄**로 바뀌어 다음 행동을 묻습니다: `후속 할 일` · `결정으로 남기기` · `답변 한 줄 남기기` · `닫기`. 체크 자체는 지금처럼 바로 저장되고(⌘Z로 되돌립니다) 이 줄은 제안일 뿐이라 무시해도 됩니다.
  - 나오는 자리는 셋입니다: 왼쪽 레일의 확인 대기 카드(`프로젝트별`·`급한 순` 모두 — 체크한 줄을 목록 맨 위에 한 번 더 그리고 그 아래에 붙습니다), 프로젝트 탭의 확인 대기 구역(같은 방식), 회의 카드·회의 탭의 `이 회의에서 나온 것`(체크한 줄이 남으므로 그 줄 바로 아래). **넓은 두 자리는 위의 버튼 줄 그대로이고, 좁은 레일(296px)에서만 아래의 한 줄 제안으로 줄어듭니다.**
  - **좁은 레일에서는 한 줄만 늘어납니다**: `답을 받았어요 ·` + 제안 하나(파란 글자, 누르면 바로 실행) + `자세히` + `✕`. 제안은 이 확인 대기를 기다리던 미완료 업무가 있으면 `기다리던 업무 N개를 오늘로 →`(누르면 오늘이 아닌 것을 전부 오늘 할 일로 옮기고 `오늘 할 일로 옮겼어요 · N개`, ⌘Z는 업무마다 하나씩), 전부 이미 오늘이면 `기다리던 업무 N개 보기 →`(상세 카드), 기다리던 업무가 없으면 `후속 할 일 만들기 →`(상세 카드를 열면서 그 안의 `후속 할 일` 입력칸까지 바로 엽니다)입니다. `자세히`는 상세 카드를 열고, `✕`는 예전 `닫기`와 같습니다. 자리가 모자라면 앞머리 `답을 받았어요 ·`가 먼저 접히고 제안 글자가 남습니다.
  - 완료한 확인 대기의 **상세 카드**에는 `답변 한 줄` 칸 바로 아래에 `다음은?` 구역이 늘 있습니다 — `후속 할 일` · `결정으로 남기기` · `이 답을 기다리던 업무` 목록을 넓게 그립니다(`답변 한 줄`은 바로 위 칸이 맡으므로 버튼에서 빠지고, 붙박이 구역이라 `닫기`도 없습니다).
  - 이 줄은 알림처럼 몇 초 만에 사라지지 않습니다. `닫기`, 액션 하나를 끝냄, 다른 확인 대기를 체크함(그 줄로 옮겨 갑니다), 탭을 떠남, 새로고침, 체크를 되돌림(⌘Z·다시 체크 해제) 중 하나로 사라집니다. 저장하지 않는 화면 상태라 브라우저를 새로 열면 남지 않습니다.
  - `후속 할 일`은 그 자리에 입력칸을 엽니다 — 확인 대기 문구가 미리 들어가 전체 선택된 상태이고, 프로젝트는 확인 대기와 같게(지라면 같은 지라 이슈) 만듭니다. 오른쪽 `오늘`·`나중에`로 담고 Enter는 `오늘`입니다(한글 조합 중 Enter는 넘깁니다, Esc는 입력만 닫습니다). 기한·우선순위는 넣지 않습니다. 만든 뒤 ⌘Z로 그 업무를 지울 수 있습니다.
  - `결정으로 남기기`는 예전과 같습니다 — 같은 내용·지라/그룹·슬랙 원문으로 정책/얼라인을 만들며, NEW로 표시하지 않습니다.
  - `답변 한 줄 남기기`는 받은 답을 한 줄로 적습니다(1,000자·줄바꿈 없음). 업무의 `결과 한 줄`과 같은 칸에 담겨 주간요약의 `확인 완료` 문장이 됩니다. 완료한 확인 대기의 상세 카드에도 `답변 한 줄` 칸이 있어 나중에 고칠 수 있습니다.
  - 이 확인 대기를 `기다리는 답변`으로 연결해 둔 미완료 업무가 있으면 `이 답을 기다리던 업무`로 한 줄씩(최대 3개, 더 있으면 `외 N개`) 보여 주고 `오늘로`(이미 오늘이면 없습니다)·`열기`를 답니다.
- 입력창 밖에서 ⌘Z(Ctrl+Z)는 되돌리기, ⌘⇧Z(Ctrl+Shift+Z)는 다시 실행입니다. 체크(완료·확인·PRD 반영), 실행 예정일 이동, 우선순위·기한 변경, 삭제, 결정으로 남기기, 회의 항목의 종류 바꾸기, 일괄 정리(오늘 정리 포함 — 한 항목입니다)가 대상이며 최근 30개까지 기억합니다. 새로고침하면 기록은 사라집니다.
- 결정의 상세 카드에는 `내용` 칸(여러 줄, 4,000자)이 있습니다. 정책 결정은 한 줄로 끝나지 않아서 본문을 적어 두는 자리이고, 고치면 바로 저장됩니다. 앱 파일(`.workflow.json`)에만 저장되고 `decisions.md`·주간요약·슬랙 글에는 나가지 않습니다. 아이디어·결정 탭의 결정 줄에는 내용이 있으면 제목 뒤에 조용한 `내용` 표시가 붙습니다.
- 회의 탭의 `빈 회의 포함` 칩에 마우스를 올리면 `아무것도 담지 않은 회의도 함께 보여요`라는 설명이 뜹니다.

키보드 사용자는 맨 앞의 `오늘 할 일로 건너뛰기` 링크로 왼쪽 레일을 건너뛸 수 있습니다(오늘 탭에서만 표시).

## 상세 — 누른 줄 옆에 뜨는 카드

- 업무·확인 대기·회의 정리는 부품 하나를 함께 씁니다. 줄의 본문을 누르면 **그 줄 옆에** 떠 있는 카드가 열립니다(업무·확인 대기 360px, 회의 정리 460px). 회의 정리는 같은 내용이 `회의` 탭의 오른쪽 자리에도 그려집니다 — 내용을 만드는 함수는 하나이고 자리만 둘입니다. 목록은 상세가 열려도 전체 폭을 그대로 쓰고, 누른 줄은 선택 강조로 표시됩니다. 카드가 길면 제목 줄과 아래 동작 줄은 붙박이고 가운데만 스크롤합니다. 목록을 스크롤하면 카드가 줄을 따라가고, 줄이 화면 밖으로 완전히 나가면 닫힙니다. 화면 폭이 520px 이하이면 아래에서 올라오는 시트가 됩니다.
- 상세의 값은 그 자리에서 고칩니다. `언제 할지`·`우선순위`는 값을 누르면 줄의 ⋯와 같은 고르개가 붙고, `기한`·`답변 받을 날`·`다시 확인할 날짜`는 날짜 칸, `누구에게`는 글자 칸, `프로젝트`는 선택 칸입니다. 제목도 눌러서 그 자리에서 고칩니다. **저장 버튼은 없습니다** — 고치면 바로 저장됩니다.
- 업무·확인 대기 카드는 바깥을 누르거나 Esc·✕·같은 줄 다시 누르기로 닫힙니다. **회의 정리 카드만 빈 곳을 눌러도 닫히지 않습니다**(✕·Esc·같은 회의 줄 다시 누르기·다른 줄 열기로 닫습니다) — 한참 붙들고 검토하는 면이라 자리를 잃으면 안 되기 때문입니다.
- 업무 상세의 답변 대기·결과 입력은 접혀 있습니다. 기록된 연결과 결과는 계속 표시하며 편집할 때 펼칩니다. 확인 요청 기록도 보조 영역에 접어 둡니다.

## 회의 탭

- `회의` 탭은 회의를 몰아서 준비하고 정리하는 자리입니다. 왼쪽이 회의 목록, 오른쪽이 고른 회의 하나의 정리 화면이고, 오른쪽에 그려지는 내용은 줄 옆 회의 카드와 **같은 것**입니다(닫기 ✕만 없고 담기 바는 카드 아래에 붙습니다).
- 왼쪽 목록은 보기가 둘입니다 — 목록 위 세그먼트 `날짜순 | 프로젝트별`(기본은 날짜순, 고른 보기는 브라우저에 기억합니다).
  - `날짜순`은 날짜 내림차순이고 날짜마다 조용한 소제목(`오늘` / `9월 14일 (월)`)이 붙습니다. 줄은 시각 + 제목 + 제목 뒤 프로젝트(색 점 + 회색 글자) + 오른쪽 상태(`초안 N` 배지, 없으면 `미완료 N` — 미완료는 할 일·확인 대기만 세고 결정은 세지 않습니다)입니다.
  - `프로젝트별`은 프로젝트 소제목(색 점 + 이름 + 회의 수) 아래로 그 프로젝트의 회의를 날짜 내림차순으로 묶습니다. **미완료 항목이 남은 프로젝트가 먼저**이고 그 안에서는 가장 최근 회의 날짜순이며, `프로젝트 없음`은 맨 끝입니다. 날짜 소제목이 없으므로 줄 맨 앞에 날짜와 시각을 함께 적고(`9/22 10:00`) 프로젝트는 소제목이 이미 말해 주므로 줄에서 뺍니다. 소제목을 누르면 그 프로젝트가 접히고(세션 동안만 기억, 다시 열면 모두 펼쳐진 채로 시작합니다), 지라와 이어진 프로젝트면 소제목 옆에 지금 지라 상태가 범주 색 글자로 조용히 붙습니다(앱이 그 티켓을 직접 읽고 있을 때만).
  - 두 보기 모두 위에 토글 칩 `초안 있음` · `미완료만` · `빈 회의 포함`(툴팁 `아무것도 담지 않은 회의도 함께 보여요`)이 똑같이 걸립니다. 프로젝트로 거르는 드롭다운은 없습니다 — `프로젝트별`에서 다른 프로젝트를 접는 것이 그 자리를 대신합니다(`모두 접기`는 없습니다). 고른 조건·기간·접어 둔 프로젝트는 세션 동안만 기억합니다.
- 기본 목록은 캘린더 회의가 매일 쌓여도 끝없이 길어지지 않도록 **오늘(과 미래) 전부 + 최근 14일 안의 기록 있는 회의(초안이 있거나 이 회의에서 나온 항목이 1개 이상) + 14일보다 오래됐어도 손댈 일이 남은 회의(초안이 있거나 미완료 항목이 있으면)**만 보여 줍니다. 손댈 일이 남은 회의는 기간과 상관없이 절대 숨기지 않습니다. 목록 끝 `이전 회의 더 보기`를 누르면 기간이 14일씩 늘어나고(더 없으면 버튼이 사라집니다), 조용한 토글 `빈 회의 포함`(기본 꺼짐)을 켜면 보이는 기간 안의 기록 없는 지난 회의도 함께 나옵니다. `초안 있음`·`미완료만`을 켜면 기간·기록 유무와 상관없이 전체 회의에서 거릅니다(찾는 행동이므로). `프로젝트별`에서는 이 `더 보기`가 프로젝트마다 `더 보기 N`으로 그 소제목 아래에 붙습니다(어느 프로젝트에도 걸리지 않은 것이 남으면 목록 끝에 `이전 회의 더 보기`가 한 줄 더 섭니다). 목록 밖의 회의를 팔레트나 `회의 탭에서 열기`로 열면 가리고 있던 필터를 끄거나 기간을 넓혀서라도 오른쪽에 그 회의를 엽니다.
- 처음 들어오면 검토할 초안이 있는 회의 중 가장 최근 것을, 없으면 오늘 남은 회의 중 가장 이른 것을, 그것도 없으면 가장 최근 회의를 고른 채로 엽니다. 다른 회의를 골랐다 돌아와도 고쳐 둔 초안 문구는 그대로 남습니다.
- 이 탭에서 업무·확인 대기 제목을 누르면 그 줄 옆에 상세 카드(360px)가 뜹니다. 회의 정리 화면은 뒤에 그대로 있으므로 `← 회의로`는 붙지 않습니다.
- 회의 정리 화면 제목 아래 `9월 19일 (토) 14:00–15:00 · 결제 리뉴얼`에서 **프로젝트 이름을 누르면** 왼쪽이 `프로젝트별`로 바뀌고 그 프로젝트만 펼쳐진 채 그 소제목으로 스크롤합니다(다른 프로젝트는 접힙니다). 줄 옆 회의 카드에는 갈 왼쪽 목록이 없으므로 이 이름은 글자 그대로입니다.
- 오늘 탭 레일의 미팅 줄을 누르면 지금처럼 그 줄 옆에 회의 카드(460px)가 뜹니다. `오늘 미팅` 옆 `전체 보기`와 회의 줄·회의 카드 머리 ⋯의 `회의 탭에서 열기`가 이 탭으로 데려옵니다.
- **미팅 노트 가져오기**는 버튼을 눌렀을 때만 합니다(자동으로 돌지 않습니다 — 티로에서 사람이 먼저 검수합니다). 회의 정리 화면 머리 아래(가져오기 버튼이 서던 그 자리)는 셋 중 하나입니다: 아직 안 가져왔고 이미 시작한 회의(지난 회의도 됩니다)면 `이 회의의 미팅 노트 가져오기`, 이미 가져왔으면 조용한 글자 `미팅 노트 가져옴`(+ 서버가 준 값에 링크가 있으면 `티로에서 열기` — 노트가 여럿이면 `티로에서 열기 1`·`2`…, 초안을 다 검토해 0개가 되어도 이 표시는 남습니다), 시작 전 회의면 아무것도 없습니다.
- 회의 목록 머리 오른쪽 끝도 오늘 가져올 게 있는지로 셋 중 하나입니다: 오늘 이미 시작했고 아직 노트가 없는 회의가 있으면 `오늘 것 모두 가져오기`(+ 그 수), 그 수가 0이 되면 버튼 대신 조용한 글자 `오늘 미팅 노트는 다 가져왔어요`(오늘 시작한 회의가 아직 하나도 없으면 `아직 가져올 미팅 노트가 없어요`) + 옆에 작은 글자 버튼 `다시 확인`(같은 길로 다시 요청합니다 — 한 회의에 노트가 둘인 드문 경우용, 이미 가져온 노트를 다시 읽지는 않습니다). 오늘 미팅 줄 ⋯ 메뉴도 같게 움직입니다(가져올 게 없으면 비활성 문구). 누르면 그 버튼만 `가져오는 중…`이 되고 나머지 가져오기 버튼은 잠깁니다(한 번에 하나). 페이지를 새로 열어도 진행 중이면 같은 표시로 이어집니다.
- 끝나면 목록을 다시 그리고 알립니다. 회의 하나를 가져왔으면 `미팅 노트를 가져왔어요 · 초안 N개`(그 시간에 녹음된 노트가 없었으면 `이 회의 시간에 녹음된 노트를 찾지 못했어요`). `오늘 것 모두 가져오기`는 보내기 전 기억해 둔 수와 비교해서 실제로 늘었으면 `미팅 노트를 가져왔어요 · 회의 N개, 초안 M개`(초안이 0이면 `· 회의 N개`만), 하나도 안 늘었으면 오류가 아니라 `새로 가져올 미팅 노트가 없었어요`로 조용히 알립니다(AI가 돈 뒤 새로 분류할 회의가 없어도 예전처럼 `가져왔어요`라고 하지 않습니다). 실패하면 오류 알림의 `자세히`가 설정 > 상태의 그 줄로 데려갑니다. 오늘 가져온 기록이 있으면 목록 머리에 `오늘 14:20에 가져왔어요`가 조용히 붙습니다. `workspace.config.json`의 `integrations.tiro`를 끄면 버튼·글자·메뉴 항목이 아예 없습니다.

## 프로젝트 · 아이디어·결정 탭

- 왼쪽 프로젝트 목록에서, 연결된 지라 티켓의 **아직 배포되지 않은** 가장 이른 배포일이 **2주 안**이면 열린 항목 수 앞에 조용한 날짜 한 마디가 붙습니다(`9/30`). 3일 안이면 주의색, 지났는데 아직 배포되지 않았으면 급함 색 글자입니다(배지가 아닙니다). 마우스를 올리면 `v2.70.0 · 9월 30일 배포 예정`으로 풀립니다. 날짜는 고정 폭이라 좁아지면 **이름 칸이 먼저** 줄고, 화면이 640px 이하이면 이 날짜는 숨습니다(띠 카드가 같은 말을 합니다). 앱이 지라를 직접 읽지 못하는 동안에는 이 날짜가 나오지 않습니다.
- 지라에 연결된 프로젝트를 열면 제목 줄 아래·첫 구역 위에 **지라 띠 카드**가 섭니다 — 앱 서버가 API 토큰으로 지라를 직접 읽어 온 **지금** 상태입니다(AI를 거치지 않습니다). 첫 줄은 `지라` 표시 + 요약 + `종류 · 담당 ○○` + `지라에서 열기 ↗`(새 탭, 지라 키는 이 링크의 툴팁에만 있습니다) + 작은 새로고침이고, 둘째 줄은 `지라 상태` · `배포 버전` · `기한` 세 칸(라벨 위·값 아래), 셋째 줄은 하위 티켓 줄(`12개 중 7개 완료` + 담당별 개수, 하위가 없으면 줄 자체가 없습니다)입니다. 세 칸의 값은 **눌러서 바꿀 수 있습니다**(아래 `지라 값 바꾸기`). 하위 티켓은 **보기만 합니다**(아래 `하위 티켓 보기`).
  - 값이 없으면 `없음`(회색)입니다. 색은 두 자리에만 붙습니다: 지라 상태는 범주로만(완료는 초록 글자, 할 일은 회색, 진행은 파란 글자 — 배지가 아닙니다), 배포 버전은 배포일이 3일 안이면 주의색(`· 9월 24일 배포 예정 · 2일 남음`), 지났는데 아직 배포되지 않았으면 급함 색(`· 9월 19일 배포 예정 · 3일 지남`)입니다. 이미 배포된 버전은 `· 9월 16일 배포함`입니다.
  - 프로젝트를 **열 때만** 부르고(왼쪽 목록은 아무것도 미리 부르지 않습니다), 부르는 동안은 카드와 높이가 같은 조용한 뼈대가 섭니다. 다른 프로젝트로 빨리 옮기면 늦게 온 응답은 버립니다. 같은 프로젝트를 다시 그리는 것만으로는 다시 부르지 않고, 60초가 지나면 뼈대 없이 조용히 새로 읽습니다. 오른쪽 위 새로고침은 캐시를 건너뛰고 바로 읽어 옵니다.
  - 지라 설정이 없거나 토큰 파일을 못 읽으면 카드 대신 조용한 한 줄 `지라 연결이 필요해요 · 설정 방법`(누르면 아래 `지라 연결 설정` 절을 알려 줍니다)이, 지라가 답하지 않으면 `지라에 연결하지 못했어요 · 다시 시도`가 섭니다. `workspace.config.json`의 `integrations.jira`를 끄면 구역 자체가 없습니다.

### 직접 만든 프로젝트에 지라 티켓 연결

`결제 리뉴얼`·`알림센터`처럼 **직접 만든(그룹) 프로젝트**에도 지라 티켓 **하나**를 손으로 걸 수 있습니다. 걸면 위의 띠 카드가 그대로(읽기도 바꾸기도) 서고, `열린 항목 N · IO-12345` 줄에 키가 붙습니다. **프로젝트 이름과 항목들은 하나도 바뀌지 않습니다** — 붙는 것은 연결 표시뿐이고, 항목이 지라 프로젝트로 옮겨 가지 않습니다.

- 아직 걸지 않은 그룹 프로젝트를 열면 띠 카드가 서는 그 자리에 조용한 글자 버튼 `지라 티켓 연결`이 있습니다(`프로젝트 없음`과 지라 프로젝트에는 없습니다). 누르면 그 자리에 입력 줄이 열립니다.
- 입력칸에는 **번호(`IO-12345`, 소문자로 적어도 됩니다)나 지라 주소를 붙여 넣으면** 됩니다(`…/browse/IO-12345`, `…/issues/IO-12345`, `…?selectedIssue=IO-12345`). 설정한 지라와 주소의 호스트가 다르면 받지 않습니다(`설정한 지라의 주소가 아니에요.`). 입력칸 아래에는 내 담당 지라 목록(`요약 · 키`, 최대 8개, 적는 글자로 걸러집니다)이 조용한 선택지로 함께 뜹니다.
- 그 목록 끝에는 조용한 글자 버튼 **`완료한 티켓도 보기`**가 있습니다 — 끝난 티켓을 프로젝트 기록으로 걸어 두는 경우가 있어서입니다. 누르면 그때 한 번만 **최근 90일 안에 완료된 내 담당 티켓**을 읽어 `완료한 티켓` 소제목 아래에 **회색**으로(`요약 · 키`, 최대 8개) 덧붙입니다. 두 목록은 **같은 입력으로 함께 걸러지고**, 위 목록에 이미 있는 티켓은 두 번 서지 않습니다. 부르는 동안 버튼은 `불러오는 중…`이고, 한 번 받으면 그 입력칸이 열려 있는 동안 다시 부르지 않습니다(닫았다 열면 다시 버튼부터입니다). 골라도 미리 보기 → `연결` 흐름은 그대로입니다. 못 읽으면 버튼은 그대로 있고 그 아래 이유만 조용히 뜹니다.
- `찾기`(또는 Enter)를 누르면 지라에서 읽어 **미리 보기 한 줄**(`요약 · 상태 · 담당 ○○` + 조용한 키)을 보여 줍니다. 여기서 `연결`을 눌러야 저장됩니다 — **미리 보기를 거치지 않으면 연결 요청이 나가지 않습니다.** 못 찾으면 그 자리에 조용한 오류 글자가 뜨고 적은 글자는 그대로 남습니다. 이미 다른 프로젝트에 걸린 티켓이어도 막지 않고 `다른 프로젝트 '○○'에도 연결돼 있어요`라고만 알립니다. Esc는 이 입력만 닫습니다.
- 푸는 것은 띠 카드 첫 줄 오른쪽 ⋯의 `지라 연결 해제`입니다(지라 프로젝트의 카드에는 ⋯이 없습니다 — 풀 연결이 아닙니다). 업무·기록에 영향이 없고 되돌리기가 곧 다시 연결이라 확인 없이 바로 하고, 알림의 `되돌리기`로 같은 티켓을 다시 겁니다(⌘Z 대상은 아닙니다).
- 연결은 `tracker/.workflow.json`의 `projectLinks`에 `"프로젝트 이름": "IO-12345"` 한 줄로만 저장됩니다(앱의 다른 저장과 같은 트랜잭션·복구 규칙을 탑니다). 서버는 저장하기 전에 그 티켓을 **지라에서 실제로 읽어 보고**, 읽히지 않으면 아무것도 저장하지 않습니다. 없는 프로젝트·형식이 틀린 번호·지라 프로젝트(`jira:KEY`)에는 걸리지 않습니다. 그룹의 항목이 모두 사라져 프로젝트가 없어지면 남은 연결은 아무 화면에도 나타나지 않습니다.
- 다른 화면(오늘 목록·왼쪽 프로젝트 목록·주간요약·슬랙 복사)의 이름과 키 표기는 연결해도 그대로입니다.

- `프로젝트` 탭은 왼쪽이 프로젝트 목록, 오른쪽이 고른 프로젝트 하나입니다. 업무, 확인 대기, 결정, 아이디어와 관련 회의를 함께 봅니다. 왼쪽 목록 끝에는 **`지난 프로젝트 N`** 구역이 접힌 채로 있고(하나도 없으면 구역이 없습니다, 펼친 뒤 `지난 프로젝트 숨기기`, 세션 동안만 기억), 아래 `지난 프로젝트` 절의 규칙대로 내려온 프로젝트가 흐린 글자로 모입니다 — 눌러서 여는 것은 위 목록과 같습니다. 머리의 `프로젝트 N`은 **위 목록의** 수입니다(지난 프로젝트는 세지 않습니다). 목록 순서는 탭에 들어오거나 새로고침할 때만 다시 정렬하고, 그 사이(체크 등으로) 다시 그릴 때는 순서를 고정합니다. `진행할 업무`의 열은 체크 · `언제 할지` · 업무 · `기한`입니다 — `우선순위` 열은 없고(체크박스 안의 화살표가 같은 말을 합니다) 정렬은 그대로 마감·중요도순입니다. 목록 어디서든 프로젝트 이름(`· ● 이름`, 그룹 제목)을 누르면 이 탭의 그 프로젝트로 옵니다. 확인 대기·결정 줄 맨 앞에도 그 종류의 체크박스가 있어 바로 체크할 수 있습니다(확인 대기는 확인 완료, 결정은 `PRD 반영함` — 목록의 체크박스와 같은 부품입니다). 확인 대기 구역은 미완료만 보여 주므로 체크하면 목록에서 빠지고, 결정 구역은 반영 완료도 함께 보여 주므로 체크해도 줄은 남고 오른쪽 글자만 반영 날짜로 바뀝니다. 아이디어 줄에는 원문이 있으면 조용한 `원문` 링크가 제목 뒤에 붙습니다. 아이디어·회의 줄에는 체크박스가 없습니다(자리는 비워 제목 시작 위치를 맞춥니다). 확인 대기·결정·아이디어·회의 줄은 할 수 있는 일이 더보기뿐이라 ⋯이 늘 보이고, 그 종류의 목록이 쓰는 메뉴를 그대로 엽니다(확인 대기·결정·아이디어·회의 각각 다른 목록의 메뉴와 같습니다).
- `아이디어·결정` 탭은 왼쪽 아이디어 좁은 칸(약 320px) + 오른쪽 결정 넓은 본문입니다. 결정은 정책 문장이 쌓이는 자리라 말줄임 없이 전문을 줄바꿈해서 보여 주고, 아이디어는 좁은 칸에서 두 줄까지만(그 이상은 말줄임 + title)입니다. 두 칸 모두 프로젝트 그룹 제목으로 묶습니다. 결정 줄에만 `PRD 반영` 체크가 있고, 체크하면 카드 아래 `반영 완료`로 내려갑니다(반영 완료는 최근 반영 순). 결정 줄 아래에는 조용한 정보 한 줄이 있는 것만 붙습니다: 결정한 날짜 · 나온 회의(있으면, 누르면 회의 탭에서 그 회의) · 원문(있으면). 결정 머리줄 오른쪽의 `결정 찾기`는 미반영 결정과 반영 완료를 같은 검색으로 함께 거르고, 찾는 중에는 반영 완료가 자동으로 펼쳐집니다 — 따로 `PRD 미반영만` 보기는 없습니다(체크하면 반영 완료로 내려가므로 위 목록이 이미 미반영 목록입니다). 넓은 창에서는 아이디어 칸이 스크롤해도 자리를 지키고(칸 안에서만 스크롤), 900px 이하에서는 쌓지 않고 머리의 세그먼트(`아이디어 N | 결정 N`)로 한쪽만 봅니다(마지막에 본 쪽을 기억합니다).

### 새 프로젝트 (지라 에픽·하위 티켓 만들기)

왼쪽 목록 머리 `프로젝트 N` 옆의 조용한 **`+`**를 누르면 오른쪽에 **새 프로젝트 화면**이 섭니다(좁은 화면에서는 가로로 흐르는 프로젝트 칩 줄의 맨 앞 칩입니다). 이름과 직군을 고르면 앱이 **지라에 에픽 하나와 직군별 하위 티켓**을 만듭니다. **새로 만든 에픽은 만든 사람(나)에게 자동으로 배정됩니다** — 그래서 만들자마자 왼쪽 프로젝트 목록에도 뜹니다(목록은 내 담당 지라 목록에서 옵니다). **하위 티켓은 배정하지 않습니다**(직군별로 다른 사람에게 갈 수 있어 담당 없음으로 만들어지고, 사람이 지라에서 정합니다). 설명·배포 버전·기한도 넣지 않습니다.

- **이름**(필수)이 곧 에픽 제목이자 앱의 프로젝트 이름입니다.
- **지라** 세그먼트는 셋입니다: `새 에픽 만들기` · `있는 에픽에 붙이기` · `지라 없이`.
  - `새 에픽 만들기`에는 **지라 프로젝트 키**(예: `IO`) 칸이 함께 섭니다. 처음에는 내 담당 티켓에 가장 많이 나오는 프로젝트를 제안하고, 마지막으로 만든 프로젝트를 브라우저에 기억합니다. 칸을 벗어나거나 Enter를 누를 때만 지라에 종류를 물어봅니다.
  - `있는 에픽에 붙이기`는 **위 `지라 티켓 연결`과 같은 입력칸**을 그대로 빌려 씁니다(번호·주소·내 담당 목록·`완료한 티켓도 보기`). 미리 보기에서 `이 에픽에 붙이기`를 누르면 그 에픽이 고정되고 `다시 고르기`로 바꿉니다. **고른 티켓이 에픽이 아니면 서버가 거절합니다.**
  - `지라 없이`는 지라를 부르지 않고 **그룹 프로젝트**만 만듭니다. 항목이 하나도 없으면 프로젝트가 생기지 않으므로 `첫 할 일` 한 줄을 함께 받고(없으면 만들 수 없다고 알립니다), 기존 업무 만들기(`POST /api/later-task/create`)로만 저장합니다.
- **직군**은 설정에 저장된 세트의 체크박스 목록입니다(기본 `Web · iOS · Android · Backend · Design · QA`). 하나도 고르지 않으면 **에픽만** 만듭니다. `직접 입력` 칸에 접두어(`[Data]`)를 적고 Enter·`추가`를 누르면 **이번에만** 쓰이고 설정에는 저장되지 않습니다. 오른쪽 조용한 `직군 목록 고치기`를 누르면 그 자리에서 줄 편집(이름·접두어·삭제·`직군 추가`)이 열리고 `저장`이 설정 세트를 갱신합니다.
  - `있는 에픽에 붙이기`에서 그 에픽에 **같은 접두어의 하위가 이미 있으면** 그 줄은 회색 `이미 있어요 IO-48401`이 되고 체크가 꺼집니다(켜면 한 번 더 만듭니다).
- **하위 티켓 종류**는 지라가 그 프로젝트에서 허용하는 **표준 타입**(하위 작업 제외, 에픽 제외) 중에서 고릅니다. 기본은 이름에 `작업`/`Task`가 있는 것이고, 허용 타입이 하나면 고르개 없이 `하위 티켓 종류 · 작업`이라고만 적습니다. 고른 값은 프로젝트마다 브라우저에 기억합니다.
- **미리 보기**는 이름·직군을 채우면 자동으로 따라옵니다. 첫 줄은 `에픽 · 이름 · (새로 만듦 / IO-48394에 붙임)`이고 그 아래 `├`·`└` 하위 줄이 섭니다. 하위 제목은 **`접두어 + 공백 + 이름`**이고 **그 자리에서 고칠 수 있습니다**(한 줄, 255자). 종류와 `담당 없음`이 줄 끝에 조용히 붙습니다.
- 주 버튼은 `지라에 N개 만들기`(에픽을 함께 셉니다. `지라 없이`면 `프로젝트 만들기`)입니다. 누르면 곧바로 나가지 않고 **확인 줄**(`지라에 이슈 N개를 만들까요? 되돌릴 수 없어요.` + `취소`/`만들기`)이 한 번 더 섭니다 — **확인을 거치지 않으면 만들기 요청이 나가지 않습니다.** 보낼 수 없는 상태면 버튼 아래에 이유가 조용히 적힙니다.
- 지라에 만드는 것은 **⌘Z 되돌리기 대상이 아닙니다**(지라에 여러 이슈를 만드는 일은 되돌릴 수 없습니다) — 확인 줄이 그 안전장치입니다.
- **만든 뒤**에는 같은 자리에 결과가 섭니다: 성공이면 `지라에 3개를 만들었어요`, 일부가 실패하면 `만들어진 것 3 · 실패 1`과 실패한 줄의 이유(`지라에서 이 프로젝트에 이슈를 만들 권한이 없어요` · `지라가 이 값을 받아들이지 않았어요 — 필수 항목이 더 있을 수 있어요…`)입니다. `실패한 것 다시 시도`는 **실패한 줄만** 이미 만든 에픽에 붙여 다시 보냅니다(에픽을 두 번 만들지 않습니다). `지라에서 열기`는 그 에픽을 새 탭으로 엽니다. **에픽 자체가 실패하면 하위는 시작하지도 않습니다**(아무것도 만들어지지 않습니다). 에픽은 만들어졌는데 나에게 배정하는 것만 실패했으면(권한 등) 그 줄에 조용한 회색 글자로 `담당자 지정은 안 됐어요 — 지라에서 직접 정해 주세요`가 붙습니다 — 만들기 자체는 성공이라 급한 색을 쓰지 않습니다.
- 새 에픽이 만들어지면(있는 에픽에 붙일 때는 아닙니다) 화면이 헤더 새로고침과 같은 조용한 길로 `GET /api/jira/list?fresh=1`을 한 번 부른 뒤 목록을 다시 받습니다 — 실패해도 알리지 않습니다. 방금 나에게 배정된 에픽이 곧바로 왼쪽 프로젝트 목록에 뜨는 것이 이 부름 덕분입니다.
- 결과 아래 `첫 할 일` 한 줄이 있습니다(**선택**) — 새 에픽은 이미 나에게 배정돼 프로젝트 목록에 떴으므로 꼭 적을 필요는 없고, 바로 업무를 하나 만들고 싶을 때만 적습니다. 적고 Enter·`만들고 프로젝트 열기`를 누르면 그 프로젝트가 열립니다.
- 서버는 `GET /api/jira/create-meta?project=IO`(조회, 프로젝트마다 60초 메모리 캐시, 파일 안 씀)와 `POST /api/jira/create`(`{ plan: { projectKey, epic: { key? , summary? }, children: [{ summary, issueTypeId }] } }`) 둘을 씁니다. 만들기는 **순서대로 하나씩** 보내고 결과를 `{ epic: {key,url,summary,created,assigned?,assignError?}, children: [{summary,key,url}|{summary,error}], made, failed }`로 돌려줍니다(하나 실패해도 다음은 계속). **새로 만든 에픽만** 만든 직후 나에게 배정합니다(`assigned:true` 또는 실패 문구가 담긴 `assignError`) — 있는 에픽에 붙일 때는 재배정하지 않으므로(남의 에픽일 수 있어) 그 칸 자체가 없고, 하위 티켓은 배정을 아예 시도하지 않습니다(담당 없음 그대로). 누가 나인지는 반응 필요(BATTENTION)와 같은 서버 메모리 값을 그대로 재사용해 프로세스마다 한 번만 묻고(`GET .../myself`), 이 조회 자체가 실패하면 **아무것도 만들지 않은 채로 전체를 중단**합니다("만들어졌는데 담당자가 없는" 상태를 만들지 않기 위해서입니다). 검증: 요약 1~255자·줄바꿈 없음, 하위 12개까지, 프로젝트 키 형식, 에픽 키의 프로젝트가 같은지, **issueTypeId는 쓰기 직전에 다시 읽은 종류 목록에 있는 것만**, 붙일 에픽이 실제로 에픽인지(계층 1). 같은 계획을 **60초 안에 두 번 받으면 거절**합니다(중복 생성 방지 — 서버 메모리에만 남는 지문이고, 아무것도 만들지 못한 요청은 지문을 남기지 않습니다). 앱 파일은 하나도 쓰지 않으므로 `idempotent()`·mutation-store를 타지 않지만, 저장이 멈춘 **복구 필요 상태에서는 지라 만들기도 막힙니다**.
- **직군 세트**는 `tracker/.workflow.json`의 `jiraRoles`(`[{ "label": "Web", "prefix": "[Web]" }]`)에 앱의 다른 저장과 같은 트랜잭션·복구 규칙으로 저장됩니다(`POST /api/workflow/jira-roles`, 20개까지·이름 30자·접두어 20자·같은 이름 금지). `workspace.config.json`은 사람이 고치는 파일이라 앱이 쓰지 않습니다. 칸이 없으면 화면이 기본 세트를 쓰고, 전부 지우면 빈 목록 그대로입니다.

### 지난 프로젝트

지라 프로젝트는 티켓이 끝나면 목록에서 저절로 빠지지만, 직접 만든 프로젝트는 쌓이기만 했습니다. **보관은 화면의 왼쪽 목록 배치와 프로젝트 고르기 목록의 소제목만 바꿉니다** — 업무·기록·주간요약·검색·슬랙 복사는 하나도 달라지지 않습니다.

- **자동으로 내려가는 것(저장하지 않습니다).** 열린 항목(열린 업무 + 열린 확인 대기)이 **0개**이고, 마지막 활동이 **14일** 넘게 없는 프로젝트입니다. 마지막 활동은 그 프로젝트 항목들의 완료·수정·등록 날짜와, 그 프로젝트에 걸린 회의 날짜 중 **가장 최근**입니다(있는 값만 봅니다 — 날짜를 지어내지 않습니다). 아는 날짜가 하나도 없으면 조용한 것으로 봅니다. 열린 항목이 0이어도 **아직 14일이 안 된 프로젝트는 위 목록에 남습니다.** 새 항목이 들어오거나 미완료가 생기면 저절로 위로 올라옵니다.
- **직접 보관하는 것(저장합니다).** 오른쪽 프로젝트 제목 옆 ⋯에서 `보관`(보관 중이면 `보관 해제`)을 고릅니다. 확인 없이 바로 하고 알림의 `되돌리기`로 되돌립니다(⌘Z 대상은 아닙니다). 지라 프로젝트도 직접 만든 프로젝트도 됩니다. 보관한 프로젝트는 **미완료가 생겨도 보관 상태를 유지**하고, 그 프로젝트를 열면 제목 아래가 `보관한 프로젝트 · 열린 항목 2`라고 알려 줍니다(꺼낼지는 사람이 정합니다).
- **정리 권유.** 자동으로 내려왔지만 아직 보관하지 않은 프로젝트가 있으면 구역 머리 아래에 조용한 한 줄 `조용한 프로젝트 3개 · 보관할까요?` + `모두 보관`이 섭니다. `모두 보관`은 한 건씩 보내고, 막히면 거기까지만 알린 뒤 `3개를 보관했어요` + `되돌리기`로 마칩니다. 없으면 줄 자체가 없습니다.
- **지금 보고 있는 프로젝트**는 구역이 바뀌어도 보는 동안 위 목록에 자리를 지킵니다(0개가 되어도 사라지지 않던 기존 규칙과 같습니다).
- 항목에 프로젝트를 지정하는 **고르기 목록**에는 보관한 프로젝트도 그대로 있고, 목록 끝의 `지난 프로젝트` 소제목 아래로 갈 뿐입니다.
- 보관은 `tracker/.workflow.json`의 `projectArchive`에 `"group:결제 리뉴얼": "2026-09-25"` 한 줄로만 저장됩니다(앱의 다른 저장과 같은 트랜잭션·복구 규칙을 탑니다). 없는 그룹·형식이 틀린 키에는 걸리지 않고, 프로젝트가 없어져 고아가 된 줄은 아무 화면에도 나타나지 않습니다.

### 프로젝트 이름 바꾸기

**직접 만든(그룹) 프로젝트**의 이름은 프로젝트 제목 옆 ⋯의 `이름 바꾸기`로 고칩니다. 지라 프로젝트에는 이 항목이 없고(이름이 지라 요약입니다) 제목에 마우스를 올리면 `이름은 지라 요약을 따라요`라고 알려 줍니다.

- 고르면 제목 자리가 그대로 입력칸이 됩니다(현재 이름이 전체 선택된 채). Enter 또는 `저장`으로 보내고 Esc 또는 `취소`로 되돌립니다(한글을 조합하는 중의 Enter는 글자를 확정하는 것이라 넘깁니다).
- 저장하면 `이름을 바꿨어요 · 옛 이름 → 새 이름` + `되돌리기`(반대 방향으로 한 번 더 바꿉니다 — ⌘Z 대상은 아닙니다)로 알리고, 목록을 다시 읽어 **새 이름의 프로젝트가 열린 채로** 남습니다.
- 서버(`POST /api/project/rename`)는 **한 트랜잭션**에서 다섯 자리를 함께 바꿉니다: ① `tasks.md`·`checks.md`·`decisions.md`·`ideas.md`의 `group:`(아이디어는 `project:`) 칸 — 파일 표기의 공백→밑줄 규칙은 그대로입니다, ② `.workflow.json`의 회의 프로젝트, ③ 같은 파일의 `projectLinks` 키(수동 지라 연결), ④ `projectArchive` 키(보관), ⑤ `.meeting_links.json`의 `group:` 값, ⑥ 주간요약 저장본(`.report-drafts.json`)의 그룹 이름(문장·연결은 손대지 않고 소제목·묶음 열쇠·근거 이름표만). **하나라도 실패하면 전부 되돌아갑니다** — 반쯤 바뀐 이름을 남기지 않습니다. 응답은 `{ ok, project, from, to, changed: { items, meetings, links, archive, report } }`이고 `meetings`는 ②와 ⑤를 함께 셉니다.
- 거절하는 경우: 지라 프로젝트(`jira:KEY`)나 `group:`이 아닌 값, 앱이 모르는 프로젝트, 60자를 넘거나 비어 있거나 줄바꿈·대괄호가 든 이름, 지금과 같은 이름, 다른 그룹·지라 요약과 겹치는 이름(공백·대소문자를 고르게 맞춰 봅니다). 거절된 요청은 어떤 파일도 고치지 않고, 저장이 멈춘 **복구 필요 상태에서는 503**입니다.
- 색 점은 프로젝트 이름으로 정해지므로 이름을 바꾸면 색도 함께 바뀝니다(같은 이름은 어디서나 같은 색이라는 규칙 그대로입니다).

### 지라 값 바꾸기

띠 카드의 `지라 상태` · `배포 버전` · `기한`은 상세 카드와 같은 값 고르개(값 + 작은 꺾쇠)입니다. 지라에 쓰는 동작이라 **고른 값은 곧바로 나가지 않습니다** — 카드 안에 확인 줄이 서고 거기서 `바꾸기`를 눌러야 보냅니다.

- 확인 줄은 `지라의 이 티켓을 바꿀까요?` + 티켓 **요약**(지라 키는 그 아래 조용한 글자) + `지라 상태: 진행 중 → 완료`(전 → 후) + `취소`/`바꾸기`입니다. Esc · 바깥 클릭 · `취소`로 닫히고, 닫으면 아무것도 보내지 않습니다.
- 성공하면 알림 `지라에서 바꿨어요`에 `지라에서 열기`가 붙고, 카드는 지라에서 **다시 읽어** 그린 값만 보여 줍니다(앱이 미리 바꿔 두지 않습니다). 실패하면 아무것도 바뀌지 않고 이유만 알립니다(`지라에서 이 티켓을 바꿀 권한이 없어요` · `지라가 이 변경을 받아들이지 않았어요. 지라에서 직접 확인해 주세요` · `지라에서 이 티켓을 찾지 못했어요` · `지라에 반영하지 못했어요`).
- 지라에 쓰는 것은 **⌘Z 되돌리기 대상이 아닙니다**(지라 쪽 규칙 때문에 되돌릴 수 없을 수 있습니다) — 확인 줄이 그 안전장치입니다. 보내는 동안에는 세 고르개와 새로고침이 모두 잠깁니다.
- `지라 상태`는 지라가 그 티켓에 허용하는 전환만 내놓습니다(같은 이름이 둘이면 전환 이름을 괄호로 붙입니다). 선택지 글씨도 카드 값과 같은 범주 색입니다(완료 초록·할 일 회색·진행 파랑). 지라에서 **입력 화면을 거쳐야 하는 전환**은 앱에서 바꾸지 않고 `이 전환은 지라에서 직접 해 주세요 · 지라에서 열기`로 안내합니다.
- `배포 버전` 메뉴는 둘입니다. ① `이 티켓을 다른 버전으로` — 아직 배포되지 않은 버전과 `버전 없음` 중에서 고릅니다. **버전이 여러 개 걸린 티켓은 앱에서 바꾸지 않습니다**(`버전이 여러 개라 지라에서 직접 바꿔 주세요`) — 다른 버전을 실수로 지우지 않기 위해서입니다. ② `이 버전 고치기` — 버전의 이름·배포일을 고칩니다. 이것은 **그 버전을 쓰는 모든 티켓에 적용되므로** 확인 줄이 `이 버전을 쓰는 모든 티켓에 적용돼요`라고 함께 말합니다.
- `기한`은 날짜 칸이고 ✕로 지울 수 있습니다.
- 앱이 지라에 **쓰는** 요청은 다섯입니다: `POST {siteUrl}/rest/api/3/issue/{KEY}/transitions`(`{ transition: { id } }`), `PUT {siteUrl}/rest/api/3/issue/{KEY}`(`{ fields: { fixVersions } }` 또는 `{ fields: { duedate } }`), `PUT {siteUrl}/rest/api/3/version/{ID}`(바뀐 칸만), 새 프로젝트 화면의 `POST {siteUrl}/rest/api/3/issue`(`{ fields: { project: { key }, issuetype: { id }, summary, parent?: { key } } }`), 그리고 새로 만든 에픽에만 쓰는 `PUT {siteUrl}/rest/api/3/issue/{KEY}/assignee`(`{ accountId }` — 이 값은 내 계정 식별자일 뿐 이메일이 아니고, 응답·로그·화면 어디에도 실리지 않습니다) — 이 다섯 칸이 전부입니다. 만들 수 있는 종류는 `GET {siteUrl}/rest/api/3/issue/createmeta/{KEY}/issuetypes`로 읽고, 그 주소가 없는 지라에서는 `…/createmeta?projectKeys={KEY}&expand=projects.issuetypes`로 한 번 물러섭니다. 서버는 보내기 **직전에** 전환 목록·버전 목록·만들 수 있는 종류를 지라에서 다시 읽어 고른 id가 아직 유효한지 대조하고, 아니면 보내지 않습니다. 저장이 멈춘 **복구 필요 상태에서는 지라 쓰기도 막힙니다**(앱 기록이 아픈 동안 바깥에도 쓰지 않습니다). 새 프로젝트 화면의 지라 토큰은 **이슈 만들기 + 담당자 지정** 권한이 있어야 합니다 — 권한이 없으면 만들기는 되고 배정만 조용한 실패 문구로 남습니다.

### 하위 티켓 보기

띠 카드 맨 아래 줄이 하위 티켓입니다 — 진행률(`12개 중 7개 완료`) 뒤에 **아직 안 끝난 것의 담당별 개수**(`엘리 2 · 담당 없음 2 · 루본 1`, 많은 순·같으면 가나다·`담당 없음`은 맨 뒤, 최대 4명이고 넘으면 `외 N명`)가 붙고, 줄 오른쪽 끝 꺾쇠로 목록을 폅니다. 다 끝났으면 이름 자리에 `모두 완료`, 하위가 하나도 없으면 줄 자체가 없습니다.

- 펼치면 티켓마다 한 줄입니다: `지라 상태`(범주로만 색 — 완료는 초록, 할 일은 회색, 진행은 파랑) · **요약**(누르면 지라가 새 탭으로 열립니다, 지라 키는 툴팁에만) · **담당자**(없으면 회색 `담당 없음`) · 조용한 배포 버전. 좁은 화면(≤640px)에서는 담당자가 요약 아래 줄로 내려가고 배포 버전은 숨습니다.
- 순서는 아직 안 끝난 것 먼저(진행 → 할 일)고 끝난 것은 맨 아래 흐리게 섭니다. 완료가 다섯 개를 넘으면 나머지는 `완료 N개 더 보기` 뒤로 접힙니다. 지라에서 읽어 오는 것은 100개까지고, 다 차면 목록 끝에 `지라에서 전체 보기 ↗`가 붙습니다.
- **담당별 개수의 이름을 누르면 그 사람 것만 보입니다**(접혀 있었으면 함께 펼쳐집니다). 다시 누르거나 파란 `전체`를 누르면 풀립니다. 따로 토글이나 드롭다운은 없습니다.
- 펼쳤는지는 프로젝트마다 브라우저에 기억해 둡니다(기억할 수 없는 창에서도 펼치기는 그대로 동작합니다). 거르기는 기억하지 않고, 다른 프로젝트로 옮기면 풀립니다. 값을 바꿔 카드를 다시 읽어도 펼침과 거르기는 그대로 남습니다.
- 하위 티켓은 **보기만 합니다** — 앱에서 상태나 담당을 바꾸는 길은 없고, 할 일로 가져오는 것도 없습니다. 고칠 일은 줄을 눌러 지라에서 합니다.

## 업무·회의 연결

- 오늘 미팅 옆 `전체 보기`를 누르면 `회의` 탭으로 갑니다(위 `회의 탭` 절). 회의 상세에서 만든 항목은 회차에 연결되며 실제 업무의 현재 상태를 표시합니다. `기존 항목 연결`은 같은 프로젝트의 기존 항목을 복제 없이 연결합니다.
- 오늘 미팅 카드에는 검토할 AI 초안이 있으면 `초안 N` 배지가 붙습니다. ⌘K 팔레트의 `회의` 칩으로는 회의를 **낱말로 찾습니다**(제목·시리즈·프로젝트와 초안 문구·그 회의에서 나온 항목까지). 결과를 열면 `회의` 탭에서 그 회의를 고른 채로 열리고, 목록 바닥의 `회의 탭에서 모두 보기`로도 갈 수 있습니다.
- 회의를 열면 미팅 노트(티로)에서 AI가 분류한 초안이 회의 정리 카드 안에 나옵니다. 카드마다 종류(할 일·확인 대기·결정)를 버튼으로 바꾸고, 문구는 여러 줄로 전부 보이는 입력칸에서 고치거나 ✕로 뺍니다. 할 일 카드에는 `나중에 할 일 | 오늘 할 일`을 고를 수 있고(기본은 나중), 카드 아래에 고정된 `N개 담기`로 한꺼번에 담습니다. 카드에서 날짜도 정합니다: 할 일은 `기한`, 확인 대기는 `답변 받을 날`(비어 있으면 `+ 기한`/`+ 답변 받을 날`). 초안에 있던 마감은 바꾸거나 지울 수 있고, AI는 확인 대기 날짜를 채우지 않습니다. 직접 적어 담기(`직접 적어 담기`)는 검토할 초안이 있는 회의에서는 접혀 있고, 초안이 없으면 펼쳐져 있으며 같은 날짜 칸을 씁니다. AI가 문구 끝에 붙여 온 `(방향 확인 필요)` 표식은 떼어 내고 보여 주며 항목 문구로도 저장하지 않습니다. 초안 카드는 문구를 맨 위에 크게 보여 주고 종류·시점·날짜는 그 아래 작게 두며, 카드 왼쪽 띠와 아래 항목 목록의 종류 칩은 같은 색입니다(할 일 파랑 · 확인 대기 주황 · 결정 회색).
- 담은 직후 결과 카드는 한 줄로 종류별 개수를 알려 주고, 나중에 담긴 할 일 옆에 `오늘로` 버튼을 둡니다(할 일이 넷 이상이면 `모두 오늘로` 한 줄, 올리고 나면 `오늘 할 일 ✓`). 처음부터 오늘로 고른 할 일은 `오늘 할 일 ✓`로 보입니다. 카드 맨 아래 `다음: ○○ (초안 N) →` 링크가 초안이 남은 다음 회의를 열어 줍니다. `실행 취소`를 누르면 방금 담은 항목이 삭제 휴지통(`tracker/.trash.json`, 원문 보존)으로 옮겨지고 초안이 다시 검토 대기로 올라옵니다(고친 종류·문구·시점은 유지). `다음 검토` 버튼은 초안이 남은 다음 회의로 이어서 엽니다(자동으로 넘어가지는 않습니다).
- `이 회의에서 나온 것`은 **종류 소제목**(`할 일 3` · `확인 대기 1` · `결정 2` — 버그는 할 일에 들어갑니다)으로 나뉘고, 소제목이 종류를 말해 주므로 줄에서는 종류 글자를 뺍니다. 한 종류 안에 프로젝트가 **둘 이상**일 때만 그 아래를 프로젝트 소제목(`· ● 알림센터`)으로 한 번 더 나눕니다 — 하나뿐이면 나누지 않습니다(부서 간 회의처럼 한 회의에서 여러 프로젝트 일이 나올 때를 위한 것입니다). 종류가 하나뿐인 회의에는 소제목을 세우지 않습니다 — 구역 제목이 이미 개수를 말하고, 줄의 종류 글자도 그대로 남습니다. 이 회의의 프로젝트가 아닌 항목은 줄 제목 뒤에 `· ● 이름`으로 적고, 프로젝트 소제목으로 이미 나눈 자리에서는 되풀이하지 않습니다. `이전 회차의 미해결 항목`도 같은 종류 소제목을 쓰지만 프로젝트로 나누지는 않습니다(줄마다 회차 표기가 이미 있습니다). 회의 탭과 줄 옆 회의 카드가 같은 함수를 씁니다.
- `이 회의에서 나온 것`과 `이전 회차의 미해결 항목`의 각 줄은 그 자리에서 고칩니다. 줄 맨 앞에는 그 종류의 체크박스가 있어(할 일·버그는 완료, 확인 대기는 확인 완료, 결정은 `PRD 반영함` — 목록에서 쓰는 체크박스와 같은 부품) 바로 체크할 수 있습니다. 체크하면 목록과 같은 완료 순간(체크 → 줄 긋기 → 옅어짐)을 거쳐 저장되고 회의 카드는 열린 채로 그 줄이 완료 모양으로 남습니다(⌘Z로 되돌릴 수 있습니다). `이전 회차의 미해결 항목`은 미해결만 보여 주므로 체크하면 그 줄이 구역에서 빠집니다(구역에 남은 항목이 없으면 구역째 사라집니다). 아이디어가 섞여 있으면 그 줄은 체크박스 없이 자리만 비웁니다. 문구를 고치는 동안은 그 줄의 체크박스를 누를 수 없습니다. 이 줄에서 할 수 있는 다른 일은 더보기뿐이라 ⋯이 늘 보이고(평소 흐리게, 손이 닿으면 진하게), 메뉴는 목록에서 쓰는 것과 같습니다 — 할 일·버그는 업무 줄 메뉴(언제 할지·기한·우선순위·프로젝트), 확인 대기는 확인 대기 줄 메뉴(다시 확인할 날짜·답변 받을 날·누구에게·프로젝트), 결정은 결정 줄 메뉴(프로젝트)이고, 맨 위에 `문구 고치기`가 붙습니다. `문구 고치기`를 고르면 제목이 입력칸으로 바뀌어 Enter로 저장하고 Esc로 되돌립니다(Esc는 회의 카드를 닫지 않습니다). 할 일·확인 대기는 제목을 누르면 상세가 열리고, 상세가 없는 결정은 제목을 누르는 것이 곧 `문구 고치기`입니다. 완료한 항목도 고치고 지울 수 있으며, 삭제는 목록과 같은 길(삭제 알림의 `삭제 실행 취소` · ⌘Z)입니다. 고치거나 지운 뒤에도 회의 카드는 열려 있고 `이 회의에서 나온 것 N`이 함께 바뀝니다. 담은 항목의 종류는 ⋯의 `종류 바꾸기`로 바꿉니다(아래 줄).
- `이 회의에서 나온 것` 줄의 ⋯에는 `종류 바꾸기 ▸ 할 일 / 확인 대기 / 결정`이 있습니다. 새 항목을 만드는 것이 아니라 **같은 id로 항목을 다른 파일로 옮기므로** 회의 연결과 검토 기록이 그대로 남습니다(종류에 맞지 않는 칸 — 결정으로 가면 기한·예정일·우선순위, 확인 대기로 가면 기다리는 답변 연결 등 — 은 버립니다). 완료한 항목은 바꿀 수 없습니다. 알림의 `되돌리기`와 ⌘Z로 되돌립니다.
- 서버 시작과 캘린더 파일 변경 시 관측한 오늘 회의를 `.workflow.json`에 보존합니다. 이미 덮어써져 남아 있지 않은 과거 일정은 복원하지 않습니다. 서버가 꺼져 있는 동안 지나간 일정도 수집할 수 없습니다.
- 같은 제목은 기본적으로 같은 시리즈입니다. 회의 상세에는 프로젝트·반복 회의 입력을 두지 않고, 프로젝트는 오늘 미팅 줄의 ⋯ 또는 회의 정리 카드 머리의 ⋯(업무 상세 카드와 같은 자리, ✕ 왼쪽) → `프로젝트 연결`에서 바꿉니다 — 두 곳이 같은 메뉴를 씁니다. 프로젝트를 바꾼 뒤에도 카드는 열린 채로 머리의 `오늘 16:00–17:00 · 프로젝트` 글자가 갱신됩니다. 이전 회차의 미해결 항목은 이동·복제하지 않고 연결된 원본으로 보여 줍니다.
- 확인 대기의 `다시 확인할 날짜`에서 재확인 날짜와 오늘 확인 요청 기록을 남깁니다. 답변 받을 날은 바뀌지 않습니다. 오늘 확인 요청을 기록한 항목은 당일 재확인 알림에서 제외됩니다.
- 업무 상세에서 기다리는 확인 대기를 연결합니다. 미해결이면 답변 대기, 해결되면 진행 가능으로 표시합니다. 미해결 업무는 나중 목록에서 오늘로 가져오는 추천에서 제외합니다.
- 완료 결과는 업무 상세의 `결과 한 줄`(확인 대기는 `답변 한 줄`)에 기록합니다. 보고 초안은 결과가 있으면 그 문구를 우선 사용하며, 이미 직접 고친 보고 문장은 덮어쓰지 않고 수정 제안으로만 보여 줍니다.
- 추가 메타데이터는 `tracker/.workflow.json`에 원본 ID로 연결해 저장합니다. 파일은 임시 파일 작성 후 교체하며, 조회 API는 읽기 전용입니다.

## 빠른 정리와 검색

- 오늘 할 일 머리줄의 ⋯ → `여러 개 선택`에서 오늘 목록과 나중에 할 일 서랍의 미완료 업무를 함께 고릅니다. 선택 모드에서는 완료 체크 왼쪽에 선택 칸이 한 칸 더 생기고, 화면 아래 막대에서 `전체 선택` · `오늘로` · `내일` · `나중에` · `날짜…` · `프로젝트…` · `완료로 표시` · `삭제` · `선택 끝내기`를 합니다. 아무것도 고르지 않았으면 바꾸는 버튼은 눌리지 않습니다. 기한은 유지됩니다.
- 날짜·프로젝트·완료는 `/api/workflow/task-batch` 한 곳으로 갑니다. `change`는 한 번에 하나이고 `{scheduled}` · `{project}` · `{status:'done'}`만 받습니다(완료 취소는 줄마다 체크로 되돌리고, 완료일은 서버가 오늘로 적습니다). 일괄 변경은 모든 대상과 값을 검증한 뒤 저장하며, 알림의 실행 취소와 기존 ⌘Z/다시 실행으로 되돌립니다. 변경한 속성을 나중에 다시 편집했다면 취소가 해당 편집을 덮어쓰지 않도록 거절합니다. 서버 재시작 시 일괄 취소 기록은 만료됩니다.
- 오늘 할 일 머리줄 ⋯의 `오늘 정리`도 이 길 하나만 씁니다 — 갈래(완료·내일·나중에)마다 한 번씩 보내고 되돌리기는 항목 하나입니다(오늘 탭 절).
- 일괄 삭제만 서버 경로가 따로 없습니다. 고른 순서대로 한 건씩 `/api/track/remove`로 휴지통에 보내고(원문 보존) 알림 하나의 `되돌리기`로 역순 복원합니다. 중간에 실패하면 멈추고 어디까지 지웠는지 알립니다.
- 헤더의 `검색`(⌘K)은 위에서 내려오는 팔레트 하나이고 **찾는 창**입니다. 완료 업무, 결과 한 줄, 결정, 확인 대기, 아이디어, 회의와 앱에 수집된 회의 초안 문구를 찾습니다(외부 미팅 노트 전문은 찾지 않습니다). 종류 칩 `전체 · 할 일 · 확인 대기 · 결정 · 아이디어 · 회의`와 토글 칩 `완료 제외`가 있고, 회의를 훑어보며 거르는 `초안 있음` · `미완료만`은 `회의` 탭에 있습니다. `오늘 신규 N`은 같은 팔레트를 필터만 다르게 엽니다. ↑↓로 옮기고 Enter로 열며 Esc로 닫습니다. 항목을 열었다가 뒤로 가면 검색어·필터·스크롤 자리가 그대로 남습니다 — 다만 회의는 `회의` 탭에서 열리므로 팔레트로 돌아가지 않습니다.
- 검색 결과 줄에서 할 일·버그·확인 대기는 바로 처리합니다(결정·아이디어·회의는 대상이 아닙니다). 맨 앞 체크박스는 목록과 같은 완료 체크(`toggleTask`)이고, 완료가 아니고 오늘이 아닌 할 일·버그에는 오른쪽에 조용한 글자 버튼 `오늘로`가 하나 더 붙어 목록과 같은 `/api/track/set-scheduled`로 오늘 할 일로 옮깁니다(확인 대기는 `scheduled`가 아니라 답변 받을 날 개념이라 대상이 아닙니다). 두 동작 모두 줄 열기로 번지지 않고, 처리한 뒤에도 팔레트는 열린 채로 남아 결과를 이어서 처리할 수 있습니다.

## 주간보고

주간요약 탭은 업무 원본에서 보고 초안을 생성합니다. 프로젝트·상태와 공통 문구/회의/원본 링크를 기준으로 보수적으로 묶으며, 외부 AI 호출이나 결과 추측은 하지 않습니다. 완료·진행·결정은 구분하고, 결과 한 줄(확인 대기는 답변 한 줄)이 있으면 사용합니다 — `확인 완료` 문장은 답변 한 줄이 있으면 그 문구가 됩니다.

화면은 세 칸입니다: 주차 목록 | 보고 문서 | 슬랙 미리보기(1120px 이하에서는 미리보기가 문서 아래로 내려옵니다). 문서는 `보고`와 `전체 업무 기록` 두 모드를 세그먼트로 오갑니다.

- 문장 수정은 원본 업무를 변경하지 않습니다. 새 관련 업무는 수정 제안으로 나타납니다.
- 근거 업무를 펼쳐 원본을 확인하고, 제외한 업무는 `전체 업무 기록`에서 복원합니다. `전체 업무 기록`의 각 줄에는 늘 보이는 ⋯이 있어(할 수 있는 일이 더보기뿐입니다) 맨 위에서 `보고에서 제외`(이미 제외됐으면 `보고에 복원`)를 바로 하고, 그 아래는 업무 종류의 목록 메뉴(할 일·확인 대기·결정)를 그대로 씁니다.
- 문장 줄의 ⋯에서 `이 아래로 문장 모으기`를 고르면 **모으기 모드**가 됩니다. 기준 문장이 연파랑 바탕 + `여기 아래로`로 표시되고, 넣을 수 있는 문장(같은 상태 · 최상위 · 아래에 문장이 없는 것)만 밝게 서서 눌리는 과녁이 됩니다. 문장을 누르면 **그 자리에서 바로** 기준 문장 아래로 한 단계 들어가고 모드는 그대로 남아 여러 개를 연달아 넣습니다. 아래 막대의 `완료`·Esc·다른 탭/주차로 이동하면 끝납니다. 모드 중에는 줄의 `수정`·`제외`·⋯이 눌리지 않습니다(누르는 것이 곧 "넣기"라서).
- 아래로 넣은 문장은 **글자를 합치지 않습니다** — 독립된 문장으로 남아 따로 고치고 제외하고 자동 갱신됩니다. 문서에서는 부모 아래 들여 쓴 `◦` 줄이 되고(프로젝트가 부모와 다르면 글 뒤에 조용히 이름을 적습니다), 슬랙 글에서는 부모 항목의 `◦` 부연으로 나갑니다(그 이름은 슬랙에 나가지 않습니다). 문서의 프로젝트 소제목은 **부모의 프로젝트** 기준입니다. 줄의 `따로 빼기`(⋯에도 있습니다)로 원래 자리로 되돌립니다. 서버에서는 `/api/report/change`의 `action:'nest'`(`{id, parentId}`) · `'unnest'`(`{id}`)이고, 행에 `parent`만 붙입니다. 한 단계까지만 들어가며 아래에 문장이 있는 문장은 먼저 비워야 옮길 수 있습니다. 부모가 사라지거나 제외되거나 상태가 달라지면 그 문장은 조용히 최상위로 보입니다(저장된 값은 지우지 않습니다).
- 여러 업무를 **한 문장으로 요약**할 때는 문장 `수정` + 나머지 `제외`를 씁니다.
- 예전에 글자를 이어 붙여 묶은 문장은 그대로 읽히고, 그 줄의 ⋯에 `묶음 풀기`가 남아 있습니다. 묶을 때 서버가 **묶기 전 문장들을 함께 저장**했으므로(`.report-drafts.json`의 `parts`) 새로고침·서버 재시작 뒤에도 풀립니다. 서버에서는 `/api/report/change`의 `action:'split'`이고, 묶음을 다시 묶은 것은 한 번에 한 단계씩 풀립니다. `parts`는 서버가 묶기(`merge`)에서만 만들고 요청 본문의 값은 받지 않습니다. 묶은 뒤 문장을 고쳤다면 풀 때 그 편집은 사라지고 묶기 전 문장들로 돌아갑니다(바로 `되돌리기`로 복구합니다). 저장된 지 오래된 옛 묶음 문장에는 `parts`가 없어 `묶음 풀기`가 보이지 않을 뿐, 그대로 읽히고 고쳐집니다. 서로 다른 프로젝트를 묶은 `여러 프로젝트` 문장은 문서·슬랙 모두 그 구역의 맨 끝(`프로젝트 없음`/`기타` 앞)에 섭니다. 새로 묶는 길은 화면에 없습니다.
- **되돌리기**는 바로 직전 변경 하나입니다. 자리를 옮긴 변경에 성공하면 알림이 `문장을 아래로 넣었어요` / `따로 뺐어요` / `묶음을 풀었어요`로 뜨고 그 알림의 `되돌리기` 버튼으로 바로 되돌립니다. 주간요약 탭에서 입력칸 밖이라면 **⌘Z(Ctrl+Z)**도 같은 되돌리기입니다(다른 탭·입력칸 안에서는 앱의 기존 ⌘Z 그대로입니다). 머리줄에도 `되돌리기` 버튼이 남아 있습니다. 되돌리기 표(토큰)는 서버 메모리에만 있어 새로고침·서버 재시작 뒤에는 쓸 수 없습니다 — 그때는 `묶음 풀기`를 씁니다.
- 다음 주 계획은 **사람이 직접 씁니다**(자동으로 채우지 않습니다). 앱은 후보를 보여 줄 뿐이고, 담기는 사람이 누른 것만입니다. 문서 머리줄의 조용한 `다음 주 계획 쓰기`가 이 구역으로 데려갑니다(이번 주 보고에서만).
- **후보에서 골라 담기.** 담은 문장 아래 `다음 주 후보`에 지금 `오늘 할 일`에 남은 미완료 업무(진행 중 포함, 완료 제외)가 프로젝트별로 섭니다. 줄은 제목 + 기한 + 오른쪽 `+ 담기`이고, 누르면 그 프로젝트의 계획 문장으로 들어갑니다(글은 업무 제목 그대로이고 그 뒤에는 `수정`으로 고칩니다). 담아도 **업무 자체는 바뀌지 않습니다**(언제 할지·상태 그대로). 이미 담은 후보는 흐리게 `담음`으로 남고 다시 누를 수 없습니다 — 판정은 계획 문장에 저장된 연결(`planOf`)로 하므로 문장을 고쳐도 풀리지 않습니다. 구역 머리의 `나중에 할 일에서 고르기`를 누르면 같은 자리에 `나중에 할 일`이 펼쳐지고(작은 거르기 칸 + 구역 안 스크롤) 다시 누르면 접힙니다. 후보는 화면이 이미 불러 둔 업무 목록에서 만들며 별도 API를 쓰지 않고, **슬랙 복사에는 절대 들어가지 않습니다**.
- **직접 쓰기.** 프로젝트 소제목에 손이 닿으면 `+ 추가`가 떠서 그 자리에서 그 프로젝트로 한 문장을 씁니다. 맨 아래에는 프로젝트를 고르는 기존 입력줄 하나가 남습니다(새 프로젝트·프로젝트 없음용). 입력줄 아래 조용한 토글 `나중에 할 일에도 추가`(기본 켜짐, 브라우저에 기억)가 켜져 있으면 문장을 담을 때 같은 글·같은 프로젝트로 `나중에 할 일` 업무도 만듭니다(기한·우선순위는 넣지 않습니다). 알림은 `다음 주 계획에 넣었어요 · 나중에 할 일에도 추가했어요`, 토글이 꺼져 있으면 `다음 주 계획에 넣었어요`입니다. 업무는 만들어졌는데 문장 추가가 실패하면 그 업무 번호를 기억해 두고 다시 시도할 때 문장만 추가합니다(업무가 두 번 만들어지지 않습니다). 만든 뒤에는 **문장과 업무가 따로 놉니다** — 문장을 고쳐도 업무 제목은 바뀌지 않고, 문장을 지우거나 되돌려도 업무는 남습니다(업무는 업무 목록에서 지웁니다).
- **여러 줄 붙여넣기.** 입력줄에 줄바꿈이 있는 글을 붙여넣으면 한 줄이 한 문장이 되어 차례로 담깁니다(빈 줄 무시, 최대 20줄). 줄 앞의 `프로젝트 이름: ` 접두는 **기존 프로젝트 이름과 정확히 같을 때만** 그 프로젝트로 보냅니다. 중간에 실패하면 거기서 멈추고 남은 줄이 입력칸으로 돌아옵니다. 한 줄만 붙여넣는 것은 평소와 같습니다.
- 후보·`+ 추가`·토글은 **이번 주 보고에서만** 나옵니다. 지난 주차에서는 기존 입력줄 하나만 남습니다.
- 서버에서는 `/api/report/change`의 `action:'add'`가 선택적 `group`(1~60자, 줄바꿈 없음)과 `planOf`(담은 업무 번호, 1~100자)를 받습니다. `planOf`는 `sourceIds`·`evidence`에 넣지 않습니다 — 넣으면 그 업무가 이번 주 `진행중` 문장에서 빠져 버립니다. 서버는 그 업무가 실제로 있는지 확인하지 않습니다(화면 표시용 연결입니다). 프로젝트를 나중에 바꿀 때는 문장 ⋯의 `프로젝트 바꾸기`(서버의 `action:'regroup'` `{id, group}`, 계획 문장에만 허용)를 쓰고, 알림의 `되돌리기`·⌘Z로 되돌립니다. 아무것도 없으면 기존처럼 `직접 작성`으로 들어가고, 이미 저장된 계획 문장도 그대로 읽힙니다.

### 슬랙 복사

`슬랙용으로 복사`는 **구역 → 프로젝트 → 글머리 항목** 형식으로 씁니다. 구역 제목은 `[완료]` `[진행중]` `[결정]` `[확인 대기]` `[예정]`처럼 대괄호로 감싸 나갑니다(구역을 고르는 칩의 이름은 그대로입니다). 프로젝트 줄에는 지라 키를 싣지 않고 요약만 내보냅니다(`PAY-77 · 결제 정산 주기 정책 변경` → `결제 정산 주기 정책 변경`). 요약을 모르는 이슈만 키 그대로 나갑니다.

- 첫 줄은 `9월 3주차 (9/21~9/27)` 제목이고, 그 아래 구역이 `완료` · `진행 중` · `결정` · `확인 대기` · `예정` 차례로 섭니다. 내용이 없는 구역은 빠집니다. 화면·서버가 모르는 소제목은 버리지 않고 **그 이름 그대로의 구역**이 되어 아는 구역들 뒤, `예정` 앞에 섭니다.
- 구역 안에서는 프로젝트 이름 한 줄 아래로 그 프로젝트의 문장을 `•` 항목으로 모읍니다. 프로젝트가 없는 문장은 구역 끝 `기타`로 갑니다. 문장이 여러 줄이면 둘째 줄부터 들여 쓴 `◦` 부연이 됩니다. `예정`에서 프로젝트를 고르지 않은 계획 문장은 구역 끝에 `* 문장` 메모 줄로 섭니다.
- **빈 줄**은 구역 이름 줄 뒤와 프로젝트 묶음 사이에 하나씩 들어갑니다(프로젝트 없는 메모 줄들도 한 묶음이라 그 앞에 하나). 구역 끝 묶음 뒤에는 넣지 않아 구역 사이의 빈 줄과 겹치지 않습니다 — 빈 줄이 잇따라 두 개가 되는 곳은 없습니다. 일반 글자·서식 있는 복사(빈 단락)·미리보기가 모두 같은 자리에 같은 간격을 씁니다.
- 구역 칩 옆의 조용한 토글 칩 `지라 정보`(**기본 꺼짐**, 브라우저에 기억)를 켜면 **슬랙 글의 프로젝트 줄에만** 괄호 한 마디가 붙습니다: `결제 정산 주기 정책 변경 (v2.70.0 · 9/30 배포 · QA 대기)`. 버전이 없으면 `(QA 대기)`처럼 상태만, 지라에 연결되지 않았거나 정보를 모르는 프로젝트는 그대로입니다. 같은 프로젝트가 여러 구역에 나오면 **처음 나오는 곳에만** 붙습니다. 값은 화면이 이미 받아 둔 지라 목록에서만 읽습니다 — **주간요약을 열었다고 지라를 새로 부르지 않습니다**(그래서 앱이 지라를 직접 읽지 못하는 동안에는 아무것도 붙지 않습니다). 지라 키는 나가지 않고, 가운데 문서는 이 토글에 영향을 받지 않습니다.
- 미리보기 카드 위의 칩으로 **슬랙에 넣을 구역**을 고릅니다. 기본은 `완료` · `진행 중` · `예정`이 켜져 있고 `결정` · `확인 대기`는 꺼져 있습니다. 처음 보는 구역은 켠 채로 시작하고, 사람이 끈 구역은 다음에도 꺼진 채로 둡니다. 선택은 브라우저에 기억합니다(주차와 무관하게 하나). 내용이 없는 구역의 칩은 누를 수 없습니다. 칩을 바꾸면 미리보기와 복사 글자가 함께 바뀝니다 — 가운데 문서는 영향을 받지 않고 늘 전부 보입니다.
- 복사는 **서식 있는 복사와 일반 글자를 함께** 넣습니다(`ClipboardItem`의 `text/html` + `text/plain`). 슬랙 입력창에 붙이면 굵은 글씨와 글머리 목록이 되고, 서식을 못 쓰는 곳에는 같은 내용이 일반 글자로 붙습니다. `ClipboardItem`을 쓸 수 없으면 일반 글자만, 그것도 막히면 미리보기 글자를 직접 고르도록 안내합니다. 제외한 항목과 근거 표시는 복사에 들어가지 않고, 수정 중인 문장이 있으면 복사를 막습니다.
- 기존 `weekly_reports.md`는 그대로 두고 새 편집은 `tracker/.report-drafts.json`에 저장합니다. 기존 숨김 항목은 복사에서 제외됩니다.
- 조회는 파일을 수정하지 않습니다. 저장 버전이 달라지면 충돌을 알리고 입력을 보존합니다. 과거의 진행 상태를 기록 없이 추정해 채우지 않습니다.

## 설정

헤더 오른쪽 톱니바퀴가 화면의 `설정`입니다(창 제목·aria 이름도 `설정`). `상태`·`사용법`·`삭제한 항목` 세 칸이고, `상태`에는 자동 수집 결과가, `사용법`에는 도움말과 `다른 기기 접속 암호 복사`가 있습니다. 자동 수집이 **지금** 실패 중이면 톱니바퀴에 빨간 점이 붙습니다(해결된 과거 실패는 접어 둡니다). `상태` 목록은 슬랙 캡처 · 캘린더 동기화 · 지라 동기화 · 미팅 노트 가져오기이고, 꺼 둔 연동은 나오지 않습니다. 지라 티켓 목록을 앱이 직접 읽고 있는 동안에는 `지라 동기화` 줄 아래에 조용한 한 마디 `목록은 앱이 직접 읽어요 · 3분 전`이 붙습니다(그때 이 자동화는 대비책이라는 뜻입니다).
- `상태` 목록 맨 아래에는 `반응 필요 · 지라 댓글` 한 줄이 붙습니다(지라에 연결돼 있을 때만) — 마지막으로 읽은 때(`3분 전 확인`)를 적고, 읽지 못하고 있으면 그 문구(`지라 댓글을 읽지 못했어요.`)를 적습니다. 자동화가 아니라 앱이 직접 읽는 것이라 목록 끝에 조용히 섭니다.
- `슬랙 캡처` 줄 아래에는 최근 수집의 처리 대장이 조용한 글자로 붙습니다. 슬랙 수집 지침이 실행마다 로그 맨 앞에 남기는 `이번에 본 메시지 N개 = 등록 a · 링크 중복 b · 비슷한 일이라 건너뜀 c · 시스템 d` 문장을 그 실행 로그에서 가장 최근 것 하나만 찾아 `최근 수집 · 본 메시지 12개 → 등록 3 · 중복 7 · 건너뜀 0 · 시스템 2`로 보여 주고(0인 항목은 흐리게), 합이 안 맞으면 그 실행이 남긴 `합이 안 맞습니다 …` 문장을 주의색 글자로 그대로 적습니다. 같은 실행에 `🔁 이미 있는 '…'랑 중복돼서 안 가져왔어요` 줄이 있으면 그 아래에 `건너뛴 것: …`(최대 3개)이, `⚠️`로 시작하는 줄(원문 못 읽음·파일만 있는 메시지)이 있으면 최대 2개가 조용히 붙어 로그를 열지 않고도 무엇이 왜 안 들어왔는지 보입니다. 옛 로그처럼 이 문장이 없으면 아무것도 그리지 않습니다.
- **`삭제한 항목` 탭**은 `tracker/.trash.json`에 원문이 남아 있는 항목을 삭제 시각 내림차순으로 보여 줍니다. 탭 이름 옆 숫자가 개수이고(0이면 숫자가 없습니다), 창을 열 때마다 새로 읽습니다(`GET /api/track/trash` — 조회라 파일을 쓰지 않습니다). 줄은 종류 글자(`할 일`·`확인 대기`·`결정`·`아이디어`) + 문구 + (있으면) 프로젝트(`· ● 이름`, 지라는 요약만) + 아래 조용한 글자 `9월 21일 22:10에 삭제`이고, 오른쪽에 `되살리기`와 ⋯이 섭니다.
  - `되살리기`는 기존 복구 길(`POST /api/track/restore`)로 **원래 파일의 원래 자리**에 돌려놓고 목록을 다시 그린 뒤 `되살렸어요 · 문구`라고 알립니다.
  - ⋯의 `완전히 지우기`는 되돌릴 수 없어 그 자리에 확인 줄(`되살릴 수 없어요 · 지우기 / 취소`)을 한 번 세웁니다. `지우기`는 `POST /api/track/trash-purge`로 `.trash.json`에서 그 줄만 빼고(업무 파일은 이미 그 줄이 없습니다) 앱의 다른 저장과 같은 트랜잭션·복구 규칙을 탑니다. **자동 영구 삭제는 없습니다** — 여기서 사람이 고른 것만 지워집니다.
  - 비어 있으면 `삭제한 항목이 없어요.` 한 줄입니다.

### 지라 연결 설정

프로젝트 탭의 지라 띠 카드가 지라를 직접 읽으려면 `workspace.config.json`에 항목 셋이 있어야 합니다.

1. https://id.atlassian.com/manage-profile/security/api-tokens 에서 `Create API token`으로 토큰을 만듭니다.
2. 토큰을 **파일 하나에만** 저장합니다(저장소에는 넣지 않습니다). 예: `~/.config/workspace-jira-token`.
   ```sh
   mkdir -p ~/.config && printf '%s' '붙여넣은_토큰' > ~/.config/workspace-jira-token && chmod 600 ~/.config/workspace-jira-token
   ```
3. `workspace.config.json`에 다음을 넣고 서버를 다시 시작합니다.
   ```json
   "jira": {
     "siteUrl": "https://내회사.atlassian.net",
     "email": "나@내회사.com",
     "tokenFile": "~/.config/workspace-jira-token"
   }
   ```

`siteUrl`은 `https://`로 시작해야 하고, 셋 중 하나라도 없거나 토큰 파일을 못 읽으면 띠 카드 자리에 `지라 연결이 필요해요`만 뜹니다(그 밖의 화면은 예전과 똑같이 동작합니다). 토큰은 요청할 때마다 파일에서 읽고, 토큰과 이메일은 로그·오류 문구·API 응답·화면 어디에도 나오지 않습니다. 앱이 지라에서 **읽는** 요청은 이 둘입니다: `GET {siteUrl}/rest/api/3/issue/{KEY}?fields=summary,status,issuetype,assignee,duedate,fixVersions,subtasks`와 하위 티켓을 읽는 `GET {siteUrl}/rest/api/3/search/jql?jql=parent={KEY}&fields=summary,status,assignee,fixVersions,issuetype&maxResults=100`(이 주소가 없는 지라에서는 `/rest/api/3/search`로 한 번 물러서고, 그때는 이슈의 `subtasks`만 남아 담당자·배포 버전을 모릅니다). 담당자는 **표시 이름만** 꺼내 씁니다 — 지라가 같이 주는 이메일·계정 id는 화면에도 API 응답에도 옮기지 않습니다. 요청은 8초에서 끊고, 결과는 키마다 60초 동안 메모리에만 담아 둡니다(`GET /api/jira/issue?key=…&fresh=1`이면 건너뜁니다). 조회는 어떤 파일도 쓰지 않습니다. 값을 바꿀 때 읽고 쓰는 요청은 위 `지라 값 바꾸기` 절에 있습니다. 직접 만든 프로젝트에 티켓을 걸 때(`지라 티켓 연결`)도 새 주소를 부르지 않고 위의 읽기 요청 그대로 한 번 읽어 확인합니다. 설정이 있는지와 `siteUrl`은 목록 응답(`jiraSync`)에 함께 실려 화면이 붙여 넣은 주소를 견주는 데만 씁니다 — 토큰과 이메일은 실리지 않습니다.

**반응 필요(지라 댓글)도 앱이 직접 읽습니다.** 오늘 탭 맨 위 구역이 쓰는 값이고, 서버가 읽는 요청은 셋입니다: ① `GET {siteUrl}/rest/api/3/myself`(누가 나인지 알려고 **계정 id 하나만** 씁니다 — 프로세스마다 한 번 묻고 서버 메모리에만 두며, 토큰이 만료되면 다음번에 다시 묻습니다), ② `GET {siteUrl}/rest/api/3/search/jql?jql=(assignee = currentUser() OR reporter = currentUser() OR watcher = currentUser()) AND updated >= -14d ORDER BY updated DESC&fields=summary,status,comment&maxResults=50`(주소가 없는 지라에서는 `/rest/api/3/search`로 한 번 물러섭니다), ③ 댓글 칸이 잘려 온 이슈만 `GET {siteUrl}/rest/api/3/issue/{KEY}/comment?orderBy=-created&maxResults=20`으로 한 번 더 읽습니다. **담당자 칸은 묻지 않고**, 댓글 작성자는 **표시 이름만** 꺼내 씁니다 — 이메일·계정 id는 화면에도 API 응답에도 옮기지 않습니다. 읽은 목록은 **메모리에만** 있고(파일은 하나도 쓰지 않습니다) 갱신은 내 담당 목록과 같은 리듬입니다: 서버가 뜰 때 한 번(설정이 있을 때만), 그 뒤 10분마다, `GET /api/attention?fresh=1`이면 바로. 동시에 두 번 돌지 않고, 실패하면 이전 값을 30분까지 `… 기준`으로 쓰다가 그보다 묵으면 빈 목록 + `지라 댓글을 읽지 못했어요.`가 됩니다. 헤더의 새로고침 버튼은 화면을 다시 받기 전에 이 주소도 `fresh=1`로 조용히 한 번 부릅니다(실패해도 알리지 않습니다). 치운 줄(`했어요`)은 `tracker/.workflow.json`의 `attention.dismissed`에 `"jira:IO-48394:10001": "치운 시각"` 한 줄로만 저장되고(앱의 다른 저장과 같은 트랜잭션·복구 규칙), 저장할 때 200개를 넘거나 30일이 지난 것은 버립니다(그 시점 목록에 있는 줄은 지킵니다).

**내 담당 티켓 목록도 앱이 직접 읽습니다.** 프로젝트를 고르는 목록과 화면 곳곳의 프로젝트 이름(요약)이 그 목록에서 옵니다. 서버는 `GET {siteUrl}/rest/api/3/search/jql?jql=assignee = currentUser() AND statusCategory != Done ORDER BY updated DESC&fields=summary,status,issuetype,fixVersions,duedate&maxResults=100`을 읽고(이 주소가 없는 지라에서는 `/rest/api/3/search`로 한 번 물러섭니다), 업무·회의·`projectLinks`에 걸려 있는 키 중 그 결과에 없는 것만 `key in (…)`으로 한 번 더 읽어 `그 밖의 이슈`로 붙입니다. **담당자 칸은 아예 요청하지 않습니다.** 읽은 목록은 **메모리에만** 둡니다 — 이 조회는 어떤 파일도 쓰지 않습니다(`tracker/jira_issues.md`는 동기화 스킬이 쓰는 대비책 파일이고 앱은 읽기만 합니다). 갱신은 서버가 뜰 때 한 번(설정이 있을 때만), 그 뒤 10분마다, 그리고 목록 조회(`/api/items`)가 5분 넘게 묵은 값을 보면 **응답을 기다리게 하지 않고** 뒤에서 한 번 더 겁니다. 갱신은 동시에 두 번 돌지 않고, 실패하면 이전 값을 30분까지 그대로 쓰다가 그보다 묵으면 버리고 대비책 파일로 돌아갑니다. 헤더의 새로고침 버튼은 화면을 다시 받기 전에 `GET /api/jira/list?fresh=1`을 조용히 한 번 부릅니다(결과는 `{ ok, connected, count, liveAt }` 한 줄뿐이고 티켓은 싣지 않습니다. 실패해도 새로고침은 그대로 진행하고 알림도 띄우지 않습니다). 앱이 직접 읽고 있는 동안에는 `jiraSync`에 `live: true`와 읽은 시각(`liveAt`)이 실려, 톱니바퀴의 지라 `어제 기준` 경고가 뜨지 않습니다.

## 저장 안전장치

쓰기에는 임시 파일 교체, `.backups/`의 직전 파일, 변경 파일별 복구 저널을 사용합니다. 복구할 파일이 외부에서 다시 수정됐으면 덮어쓰지 않고 저널을 보존합니다. 이는 장기 백업을 대체하지 않습니다.

### 업무 데이터 백업

`tracker/`의 업무 데이터는 코드 저장소에서 제외돼 있어서, `automation/backup-data.sh`가 하루 한 번(19:30) 별도의 비공개 Git 저장소에 커밋하고 올립니다. 백업용 저장 공간은 프로젝트 밖 `~/.local/share/workspace-automation/data-backup.git`에 있고, 올릴 파일은 그 안의 `info/exclude` 허용 목록으로 고정합니다(접속 암호·잠금·`.backups`는 제외). 결과는 `logs/data-backup.log`에 남습니다.

- 과거 상태 보기: `git --git-dir=~/.local/share/workspace-automation/data-backup.git log` 로 날짜를 찾고 `show <커밋>:tasks.md` 로 그날의 내용을 확인합니다.
- 새 맥에서 복구: 비공개 저장소를 받아 파일을 `tracker/`에 넣은 뒤, `git clone --bare`로 같은 위치에 저장 공간을 만들고 `core.bare false`와 `info/exclude` 허용 목록을 다시 설정한 다음 `setup.sh`를 실행합니다.

### 복구 필요 상태

되돌리기가 거절되거나(외부에서 바뀐 파일), 서버 시작 때 복구를 끝내지 못하면 저장을 멈춥니다. 서버와 조회는 그대로 동작하고, 저장 요청만 503과 안내 문구로 거절하며 화면 위에 같은 안내가 계속 표시됩니다(`GET /api/storage-status`). 회의 기록 자동 저장도 함께 멈춥니다. 앱은 아무 파일도 자동으로 지우거나 되돌리지 않습니다.

- 관련 파일: `tracker/.mutation-journal.json`(`{"changes":[{"file","before","after","intermediate"}]}` 형식이며 `before`는 변경 전 내용을 base64로 담습니다. 끝난 거래는 `{"committed":true}`), `tracker/.mutation.lock`(저장 중인 프로세스 번호), `<파일이 있는 폴더>/.backups/<파일명>.previous`(직전 내용).
- 저널의 `changes[].file`을 하나씩 열어 지금 파일과 `before`를 디코드한 내용(`base64 -d`), 그리고 `.previous` 백업을 비교합니다.
- 지금 파일이 맞으면 그대로 두고, 되돌리는 쪽이 맞으면 `before` 또는 `.previous` 내용을 직접 파일에 씁니다.
- 정리한 뒤 저널과 잠금 파일을 지우지 말고 다른 이름으로 옮겨 둡니다(예: `.mutation-journal.json.2026-09-20`).
- 서버를 다시 시작하면 복구를 다시 시도하고, 성공하면 저장이 풀립니다. 남은 파일은 확인 후 직접 정리합니다.

Slack 수집은 모든 페이지를 읽고 `import-record.js`로 앱의 검증·저장 API를 사용합니다. JSON은 명령줄 인자로 넘기며(`node tracker/inbox-app/import-record.js item '{…}'`), 인자를 주지 않으면 표준 입력도 그대로 받습니다. 일부 저장에 실패하면 수집 커서를 유지합니다. 수집 시도와 성공은 별도로 표시합니다. 수집 스크립트 변경 후 설치된 `~/.local/share/workspace-automation/slack-capture.sh`도 함께 갱신해야 합니다.

수집 지침(`.claude/skills/slack-todos.md`·`slack-waiting.md`·`slack-someday.md`·`slack-alignments.md`)은 채널의 메시지를 **세 갈래로 빠짐없이** 나눕니다: ① 시스템·봇 메시지는 건너뜀, ② `attachments`에 `is_share: true`가 있으면 공유(포워드), ③ **그 밖의 모든 메시지는 직접 적은 메모**입니다 — 링크 미리보기(`attachments`)·파일(`files`)·서식(`blocks`)이 붙어 있어도 메모로 봅니다. 공유하면서 같이 적은 메모는 버리지 않고 **맥락으로 참고**하며(문구를 대체하지는 않습니다), 같은 원본을 다른 메모로 다시 공유하면 개인 채널의 그 메시지 링크(`…/archives/<채널ID>/p<ts>`)를 원본 링크로 써서 별개 항목이 됩니다(서버의 중복 제거는 원본 링크 글자가 같을 때만 걸립니다). 직접 적은 메모의 "사실상 같은 일" 중복 제거는 보수적으로 하고, 실행 결과에는 `이번에 본 메시지 N개 = 등록 a · 링크 중복 b · 비슷한 일이라 건너뜀 c · 시스템 d`처럼 **본 메시지의 처리 결과를 빠짐없이** 남깁니다.

지라 캐시(`tracker/jira_issues.md`)는 `- 키 | 이슈타입 | 상태 | 요약` 한 줄 형식이고, 기본 조회(내 담당·미완료) 뒤에 `## 업무에 연결된 그 밖의 이슈` 소제목이 올 수 있습니다. 업무에 연결돼 있는데 완료됐거나 담당이 바뀌어 기본 조회에서 빠진 이슈를 동기화가 여기에 적어, 요약이 사라지지 않게 합니다. 그 구역의 이슈는 **요약 표시에만** 쓰이고 프로젝트 고르기 선택지·프로젝트 목록에는 새로 오르지 않습니다(이미 항목이 걸려 있으면 그 항목 때문에 목록에 섭니다). 완료 범주인 이슈는 상태 칸이 정확히 `완료`입니다. 소제목이 없는 옛 파일도 그대로 읽습니다. 이 파일은 이제 **대비책**입니다 — 앱 서버가 지라를 직접 읽을 수 있으면 화면은 그 값을 쓰고 이 파일은 보지 않습니다(지라 설정이 없거나 토큰이 만료됐거나 지라가 답하지 않을 때만 쓰입니다). 동기화 자동화(`jira-sync`)는 그래서 그대로 둡니다 — 끄고 싶으면 `workspace.config.json`의 `integrations`가 아니라 launchd에서 그 작업을 내려야 합니다.

미팅 노트 가져오기는 일정표 없이 **앱의 버튼으로만** 돕니다. 앱 서버는 프로세스를 띄우지 않고 요청 표시 파일 `~/.local/share/workspace-automation/requests/tiro-sync.request`(JSON: `{"requestedAt", "scope": "today"|"meeting", "meeting": {…}}`) 하나만 씁니다. 그 파일을 `WatchPaths`로 지켜보던 launchd 에이전트(`com.luvon.workspace.tiro-sync`)가 기존 `run-task.sh`로 `.claude/skills/tiro-sync.md`를 실행하고, 앱은 `logs/tiro-sync.log`의 시작·종료 줄로 진행 상태를 읽습니다(`GET /api/meeting-notes/status` — 파일을 쓰지 않습니다). 요청에 담기는 회의 값은 **앱이 아는 회의 목록에 실제로 있는 회의**만 통과하고(형식 오류·미래 회의는 거절), 요청 파일의 글자는 자동화가 데이터로만 다룹니다. 60초가 지나도 실행이 시작되지 않으면 `setup.sh를 다시 실행해 주세요`로, 35분이 넘으면 실패로 봅니다. 가져오는 중에 들어온 요청은 409(`지금 가져오는 중이에요`)로 막습니다. 티로 MCP(`tiro-mcp`, user 범위)가 `claude`에 연결돼 있어야 실행이 성공합니다.

자동화 실행(`run-task.sh`)은 모델을 **Sonnet으로 고정**해 부릅니다(`--model sonnet`, 바꾸려면 `TASK_MODEL`) — 계정 기본 모델을 따라가면 `/model`을 바꾼 뒤 수집·동기화가 비싼 모델로 돌아 사용량 한도를 먹기 때문입니다. 30분(`TASK_TIMEOUT_SECONDS`, 맥이 깨어 있는 시간 기준)이 넘으면 자식 프로세스까지 정리하고 `exit 124`로 끝냅니다. Slack 수집은 잠금 주인 프로세스가 살아 있는지 확인해서, 살아 있으면 건너뛰고 죽었으면 바로 회수합니다. 수집 실행은 파일 수정 도구 없이(Write·Edit 금지) `import-record.js`와 `fetch_slack_channel.sh` 두 명령만 쓸 수 있습니다.

자동 갱신(슬랙·캘린더·지라)이 낡았으면 머리줄에 글자를 끼우지 않고 **설정 톱니바퀴에 주황 점**이 켜집니다(지라는 앱이 목록을 직접 읽고 있는 동안에는 낡을 일이 없어 이 경고가 뜨지 않습니다)(지금 실패 중이면 빨간 점이 이깁니다). 무엇이 낡았는지는 톱니바퀴의 툴팁(`설정 — 캘린더 어제 기준`, 둘 이상이면 `자동 갱신 3개 어제 기준`·나이가 다르면 `확인 필요`)이 말하고, 누르면 설정 > 상태의 그 줄이 밝혀집니다. 그날의 첫 자동 갱신(9시대)이 돌기 전인 09:30 이전에는 `어제 기준`을 알리지 않습니다(오류가 있었거나 이틀 넘게 멈춘 것은 그대로 알립니다).

다른 기기 접속에는 인증이 필요합니다. 로컬 앱의 설정 → 사용법 → `다른 기기 접속 암호 복사`에서 암호를 복사하고, 접속 시 사용자 이름은 `workspace`를 사용합니다. 암호는 `tracker/.access-token`에 보관되며 Git에서 제외됩니다. 원격 접속은 기존 Tailscale 또는 HTTPS 보호 환경에서 사용합니다. 앱 아이콘(`/icons/*.png`)과 `manifest.webmanifest`만 인증 없이 열립니다 — 아이폰이 홈 화면에 추가할 때 로그인 정보 없이 가져가기 때문입니다. 아이콘을 바꾼 뒤에는 홈 화면의 앱을 지우고 다시 추가해야 새 아이콘이 보입니다.

## 화면 파일 구성

화면 코드는 여러 파일로 나뉘어 있고, 번들러 없이 `index.html`의 `<script>` 차례대로 **같은 전역 공간**에서 돕니다. 차례가 곧 의존 방향입니다(뒤에 오는 파일이 앞 파일을 씁니다).

| 파일 | 담는 것 |
| --- | --- |
| `workflows.js` | 회의·항목 흐름 기록을 읽는 순수 함수(`wf*`) |
| `jira-ui.js` | 지라 띠 카드(값 세 칸·확인 절차를 거치는 바꾸기), 하위 티켓 목록, 그룹 프로젝트의 수동 티켓 연결, 배포 임박 판단 |
| `meeting-notes-ui.js` | 미팅 노트 가져오기 버튼·진행 상태·알림·안 가져온 회의 판정 |
| `project-new-ui.js` | 새 프로젝트 화면(이름·지라 세 모드·직군 세트·하위 티켓 종류·미리 보기·확인 줄·만든 결과) |
| `projects-ui.js` | 프로젝트 탭(왼쪽 목록·지난 프로젝트·보관·이름 바꾸기, 오른쪽 상세) |
| `meetings-ui.js` | 회의 정리 패널(초안 검토·담기·종류 바꾸기·연결)과 회의 탭의 두 보기 |
| `waiting-ui.js` | 확인 대기 카드(`다음은?` 줄·더보기·두 보기·줄 그리기) |
| `settings-ui.js` | 설정 창(상태 탭·사용법 문답·삭제한 항목 탭·열고 닫기) |
| `wrap-ui.js` | 오늘 정리 창(남은 오늘 업무의 갈래 고르기·기존 일괄 저장 길로 보내기·되돌리기 한 항목) |
| `attention-ui.js` | 오늘 탭 맨 위 `반응 필요` 구역(줄 그리기·`했어요`·`할 일로`·설정 > 상태의 그 줄) |
| `report-ui.js` | 주간요약 문서·슬랙 복사 |
| `app.js` | 공용 부품(`ui*`), 오늘 탭, 상세 카드, 검색 팔레트, 되돌리기, 저장 안전장치(`request`·`showNotice`·`pushUndo`·`fadeOutAndRun`), 화면을 켜는 실행 코드 |

서버는 파일 이름을 하나하나 적지 않고 이 폴더의 `*.js`/`*.css` 가운데 서버 파일·저장소 코드·테스트·픽스처를 뺀 것만 내보냅니다(`server.js`의 `isClientFile`). 브라우저가 스스로 새로고침할지 판단하는 값(`appVersion`)도 같은 목록을 씁니다. 화면 파일을 더할 때는 `index.html`에 `<script>` 한 줄만 넣으면 됩니다.

## 검증

```sh
node --test server.test.js client.test.js report-drafts.test.js
```

`tracker/inbox-app`에서 실행합니다. 임시 디렉터리와 임시 포트를 사용하며 실제 업무 데이터는 변경하지 않습니다.
클라이언트 테스트는 `app.js`와 위 화면 파일들을 같은 차례로 가짜 화면 환경에 올려 입력 보존, 실패 처리, 한글 조합 중 Enter, 복구 필요 안내 표시, 업무 카드의 배지·프로젝트 라벨·그룹 선택지를 검증합니다.

테스트·별도 실행 시 `WORKSPACE_DATA_DIR`, `WORKSPACE_PORT`, `WORKSPACE_NO_OPEN=1`을 사용할 수 있습니다.
기본 서버는 로컬 컴퓨터의 `127.0.0.1`에만 바인딩합니다.

브라우저 검증용 `node browser-fixture.js`는 4322 포트에서 임시 데이터만 사용합니다. 종료 시 임시 데이터를 정리합니다.
