# 배포 전 실제 환경 점검

테스트와 확인용 서버(`browser-fixture.js`)는 가짜 데이터·가짜 명령으로 돈다. 아래는 **실제 맥에서만 드러나는 것**이라 배포(`release.sh`) 전에 한 번 직접 확인한다. 가장 좋은 곳은 맥의 **새 사용자 계정**(시스템 설정 › 사용자 및 그룹) — 동료의 첫 설치와 같은 조건이다.

## 새로 설치
- [ ] 팀 설치 파일(`bash make-team-installer.sh`)을 만들고, 새 계정에서 zip을 풀어 `설치.command` 우클릭 → 열기. "확인되지 않은 개발자" 경고 뒤 설치가 끝까지 도는지
- [ ] 끝에 크롬에서 앱 주소가 저절로 열리는지(크롬이 없는 계정이면 기본 브라우저 + 크롬 설치 권유 한 줄), `~/Applications`에 새 앱이 생기지 않았는지, python3 없이도 끝까지 도는지
- [ ] 오늘 탭에 사용설명서 카드, 설정을 열면 연동 탭이 먼저인지

## 연동 (실제 계정)
- [ ] 슬랙(새 방식): `슬랙 연결` → 슬랙 `허용` → `✓ 연결됐어요` 탭 → 채널 만들기 → 연결. 카드에 `자동 갱신 켜짐`, 점검하기에 `자동 갱신 · 다음 갱신 …`
- [ ] 슬랙 자동 갱신: 연결하고 12시간 넘긴 뒤(맥을 재웠다 깨운 경우 포함)에도 수집이 이어지고 점검하기가 `갱신이 잠시 안 돼요`가 아닌지
- [ ] 슬랙 옛 방식 그대로: 한 버전 전 설치본(토큰 붙여 넣기)이 업데이트 뒤 아무것도 누르지 않아도 수집되는지, `⋯`에 `새 방식으로 다시 연결 (자동 갱신)`이 보이는지
- [ ] 슬랙 옮기기: 옛 방식 → `새 방식으로 다시 연결` 뒤 채널 그대로·중복 항목 없음, 다시 `고급: 토큰 직접 붙여 넣기`로 저장하면 옛 방식으로 돌아오는지
- [ ] 슬랙 고급(옛 길): `고급: 토큰 직접 붙여 넣기` → 토큰 받는 곳 열기(옛 슬랙 앱) → `xoxp-` 토큰 → 채널 만들기(기본 이름이 `<슬랙 이름>-todo` 모양) → 연결. 5분 안에 전달한 메시지가 새로 들어온 것에 뜨는지(9–19시)
- [ ] 슬랙 막힘: 허용 화면에서 `취소` → 카드에 `취소했어요`, 다른 기기(Tailscale)에서는 버튼이 회색 + `앱을 설치한 맥에서`
- [ ] 연동을 전부 끈 계정(지라·캘린더·Claude 없음)에서 오늘 탭 `분류` 판·머리줄 `✓ M/N`·회의 적기가 오류 없이 뜨는지
- [ ] 슬랙 `⋯ › 새로 받기`가 1~2분 뒤 반영되는지, 채널 고르기에서 빼기·다시 켜기
- [ ] 지라: 토큰 → 이메일 → ○○님으로 연결, 프로젝트 탭에 내 티켓
- [ ] 캘린더 비밀 주소: 오늘 일정 수가 맞는지(반복 일정·시간대 포함)
- [ ] 연동을 켜고 저장한 뒤 `업데이트.command` 없이 자동 등록되는지(`launchctl list | grep workspace.app`)

## 업데이트·되돌리기
- [ ] 한 버전 전 설치본에서 `업데이트.command` → 새 버전, 데이터 그대로
- [ ] 설정 › 앱 `업데이트 받기` 진행 목록 → 다시 켜는 중 → 완료·새로고침
- [ ] 자동 업데이트: 동료 맥(한 버전 전 설치본)에서 앱을 10분 쉬게 두면 1시간 안에 새 버전이 알아서 깔리고, 다시 열면 오늘 탭에 그 버전의 소식 카드가 서는지(`local/auto-update.json`에 `triedOn` 기록)
- [ ] 회사(playio) 폴더 안 설치본이 `~/workspace`로 옮겨지는지(`~/workspace`가 이미 있으면 멈춤)

## 꾸미기·백업
- [ ] 꾸미기 `앱 아이콘`·`앱 이름`을 바꾸면 저장 뒤 `✓ 바뀌었어요` 아래 `크롬 앱에는: …` 한 줄만 보이는지
- [ ] 크롬 앱: 사용설명서 `설치하기` → 새 창 · Dock·⌘Tab에 따로 아이콘. 아이콘을 바꾸면 `about://restart` → 앱 오른쪽 위 `앱 업데이트 있음` → ⌘Q 뒤 다시 열 때 Dock까지 바뀌는지
- [ ] 다음 날 `~/workspace-data-backup/daily/`에 날짜 폴더가 생기는지, 앱 탭 백업 줄

## 주간요약·프로젝트 묶음
- [ ] 한 버전 전 설치본의 주간요약·프로젝트가 업데이트 뒤 그대로인지(주차 번호만 목요일 기준으로 바뀜), 지라 티켓 둘을 묶었다 풀기

## 체크인·슬랙 원문 모드
- [ ] 체크인: 동료 맥(갈래 stable)에서 3일째 창이 뜨고, 보낸 답이 구글 폼 응답 탭에 한 줄로 쌓이는지(선택지 글자·자동 칸). 내 맥(main 갈래)에서는 안 뜨는지
- [ ] 사용 횟수: 동료 맥에서 업데이트 뒤 처음 연 날 폼 응답 탭에 회차 `설치` 줄이 한 번 쌓이는지, 사용설명서 맨 아래 `… 보내요 · 끄기` 줄과 주간요약 탭 주차 목록의 끝낸 일 막대와 목록 아래 `내 일 기록 자세히`(맨 아래 `기능별 전체 보기` 표)가 보이는지. `끄기` 뒤에는 아무 줄도 더 쌓이지 않는지
- [ ] 슬랙 원문 모드: Claude 로그인이 없는 계정에서 설정 › 연동 › 슬랙을 `원문 그대로`로 두고, 전달한 메시지가 첫 줄 그대로 들어오는지(할 일·확인 대기·결정·아이디어 채널 각각)

## 다른 기기
- [ ] Tailscale 주소로 접속 → 이름 `workspace` + 접속 암호로 열리는지(암호는 설정 › 도움말에서 복사, 대화창에 붙이지 않는다)

점검에서 나온 문제는 배포를 멈추고 고친 뒤 다시 이 목록을 돈다. 목록에 없는 새 기능이 생기면 여기에 한 줄 더한다.

## 배포 뒤 고장 났을 때
코드를 읽어 확인한 것만 적었고, 실제로 돌려 보지 않은 것은 "미확인"이라고 적었다. 새 버전으로 내는 것이 원칙이고, 되돌리는 건 급할 때만 쓴다.

1. **증상별 첫 확인** — 설정 › 앱에서 본다. 버전 줄(지금 버전·새 버전·업데이트가 어디서 멈췄는지) → `점검하기`(연동·자동화 상태) → `문제 보고 복사`(버전·연동 상태·자동화 요약만 담기고 업무 문장은 한 줄도 안 들어간다. 이걸 붙여 알려 준다).
2. **동료 맥에서 되돌리기** — 앱 설정 › 앱의 `이전 버전으로 되돌리기`(업데이트가 `③ 새 버전 받기` 뒤에서 멈췄을 때만 보인다) 또는 설치 폴더에서 `bash update.sh --rollback`. `업데이트.command`(더블클릭)는 새 버전 받기만 하고 되돌리지 않는다.
   - 코드는 업데이트 직전 자리로, **업무 데이터·설정도 업데이트 직전 백업으로 덮어쓴다.** 그래서 업데이트 뒤에 적은 일은 사라진다. 한 번만 되고(두 번째는 "업데이트한 기록이 없어요"), 되돌린 버전은 자동 업데이트가 다시 깔지 않는다.
   - 성공한 업데이트 뒤의 `--rollback`은 코드로만 확인(미확인).
3. **아직 안 받은 동료에게 퍼지는 걸 멈추기** — 동료 앱(stable 갈래)은 원격 태그 중 **가장 높은 번호**를 받는다. 멈추려면 먼저 `git ls-remote --tags origin`으로 태그를 보고, `git push origin :refs/tags/v1.4.1`로 그 태그만 지운다(원격 main은 건드리지 않는다. 강제 푸시 금지).
   - 아직 안 받은 맥: 다음 확인에서 직전 태그가 가장 높아 새 버전이 없다고 뜬다. 이미 받은 맥: 그대로 새 버전에 남는다(태그를 지워도 되돌려지지 않으니 2번으로 각자 되돌린다).
   - 태그만 받아 두고 적용은 못 한 맥은 그 태그를 다시 받으려 할 수 있다 — 그 맥에서 `git tag -d v1.4.1`(미확인). 지우기 전에 누가 이미 받았는지 확인하고, 고쳐서 새 버전을 내는 쪽이 더 빠른지 먼저 본다.
4. **내 맥(main 갈래)에서 이전 버전으로** — 저장소 폴더에서 `git log --oneline`으로 돌아갈 버전 태그를 찾고, `git revert --no-commit <태그>..HEAD` 뒤 `git commit`(기록을 지우지 않고 되돌리는 커밋 하나를 만든다). 이어 서버를 다시 켠다: `launchctl kickstart -k gui/$(id -u)/com.workspace.app.server`. 업무 데이터는 git 밖이라 이 명령이 건드리지 않는다. 직접 돌려 보지 않았다(미확인).
5. **데이터 보호** — 업데이트 직전 백업은 `~/workspace-data-backup/YYYY-MM-DD-HHMM/`에 최근 5개만 남는다(2번이 쓰는 백업). 따로 매일 19:30에 `~/workspace-data-backup/daily/YYYY-MM-DD/`에 7일치가 쌓인다(접속 암호는 뺀다). 되돌리기는 가장 최근 업데이트 직전 백업을 쓴다. 손으로 복원하는 순서는 미확인.
6. **새 방식 슬랙이 멈추면** — 설정 › 앱 `점검하기`의 `슬랙 연결` 줄에서 오류 이름(`슬랙 오류: …`)을 확인 → 슬랙 카드의 `다시 연결` → 안 되면 `고급: 토큰 직접 붙여 넣기`(옛 방식으로 돌아간다). 그래서 옛 슬랙 앱은 지우지 않는다.
7. **앞으로는 새 버전으로** — 고쳐서 내는 건 v1.4.2처럼 새 번호로 낸다. 이미 낸 태그는 다시 쓰지 않는다(`release.sh`도 이미 있는 태그는 막는다).
