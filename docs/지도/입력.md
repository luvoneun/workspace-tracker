# 지도: 입력

> 입력칸·편집 칸을 만들거나 고치면 이 문서도 함께 고친다. 규칙(무엇을 지키나)은 `DESIGN.md` 「동작 관습」 1~5, 이 문서는 **어디서 지키나**(함수 이름 — 행 번호는 금방 낡는다). 마지막 확인: 2026-10-08(입력 공통 기능 정리).

## 한 줄 요약
입력 약속을 맡는 공통 함수는 다섯이다 — 저장 순서 `uiQueueSend`, 입력 중 다시 그리기 보류 `uiRenderOrHold`(`uiRenderHeld`·`uiHeldFlush`), 한글 조합 추적 `uiComposingEl`·`uiComposingLive`, Esc 층 `escPush`·`escDrop`(`escStack`), 탭 들어올 때·나갈 때 `TABS[탭].enter·leave`. 바깥 클릭 저장·편집 하나에는 공통 함수가 없고 칸마다 `blur`/`focusout`으로 지킨다.

## 공통 함수

| 함수 | 파일 | 하는 일 |
|---|---|---|
| `uiQueueSend(key, job)` | `app.js` | 같은 칸의 저장을 하나씩 순서대로(동작 관습 5). 칸은 잠그지 않는다 |
| `uiRenderOrHold(name, zone, render)` · `uiRenderHeld` · `uiHoldArm` · `uiHeldFlush` | `app.js` | 구역 안 글자 칸에서 치는 중·조합 중·저장 중(잠긴 칸·`data-saving`)이면 다시 그리기를 미루고, 칸을 떠나거나 조합이 끝나면 한 번 그린다 |
| `uiComposingEl` · `uiComposingLive()` | `app.js`(듣기 두 줄은 실행 코드 쪽 `compositionstart`·`compositionend`) | 지금 한글을 조합 중인 칸. 다시 그리기로 떨어져 나간 칸(`isConnected === false`)은 끝난 것으로 본다. 주간요약(`report-ui.js`)의 "조합이 끝날 때까지 기다리기"도 이것을 본다 |
| `escPush(close)` · `escDrop(close)` · `escStack` | `app.js` | Esc는 가장 위에 열린 것 하나만 닫는다. 문서 `keydown` 하나가 스택 맨 위를 부른다 |
| `TABS[탭].enter` · `TABS[탭].leave` | `app.js` `setActiveTab`이 부름, 몸통은 화면 파일 | 탭을 옮길 때만(같은 탭 다시 누름은 아님), `activeTabKey`를 바꾸기 전에 떠나는 탭의 `leave` → 들어오는 탭의 `enter`. 지금 둘: 주간요약 `reportTabLeave`(`report-ui.js`), 프로젝트 `projectsTabEnter`·`projectsTabLeave`(`projects-ui.js`) |

## 한글 조합 추적

| 곳 | 무엇 | 공통 함수 |
|---|---|---|
| `app.js` `uiRenderHeld` · `uiGlide…`(줄 이동 멈춤) | 조합 중인 칸이 있는 구역은 다시 그리지 않음 · 줄을 움직이지 않음 | `uiComposingEl`·`uiComposingLive` |
| `report-ui.js` `reportLeaveSave` · 바깥 누르기 저장 기다림(`reportLeaveWait`) | 조합이 끝나 마지막 글자가 `reportEdits`에 들어온 뒤 저장·다시 그리기 | `uiComposingLive` (전에는 `reportComposing`·`reportComposingEl`·`reportStillComposing` 따로 — 2026-10-08 합침) |
| 칸마다의 `keydown` | `event.isComposing`이면 Enter·Esc를 넘김 | 브라우저 값 그대로(공통 함수 필요 없음) — 30여 곳 |

## Esc

`escStack`에 올리는 것(14곳): `uiMenu`·`uiSchedToggle`·`taskSelectStart`·`drawerOpen`·`panelOpen`·`palOpen`(`app.js`), `panelMeetingRowEdit`·`meetingTypeToggle`(`meetings-ui.js`), `projectRenameStart`(`projects-ui.js`), `projectNewStart`(`project-new-ui.js`), `waitingNextEdit`(`waiting-ui.js`), `jiraConfirmOpen`·`jiraLinkOpen`(`jira-ui.js`), `settingsOpen`(`settings-ui.js`), `wrapOpen`(`wrap-ui.js`), `usageWorkOpen`(`usage-ui.js`), `reportTidyStart`(`report-ui.js`).

칸·판 자기 `keydown`으로 처리하는 것(스택 안 씀, 15곳):

| 곳 | 파일 | 스택으로 안 가게 막나(`stopPropagation`) |
|---|---|---|
| `uiDateField` | `app.js` | 막음 |
| `uiGroupAddRow`(`.d-addinput`) | `app.js` | 막음 |
| `uiResultCell`(결과 한 줄) | `app.js` | 막음(저장 중의 Esc도 — 칸은 넘기기만) |
| `panelTitleEdit`(상세 제목) | `app.js` | 막음 |
| `makeEditableDesc`(결정 문구) | `app.js` | 막음 |
| `uiPickList`(고르개) | `app.js` | 막음 |
| `uiGroupNameInput` | `app.js` | 막음 |
| `panelMeetingDrafts`(초안 문구 접기) | `meetings-ui.js` | 막음 |
| `projectFindInput`(찾기 칸 비우기) | `projects-ui.js` | 값이 있을 때만 막음 |
| `reportRenameBox` · `reportMoveOpen` · `reportSentenceRow` · `reportAddLineRow` | `report-ui.js` | 막음 |
| `reportPlanInput`(다음 주 계획 적기 줄) | `report-ui.js` | 값이 있을 때만 막음 |
| `checkinKeydown`(체크인 창) | `checkin-ui.js` | 막음 |

칸의 Esc는 칸만 닫는다 — 막지 않던 넷(`uiGroupAddRow`·`uiResultCell`·`panelTitleEdit`·`makeEditableDesc`)이 Esc 한 번에 열린 상세 카드·서랍까지 닫던 것을 2026-10-08에 막았다(동작 관습 2).
`makeEditableDesc`의 Esc는 초점을 제목 판에 주기 **전에** `uiHeldFlush()`를 부른다 — 먼저 주면 같은 구역에 초점이 있다고 미룬 그리기가 계속 기다려 다른 창이 고친 문구가 안 보인다. 다시 그려졌으면 같은 id 줄(`data-move-id`)의 새 제목 판에 준다.

두 갈래를 하나로 모으지 않은 까닭: 칸의 `keydown`은 **그 칸에 초점이 있을 때만** 듣고, 스택은 **초점이 어디 있든** 듣는다. 칸을 스택에 올리면 칸에서 초점이 빠진 뒤의 Esc가 칸을 닫게 바뀐다.

## 바깥 클릭(초점이 나가면) 저장 — 동작 관습 1

| 곳 | 파일 | 바깥 클릭 | 듣기 |
|---|---|---|---|
| `panelTitleEdit` · `makeEditableDesc` | `app.js` | 저장 | `blur` |
| `panelMeetingRowEdit` | `meetings-ui.js` | 저장 | `blur` |
| `reportBlurWatch` → `reportBlurSave`(주간요약 칸 전부) | `report-ui.js` | 저장(탭을 떠날 때도 — `reportTabLeave`) | 구역 `focusout` |
| `uiDateField` | `app.js` | 확정 | `focusout` |
| `projectNewRender`(프로젝트 칸) | `project-new-ui.js` | 확정 | `blur` |
| `uiGroupAddRow`(`.d-addinput`) | `app.js` | 저장 안 함(글 그대로) | `blur` |
| `uiGroupNameInput` | `app.js` | 취소 | `blur` |
| `uiPickList` · `uiSchedToggle` | `app.js` | 닫기만 | `focusout`·`blur` |
| `settingsSlackWizard` · `settingsSlackPick` | `settings-ui.js` | 칸 정리만 | `blur` |
| 설정·오늘 정리·내 일 기록·체크인 창(`<dialog>`) | 각 파일 | **닫히지 않음**(✕·Esc·`취소`로만) | 없음 |

공통 함수는 없다 — 칸마다 3~10줄이고 하는 일(저장·취소·닫기만)이 갈려서 묶을 몫이 작다.

## 편집은 한 번에 하나 — 동작 관습 3

공통 함수는 없다. 지키는 길은 둘: ① 새 칸을 누르면 앞 칸에서 초점이 빠져 앞 칸의 `blur`/`focusout` 저장이 돈다(위 표), ② 떠 있는 층은 한 벌(`uiMenuClose` — 메뉴, `palOpen`이 메뉴를 먼저 닫음, 회의 초안 펼침은 한 줄). 주간요약은 `reportBlurWatch`가 다른 문장을 누른 누름(mousedown) 때 저장하고 뗌까지 다시 그리기를 미룬다.

## 공통 함수를 안 쓰는 곳 — 세기

- 조합 추적 중복: 1곳 → 0곳(합침).
- Esc를 스택 밖에서 처리: 15곳(위 표, 전부 칸만 닫음 — 값이 있을 때만 막는 둘은 빈 칸의 Esc가 스택으로 간다).
- 바깥 클릭 저장·편집 하나: 공통 함수 자체가 없음(칸마다 13곳).
- 저장 순서(`uiQueueSend`): Enter 뒤에도 칸이 남는 칸은 전부 씀 — `uiGroupAddRow`·`uiMenuText`·`setupQuickAdd`·`meetingCaptureSend`·`reportPlanInput`. 안 쓰는 칸은 Enter로 닫히는 칸(`uiResultCell`·주간요약 문장·이름 바꾸기·한 줄 추가 — 저장 중 표시 `saving`·`reportEnterSaving`)과 잠금 유지 셋(`panelTitleEdit`·`makeEditableDesc`·`panelMeetingRowEdit`)으로, 동작 관습 5에 적힌 그대로다.
