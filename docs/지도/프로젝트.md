# 지도: 프로젝트
> 이 주제 기능을 고치면 이 문서도 함께 고친다. 마지막 확인: 2026-09-29 · bundle-2(프로젝트 묶어 보기 덩어리 2 — 고르기 검색 칸·다른 화면 묶기)

## 한 줄 요약
업무·확인 대기·결정·아이디어를 묶는 단위. 프로젝트는 **지라 티켓(`jira:KEY`)** 이거나 **직접 만든 이름(`group:이름`)** 이고, 한 항목에는 프로젝트가 하나뿐이다. 프로젝트 목록은 따로 저장된 것이 아니라 항목·회의·내 담당 지라 티켓에서 **매번 계산**한다.

## 데이터 — 어디에 무엇이 저장되나
| 값 | 저장 위치(파일·설정 키) | 누가 쓰나 | 누가 읽나 |
|---|---|---|---|
| 항목의 프로젝트 | 업무 파일 줄의 `jira:KEY` 또는 `group:이름`(밑줄 저장, 화면은 공백), 아이디어는 `project:` | server.js:setTrackField(jira를 넣으면 group을 지우고 반대도 같음), task-batch.js(일괄), workflow-store.js:addToMeeting·review(회의 담기 기본값), routes-track.js `/api/idea/set-project` | workflows.js:wfKey(키 규칙: jira 우선 → group/project → 없음 `__misc__`), report-drafts.js:project, server.js:projectKeyOf |
| 그룹에 지라 티켓 하나 연결 | `tracker/.workflow.json`의 `projectLinks: { 그룹이름: "KEY" }` (그룹 하나에 티켓 하나, 표시 전용 — 항목의 jira는 안 바뀜) | workflow-store.js(link·checkProjectLink), routes-jira.js `/api/project/jira-link` | jira-ui.js:jiraKeyOf(화면에서 키→티켓의 유일한 길), server.js:linkedJiraKeys, report-ui.js:reportJiraKeyOf |

| 묶음(BBUNDLE, 표시 전용) | `.workflow.json`의 `projectBundles: [{ id, lead:'jira:A', keys:['jira:A','jira:B'], at }]` — 지라 키끼리만, 한 키 한 묶음, 키 2~10개, 묶음 100개까지(BUNDLE_MAX_BUNDLES — 묶인 키가 지라 추가 조회 100개 한도에 실림) | workflow-store.js:bundleProjects·unbundleProjects·setBundleLead·restoreBundle(`/api/project/bundle`·`unbundle`·`bundle-lead`·`bundle-restore`, server.js workflowActions) | workflow-store.js:cleanBundles(snapshot이 깨진 값을 걸러 보냄, 파일은 안 고침)·bundleLeadProject(회의 담기 기본값), projects-ui.js:projectBundles·projectBundleOf·**projectGroupKey**(여러 화면 공용 — 아래 표), server.js:linkedJiraKeys(묶인 키도 extra로 읽음) |
| 회의↔프로젝트 | `.meeting_links.json` (회의 **제목** → `jira:KEY`/`group:이름` 하나), 회의 기록의 `project` | server.js:setMeetingLink(+ workflows.syncProject — 오늘 회의와 고른 회의) | server.js:getCalendarWithLinks, workflows.js:wfMeetingKey, workflow-store.js:addToMeeting |
| 이름 바꾸기·옮기기 흔적 | `.workflow.json`의 `projectArchive`, 옮기기 기록(recordProjectMove) | server.js:renameProject·moveProject | workflow-store.js:renameGroup·moveGroup·undoMoveGroup |
| 내 담당 지라 목록(목록 모양) | 서버 메모리 `jiraIssuesCache` — `{key,type,status:"문자열",summary,extra,category,due,versions}` (담당·하위 없음), 10분마다 | jira-client.js:listMyIssues(`assignee = currentUser() AND statusCategory != Done`, 항목에 걸렸는데 빠진 키는 `extra:true`로 추가 조회) · jira-live.js | workflows.js:wfProjects, 고르기 목록, projects-ui.js:projectStatusOf |
| 지라 티켓 한 건(단건 모양) | 서버 메모리 키별 60초 — `{status:{name,category}, assignee, due, versions:[{id,…}], children:{total,done,items}}` | jira-client.js:shapeIssue | jira-ui.js 띠 카드 (클라이언트 `jiraCard`는 키 하나만 기억) |
| 반응 필요(지라 댓글) | 서버 메모리만 | jira-client.js:ATTENTION_JQL·shapeAttention, attention-live.js | attention-ui.js |
| 치운 반응 필요·뺀 옮기기 제안 | `.workflow.json` `attention.dismissed` / 브라우저 `projectMoveDismissed` | workflows.dismissAttention / projects-ui.js | 같은 곳 |

**주의 — 모양이 두 가지**: 목록 모양(status 문자열·category 최상위)과 단건 모양(status 객체)이 섞인다. 새 코드는 어느 쪽을 읽는지 확인한다(아래 "알려진 문제" 참고).

## 흐름 — 대표 경로
1. **업무의 프로젝트를 바꾸면** → app.js:renderGroupControl → setTaskJira/setTaskGroup → server.js:setTrackField(jira↔group 배타) → `load()` → wfProjects가 목록을 다시 계산.
2. **프로젝트 탭을 열면** → projects-ui.js:renderProjects(uiProjectRows) → 상세 renderProjectDetail → jiraKeyOf로 티켓 키 → jiraCardEnsure(단건 60초) → 띠 카드.
3. **묶음(BBUNDLE)을 열면** → renderProjects(projectBundleRows로 합친 줄) → renderProjectDetail(row.bundle) → jiraSideEnsure(나머지 키) + jiraCardEnsure(대표) → jiraStripPaint가 `#jiraStrip`·`#jiraStrip-KEY`를 함께 그림.
4. **회의를 프로젝트에 연결하면** → meetingMenuSections → `/api/meeting/set-project` → setMeetingLink(.meeting_links.json + syncProject) → (회의 탭) 이미 담은 항목 옮길지 확인 줄 → `/api/meeting/move-items`.
5. **주간요약 소제목** → server.js:projectLabelOf로 label → report-drafts.js bucket·group 저장 → report-ui.js:reportGroupTitles.

## 고칠 때 주의
- **새 키 종류**를 만들면 키를 만드는 곳(위 "프로젝트 키 만들기")과 검증 정규식 네 곳을 모두 고친다.
- `uiGroupTasks`를 고치면 `waiting-ui.js:waitingGroups`(복제본)도.
- `projectLinks`·`meeting_links`·`projectAliases`는 **값이 문자열 하나**라는 가정이 renameGroup·moveGroup·linkedJiraKeys·reportJiraKeyOf 등에 퍼져 있다.
- 배포일 판정 두 함수(projectDeployVersion vs deploySoonVersion)가 다르다 — 한쪽만 고치면 화면끼리 어긋난다.
- 지라에 쓰는 기능은 티켓 하나 단위·확인 줄 필수·⌘Z 대상 아님(DECISIONS).
- 주간요약은 저장된 문자열 기준이라 지난 주 보고에 소급하지 않게 조심.
- 묶음(BBUNDLE)으로 한 그룹이 되는 곳은 projectGroupKey 하나로 판단한다(오늘 탭·서랍·확인 대기·회의 탭 프로젝트별·고르기·반응 필요 색). **주간요약은 묶음을 모른다**(저장된 이름 단위 — 소급 위험). 리마인드(deployReminders)는 uiProjectRows(티켓별 줄)를 받아 스스로 합친다 — uiProjectRows 자체에 묶음을 넣으면 리마인드가 두 번 합쳐진다.
- 그룹(`group:`)을 묶음에 넣게 되면 renameProject·moveProject·undoMoveProject가 묶음 keys도 따라 바꿔야 한다(지금은 지라끼리만이라 해당 없음).

## 알려진 문제
- (고침, bundle-1) meetings-ui.js:meetingsProjectStatus가 목록 모양 캐시를 단건 모양으로 읽던 것 — 이제 목록 모양(`status` 글자·맨 위 `category`)으로 읽고 테스트도 목록 모양 가짜 데이터다.
- (고침, bundle-2) 하위 티켓 담당 거르기가 전역 하나라 다른 카드도 걸러지던 것 — 이제 jira-ui.js:jiraChildPicks·jiraChildDoneOpen이 티켓 키별이다(jiraChildReset(key), 프로젝트를 옮기면 전부 비움).
- jira-client.js:listMyIssues의 추가 조회는 `key in (…)` 한 번이라, 지워졌거나 권한이 없는 키가 하나 섞여 지라가 400을 주면 **내 담당 목록까지 통째로 실패**한다(가짜 fetch로 재현, 2026-09-29). 아직 고치지 않음.
