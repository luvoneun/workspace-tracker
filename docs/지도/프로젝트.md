# 지도: 프로젝트
> 이 주제 기능을 고치면 이 문서도 함께 고친다. 마지막 확인: 2026-10-08 · 열쇠 바꾸기 한 곳(project-keys.js 자리 표) — 그 전: 2026-10-06 프로젝트 정리(같은 이름 감지 확대·합치기·지우기)

## 한 줄 요약
업무·확인 대기·결정·아이디어를 묶는 단위. 프로젝트는 **지라 티켓(`jira:KEY`)** 이거나 **직접 만든 이름(`group:이름`)** 이고, 한 항목에는 프로젝트가 하나뿐이다. 프로젝트 목록은 따로 저장된 것이 아니라 항목·회의·내 담당 지라 티켓에서 **매번 계산**한다.

## 데이터 — 어디에 무엇이 저장되나
> 직접 만든 프로젝트의 이름(열쇠)이 글자로 박힌 자리 목록은 **`tracker/inbox-app/project-keys.js`의 자리 표(`SITES` · 일부러 안 바꾸는 `KEPT`) 하나**다. 이름 바꾸기·옮기기·합치기·지우기와 되돌리기는 모두 그 파일의 `rekeyProject`·`unrekeyProject`만 부른다. 새 자리를 만들면 표에 한 줄 — 안 올리면 `project-rekey.test.js`(데이터 폴더 전체에서 옛 이름 0번)가 빨개진다.

## 흐름 — 대표 경로
1. **업무의 프로젝트를 바꾸면** → app.js:renderGroupControl → setTaskJira/setTaskGroup → server.js:setTrackField(jira↔group 배타) → `load()` → wfProjects가 목록을 다시 계산.
2. **프로젝트 탭을 열면** → projects-ui.js:renderProjects(uiProjectRows) → 상세 renderProjectDetail → jiraKeyOf로 티켓 키 → jiraCardEnsure(단건 60초) → 띠 카드.
3. **묶음(BBUNDLE)을 열면** → renderProjects(projectBundleRows로 합친 줄) → renderProjectDetail(row.bundle) → jiraSideEnsure(나머지 키) + jiraCardEnsure(대표) → jiraStripPaint가 `#jiraStrip`·`#jiraStrip-KEY`를 함께 그림.
4. **회의를 프로젝트에 연결하면** → meetingMenuSections → `/api/meeting/set-project` → setMeetingLink(.meeting_links.json + syncProject) → (회의 탭) 이미 담은 항목 옮길지 확인 줄 → `/api/meeting/move-items`.
5. **주간요약 소제목** → server.js:projectLabelOf로 label → report-drafts.js bucket·group 저장 → report-ui.js:reportGroupTitles.

## 고칠 때 주의
- **새 키 종류**를 만들면 키를 만드는 곳(위 "프로젝트 키 만들기")과 검증 정규식 네 곳을 모두 고친다.
- `uiGroupTasks`를 고치면 `waiting-ui.js:waitingGroups`(복제본)도.
- `projectLinks`·`meeting_links`·`projectAliases`는 **값이 문자열 하나**라는 가정이 renameGroup·moveGroup·linkedJiraKeys·reportJiraKeyOf 등에 퍼져 있다.
- 배포일 판정 두 함수(projectDeployVersion vs deploySoonVersion)가 다르다 — 한쪽만 고치면 화면끼리 어긋난다.
- 지라에 쓰는 기능은 티켓 하나 단위·확인 줄 필수·⌘Z 대상 아님(DECISIONS).
- 주간요약은 저장된 문자열 기준이라 지난 주 보고에 소급하지 않게 조심.
- 묶음(BBUNDLE)으로 한 그룹이 되는 곳은 projectGroupKey 하나로 판단한다(오늘 탭·서랍·확인 대기·회의 탭 프로젝트별·고르기·반응 필요 색). **주간요약은 묶음을 모른다**(저장된 이름 단위 — 소급 위험). 리마인드(deployReminders)는 uiProjectRows(티켓별 줄)를 받아 스스로 합친다 — uiProjectRows 자체에 묶음을 넣으면 리마인드가 두 번 합쳐진다.
- 그룹(`group:`)을 묶음에 넣게 되면 묶음 keys를 project-keys.js 자리 표의 한 자리로 올린다(지금은 지라끼리만이라 해당 없음).
- 합치기·옮기기 대상에 같은 소제목 이름(weekPolish names)이 이미 있으면 대상 것을 남기고 옛 열쇠 이름 줄은 그대로 남는다(기존 규칙 — 빠뜨림 시험은 이 겹침 없이 심는다).

## 알려진 문제
- (고침, bundle-1) meetings-ui.js:meetingsProjectStatus가 목록 모양 캐시를 단건 모양으로 읽던 것 — 이제 목록 모양(`status` 글자·맨 위 `category`)으로 읽고 테스트도 목록 모양 가짜 데이터다.
- (고침, bundle-2) 하위 티켓 담당 거르기가 전역 하나라 다른 카드도 걸러지던 것 — 이제 jira-ui.js:jiraChildPicks·jiraChildDoneOpen이 티켓 키별이다(jiraChildReset(key), 프로젝트를 옮기면 전부 비움).
- jira-client.js:listMyIssues의 추가 조회는 `key in (…)` 한 번이라, 지워졌거나 권한이 없는 키가 하나 섞여 지라가 400을 주면 **내 담당 목록까지 통째로 실패**한다(가짜 fetch로 재현, 2026-09-29). 아직 고치지 않음.
