# 주간 보고 양식 — 구현 명세 (2차, 시안 4.1 기준)

- **왜 만드나**: 지금 주간요약은 업무 하나가 줄 하나이고 칸이 다섯(완료한 일·진행 중·새로 정해진 것·확인 완료·확인 대기)이라, 팀이 실제로 올리는 글("[완료] / [진행 예정]" 두 칸 → 프로젝트 → 짧은 명사구)과 모양이 다르다. 그래서 앱 글은 참고만 하고 슬랙에서 다시 쓴다.
- **어떤 사용자 행동이 달라지길 기대하나**: 금요일에 앱 글을 거의 그대로 복사해 올린다. 다음 주 칸을 빈칸에서 쓰지 않고, 채워진 것에서 덜어 낸다.
- **무엇을 보면 성공인가**: ①②는 ⓐ 붙인 글의 모양이 팀 글과 같고 ⓑ 다음 주 칸이 빈칸에서 시작하지 않으며 ⓒ 사용자가 두 주 연속 앱 글을 복사해 올린다. **줄 수가 크게 주는 것은 ③(Claude로 줄이기)이다** — 가짜 한 주로 세면 한 일 칸이 14줄 → 13줄이라 ①만으로는 거의 줄지 않는다.

기준 시안: `design/주간보고-양식-시안/index.html`(4.1차). 앞 시안(1~3차)은 같은 폴더에 참고로 둔다. 예시의 이름은 전부 가짜다.

## 목표 모양 (슬랙에 붙는 글)

```
10월 1주차 (9/28~10/4)

[완료]
• 결제 리뉴얼 (10/15 배포 목표)
    ◦ 결제 실패 사유 문구 초안 작성
    ◦ 환불 정책 문서 1차 작성
    ◦ 팔로업
• 운영툴 (진행 중)
    ◦ 관리자 권한 등급 확인
• 슬랙 문의 채널 정리

[진행 예정]
• 결제 리뉴얼
    ◦ 환불 API 연동 확인
• 금요일 휴가
```

- 서식 있는 복사(`text/html`: 칸 이름 굵게, 프로젝트는 `<ul><li>`, 그 아래 줄은 한 단계 안쪽 `<ul>`)와 글자만(`text/plain`, 위 모양)을 **함께** 담는다(붙이기 시험 "다").
- 프로젝트 사이에 빈 줄을 넣지 않는다. 빈 줄은 제목 뒤·칸 사이에만.

## 정해진 것 (사용자 결정 10/2~10/4, 1차 명세보다 우선)

1. **칸은 둘** — 한 일 칸·할 일 칸. 이름은 글자를 눌러 고치고 **그 맥에 기억**한다(기본 `[완료]`·`[진행 예정]`, 주마다가 아니라 사람마다 하나 — 브라우저 저장).
2. **한 일 칸**에는 완료한 일·진행 중·결정·확인이 **프로젝트별로 함께** 선다. 저장된 소제목(`heading`)은 바꾸지 않고 **보이는 모양과 슬랙 글만** 합친다(옛 앱이 같은 파일을 읽어도 깨지지 않게).
3. **끝말 다듬기는 규칙**(AI 아님): 업무 제목 끝의 `요청 답하기` · `하기` · `했음`만 뗀다. 업무 제목은 그대로이고 보고 줄에 손을 올리면 원래 제목이 풍선으로 보인다. 사람이 고친 줄은 다시 다듬지 않는다.
4. **소제목 괄호는 자동**(한 일 칸만): 배포 버전에 날짜가 있으면 `(10/15 배포 목표)` > 날짜 없는 배포 버전만 있으면 `(v2.70)` > 보고에 든 업무 줄이 전부 진행 중이면 `(진행 중)` > 없음. 사람이 고친 소제목이 이긴다(괄호까지 한 글자처럼 고친다).
5. **결정·확인 줄은 처음부터 흐리게 빠져** 그 프로젝트 아래 남는다. `다시 넣기`로 보고에 넣는다.
6. **뺀 줄은 지우지 않고 제자리에 흐리게** 남는다(취소선 없음, 읽어 주는 이름 `보고에서 뺌`). 슬랙 글에는 없다.
7. **줄에서 하는 일은 둘** — 글자를 누르면 고치기 / `정리` 모드에서 골라 아래 막대 버튼. 줄 끝에 버튼을 늘어놓지 않고, 문장 ⋯ 메뉴는 없앤다.
8. **정리 모드**: 평소 문서 머리에 `정리` 글자 하나(손볼 줄이 있으면 `정리 N`). 누르면 글머리 자리에 선택 칸 · 맨 위 알림 한 줄 · 아래 선택 막대. 머리 버튼은 `완료`가 되어 모드를 끝낸다. Esc 한 번은 떠 있는 목록만 닫고, 목록이 없으면 모드를 끝낸다. 모드 중에는 글자 고치기가 쉰다.
9. **알림 한 줄**: `팔로업으로 묶을까요? 결제 리뉴얼 2 · 운영툴 1` · `결정 1` · `프로젝트 없음 1` — 할 것이 있는 항목만. 누르면 그 줄들이 **미리 골라진다**(팔로업은 그 프로젝트 후보만). 눌러 본 항목은 흐려지고 머리 숫자에서 빠진다. 팔로업 후보 = 한 일 칸의 프로젝트 있는 업무 줄 중 업무 제목에 `팔로업`·`QA`·`대응`이 든 것. **앱이 스스로 묶지 않는다.**
10. **막대 버튼**(고른 줄에 맞는 것만, 일부에만 맞으면 끝에 줄 수 — 예 `프로젝트 옮기기 1`): `보고에서 빼기`(든 줄) · `다시 넣기`(뺀 줄·처음부터 빠진 결정·확인) · `팔로업으로 묶기`(한 일 칸, 프로젝트 있는 업무 줄) · `팔로업에서 빼기`(묶인 줄) · `프로젝트 옮기기`(업무 줄·할 일 칸에 적은 줄) · 맨 오른쪽 늘 `완료`. 눌러도 고른 줄은 그대로라 바로 반대 버튼으로 되돌린다.
11. **팔로업 묶기는 늘 프로젝트마다 따로**: 묶인 줄은 그 프로젝트 맨 아래로 흐리게(앞에 `팔로업` 꼬리표), 슬랙 글에는 그 프로젝트 맨 아래 `팔로업` 한 단어 한 줄. 여러 프로젝트 줄을 한꺼번에 골라도 각자 한 줄씩.
12. **프로젝트 옮기기**: 버튼 위로 작은 목록 — 프로젝트들 · `기타`(프로젝트 없이 맨 아래 `기타` 소제목) · `새 프로젝트…`(그 자리가 입력칸, Enter로 옮기고 업무에도 씀, Esc는 목록으로). 업무의 프로젝트도 같이 바뀐다.
13. **할 일 칸 미리 채우기**: ⓐ 진행 중 업무 ⓑ 지난주 계획 중 안 끝난 것 — 이 둘만. 실행일·기한만으로는 넣지 않는다(진행 중이면 기한이 다음 주여도 들어온다). 왜 들어왔는지는 풍선으로만. 덜어 낸(뺀) 줄은 다시 들어오지 않는다.
14. **할 일 칸에 적기**: 프로젝트마다 입력줄 `할 일 적기` + 맨 아래 `한 줄 적기 (휴가 · 이슈)`. 적으면 **보고에만** 들어가고, 프로젝트 아래 줄에만 작은 질문 `나중에 할 일에도 담을까요? 담기`(누르면 `담았어요 · 되돌리기`, 몇 초 뒤 숨고 손을 올리면 다시 보임). 초점은 입력줄에 남는다.
15. **Claude로 줄이기(③)**: 버튼을 누를 때만, Claude임을 드러내고, 제안은 지금 글 옆에 나란히, 받아들인 것만 저장. 금요일 자동 실행은 두어 주 뒤 결정.
16. **하지 않는 것**: 겹친 업무 처리(지금은 업무 삭제로) · 스레드에 바로 올리기 · 보고 요청과 잇기 · 손잡이로 끌기(④에서 결정).
17. **결정 대기 — 범위 밖**: 짧은 제목(시안 8번, 슬랙 수집이 처음부터 짧은 명사구로 적기). 사용자 답이 오기 전에는 손대지 않는다.

## 예외 상황

| 상황 | 동작 |
|---|---|
| **이름 바뀜** — 프로젝트 이름 바꾸기·별칭·에픽으로 옮기기 | 한 일 칸은 지금처럼 프로젝트 열쇠(`groupKey`)를 따른다. 팔로업 표시(행 안)는 행을 따라간다. **할 일 칸 줄은 이름(`group` 글자)으로 묶여서** 직접 만든 프로젝트 이름 바꾸기는 따라가지만(renameGroup) 지라 별칭 바꾸기는 안 따라간다(relabelProject는 bucket 있는 행만) — 지금도 같은 문제. ①에서 미리 채운 줄은 한 일 칸과 같은 이름 규칙(서버 `label`)으로 짓는다 |
| 이름 바뀜 — 칸 이름 | 브라우저 저장이라 다른 맥·다른 브라우저에서는 기본 이름. 빈 값으로 저장하면 기본으로 |
| 이름 바뀜 — 옛 소제목 이름이 `진행중|열쇠`에만 있음 | 한 일 칸은 `완료한 일|열쇠` → 없으면 `진행중|열쇠` 순서로 찾아 보인다. 고쳐 저장하면 `완료한 일|열쇠`에 쓴다 |
| 사람이 고친 소제목 = 자동 글자와 같음 | 원래대로(자동 괄호가 다시 따라감). 괄호는 화면이 계산하므로 화면이 같으면 빈 값을 보낸다 |
| **중복** — 같은 업무가 두 줄 | 진행 중 업무는 한 일 칸 `(진행 중)`과 할 일 칸에 함께 설 수 있다(팀 글도 그렇다). 진행 중이면서 지난주 계획에도 있으면 할 일 칸에는 한 줄(`planOf` 하나) |
| 중복 — 같은 이름으로 `새 프로젝트…` | 이미 있는 프로젝트(직접 만든 이름·지라 요약·별칭)와 같으면 그 프로젝트로 옮긴다(새로 만들지 않음) |
| 중복 — 겹친 업무 | 이번 범위에서 처리하지 않는다(사람이 업무를 지움) |
| **사라짐** — 업무 삭제 | 근거가 사라진 줄은 지금처럼 `확인 필요`. 흐린 줄·팔로업 줄도 남는다. 미리 채운 줄(아직 안 고친 것)은 사라진다 |
| 사라짐 — 완료 취소 | 자동 줄은 지금처럼 칸을 따라간다. 팔로업 표시는 행에 남아, 줄이 진행 중이 되어도 한 일 칸 그 프로젝트에 묶인 채 |
| 사라짐 — 진행 중이던 업무가 이번 주에 끝남 | 미리 채운 줄(안 고친 것)은 할 일 칸에서 빠진다. 고친 줄은 남는다 |
| 사라짐 — 프로젝트 삭제·묶음 풀기 | 줄은 `프로젝트 없음`으로 내려가고 팔로업 표시는 보이지 않는다(저장값은 지우지 않음). 알림 `프로젝트 없음 N`에 잡힌다 |
| 사라짐 — 결정·확인 줄의 업무 삭제 | 흐린 채로 근거 없음. 다시 넣으면 `확인 필요` |
| **옛 설치**(1.5.0 이하 앱이 같은 파일을 읽음) | 새 행 칸(`included`·`follow`·`origin:'carry'`)은 보존되지만 옛 앱은 몰라서 결정 줄을 보이고, 팔로업 줄을 보통 줄로, 미리 채운 줄을 보통 계획 줄로 보인다. 또 옛 앱은 미리 채운 줄(안 고친 줄·근거 없음)에 빈 글 수정 제안을 붙여, `제안대로 바꾸기`를 누르면 그 줄 글이 비워진다(옛 view엔 carry 건너뛰기가 없음). 드묾 — 각자 맥, 앱을 되돌릴 때는 데이터도 되돌림 |
| 옛 설치 — 옛 주의 접힌·합친·아래로 넣은 보고 | 그대로 읽힌다. 슬랙 글에서 접힌 부모는 `◦` 한 줄, 아래로 넣은 줄·여러 줄 문장은 각 줄이 `◦`(두 단계까지). 푸는 길(`따로 빼기`·`풀기`·`묶음 풀기`)은 ②부터 정리 막대 `풀기` |

### ③ Claude로 줄이기 — ①을 한 주 써 본 뒤 시작. 서버·자동화 바뀜 → 무거운 모델 + Codex 검토

**하는 것**

- **부르는 길은 기존 자동화와 같다**: 화면 → 서버가 요청 표시 파일 → launchd가 `run-task.sh`로 `claude -p`(새 스킬 `.claude/skills/report-condense.md`) → 제안 파일(앱은 읽기만). **서버는 프로세스를 띄우지 않는다.** 요청 파일을 지켜보는 launchd 작업은 새로 필요(지금 run-task.sh에는 요청 길이 없음 — `com.workspace.app.<작업>` 이름 규칙).
- **지어내지 않게 하는 선**: Claude에게는 그 주 보고 줄의 글과 id만 준다. 제안 줄마다 근거 id가 하나 이상이고, 서버가 ① id가 그 주 그 프로젝트 줄인지 ② 한 줄이 두 요약에 들지 않았는지 ③ 빠진 줄이 없는지 확인해 어긋난 프로젝트 제안은 통째로 버린다. 숫자·날짜·사람 이름은 원래 줄에 있는 것만(없는 숫자가 나오면 버림). 요청 때 줄 지문과 대조해 그 사이 고친 프로젝트 제안은 버린다.
- 줄이 3개 이하인 프로젝트는 제안하지 않는다. 사람이 고친 문장도 근거로는 쓰되 글은 요약 줄 아래 그대로 남는다.
- 세는 칸: `weekly_condense`(요청) · `weekly_condense_accept`(받아들인 프로젝트 수).

**하지 않는 것**: 금요일 자동 실행(두어 주 뒤 결정) / 할 일 칸 줄이기 / 받아들이기 전 보고에 닿는 것.
