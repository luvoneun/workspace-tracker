# 슬랙 수집 "원문 그대로" 모드 (Claude 없이도 수집)

## 세 줄
- **왜**: 슬랙 수집의 분류 단계가 Claude Code(유료 구독·로그인)에 묶여 있어, 구독이 없는 동료는 핵심 기능을 못 쓴다.
- **기대 변화**: Claude 없는 동료도 슬랙에서 전달한 메시지가 할 일·확인 대기·결정·아이디어로 빠짐없이 들어온다(문구는 원문 첫 줄). Claude 있는 사람은 지금 그대로.
- **성공 기준**: Claude가 없는 환경(가짜 PATH)에서 채널별 메시지가 원문 규칙대로 저장됨 · 기존 사용자(설정 없음)는 동작 변화 0 · 카드에 방식·주의 문구가 보임 · 테스트 전부 통과(개수 늘어남).

## 할 일
1. **설정**: `slack.tidy` = `'claude'`(기본, 칸 없음 포함) | `'raw'`. 연동 저장(`/api/integrations/save`)이 아는 키로만 받는다. 슬랙을 **처음 연결할 때** 이 맥에 Claude가 없으면(`claudeInstalled()`) `raw`를 기본으로 저장, 있으면 `claude`. 이미 연결된 사람은 칸이 없으므로 `claude` 그대로(동작 변화 0).
2. **수집(`slack-collect.js`)**: `processChannel`에서 `tidy === 'raw'`면 `runClassifier`를 부르지 않고 규칙으로 `answer`를 만든다 — 이후 저장(`importRecord`)·기록 줄·링크 중복 처리는 그대로 탄다. 갈래는 지금처럼 채널이 정한다.
   규칙(예외 목록 반영):
   - 글: 전달된 메시지면 원래 메시지 글, 아니면 메시지 글. 슬랙 표기 정리 — `<@U…>`→이름(이미 조회한 이름표), `<#C…|name>`→`#name`, `<url|글자>`→글자, `<url>`→url, `:emoji:` 제거 또는 그대로(판단해서 한쪽으로, 테스트 고정), `*굵게*`·`_기울임_`·`~취소~`·`` ` `` 기호 제거, `&amp; &lt; &gt;` 되돌림.
   - 첫 번째 비어 있지 않은 줄을 쓰고, 그 줄이 12자 이하면 다음 줄을 이어 붙인다. 목록 기호(`-`,`•`,`1.`)는 떼고, 한 메시지 = 항목 하나(나누지 않음).
   - 전달할 때 내가 적은 메모가 있으면 ` — 메모 첫 줄`을 뒤에 붙인다.
   - 200자에서 자르고 `…`. 줄바꿈 없음(`validateDescription` 통과).
   - 글이 없고 파일만: 이미지 설명(title/alt)이 있으면 그것, 없으면 `(파일) 파일 이름`.
   - 확인 대기 채널: 전달된 원래 메시지의 **작성자 이름**을 담당자(`who`)로(내가 쓴 메시지면 비움). 결정 채널: 지라 연결 안 함. **기한은 넣지 않는다**(잠금 — 원문에 날짜가 있어도).
   - 링크(`permalink`)는 지금과 같은 규칙(원래 메시지 링크 우선).
   - 시스템 메시지 거르기·한 회차 최대 개수·커서는 지금 그대로.
   - `claude` 모드에서 Claude가 실패하면 **지금처럼 실패 기록 + 다음 회차 재시도**(원문으로 대신 넣지 않음).
3. **카드(설정 › 연동 › 슬랙)**:
   - 정리 방식 선택: `원문 그대로` / `Claude로 다듬기`(Claude 없으면 흐리게 + "Claude Code가 있어야 해요").
   - `원문 그대로` 아래 한 줄: **"요약하지 않고 메시지 첫 줄을 그대로 넣어요. 문구가 길거나 정확하지 않을 수 있으니, 필요하면 앱에서 고쳐 주세요."**
   - 상태 줄에 지금 방식(예: `원문 그대로 받는 중`).
   - `claude` 모드인데 Claude가 없거나 로그인 풀림이 이어지면(가장 최근 실패가 claudeAuth이거나 claudeReady false) 카드에 `원문 그대로로 바꾸기` 버튼(자동 전환 없음).
   - `raw` 모드인데 이 맥에 Claude가 있으면 조용한 한 줄 `이제 Claude로 다듬을 수 있어요`.
   - 방식을 바꾸면 이미 들어온 항목은 그대로(다시 다듬지 않음).
4. **긴 문구**: 할 일·확인 대기 줄 문구가 길면 1.1.5 아이디어 줄과 같은 **두 줄 말줄임 + 클릭/Enter로 펼침**(같은 부품 재사용, 새 부품 금지). 이미 그렇게 돼 있으면 건드리지 않는다.
5. **주간보고 초안**: 할 일 문구가 들어갈 때 **첫 문장(마침표·물음표·느낌표 또는 80자)까지만** — 기존 문구가 짧으면 변화 없음(기존 테스트 유지).
6. **도움말**: 문답 "슬랙에서 온 할 일이 요약되지 않고 길게 들어와요" → 원문 그대로 모드 설명 + 부정확할 수 있음 + Claude로 다듬기 조건. 답은 260자 이하(기존 테스트 규칙).
7. **문서**: 앱 README 슬랙 절, `docs/연동.md` 슬랙 절, `.claude/skills/slack-*.md`에 "원문 모드에서는 이 지침이 쓰이지 않는다" 한 줄, DECISIONS 한 줄(원문 모드: 갈래는 채널, 기한·요약 없음, Claude 실패 때 원문 대체 안 함).

## 예외 상황 (테스트로 고정)
1. 슬랙 표기(사람·채널·링크·굵게·&amp;) 정리
2. 첫 줄이 짧은 인사말 → 다음 줄 이어 붙임
3. 목록 여러 개 → 항목 하나(첫 줄)
4. 줄바꿈 없는 긴 글 → 200자 + …
5. 파일만 → 설명 또는 `(파일) 이름`
6. 확인 대기 담당자 = 원래 메시지 작성자, 내 메시지면 비움
7. 날짜가 적힌 원문 → 기한 없음
8. claude 모드 + Claude 실패 → 원문으로 넣지 않고 실패·재시도
9. 기존 설정(칸 없음) → claude 모드 그대로
10. 방식 전환 → 기존 항목 불변
11. 링크 중복 → 지금처럼 건너뜀
12. 밀린 메시지 → 한 회차 최대 개수 유지, 기록에 개수
