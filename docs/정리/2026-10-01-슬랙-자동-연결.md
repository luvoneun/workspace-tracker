# 슬랙 자동 연결 (v1.5.0 후보) — 구현 명세

- **왜 만드나**: 슬랙 연결이 설치에서 가장 큰 벽이다. 지금은 슬랙 개발자 화면에서 토큰을 찾아 복사해 붙여야 하고, 만든 사람이 동료를 앱 협업자로 넣어 줘야 한다.
- **어떤 사용자 행동이 달라지길 기대하나**: 동료가 `슬랙 연결` 버튼 → 슬랙의 `허용` 한 번으로 연결을 끝낸다. 토큰을 복사하지 않고, 연결이 끊겨도 `다시 연결` 한 번으로 돌아온다.
- **무엇을 보면 성공인가**: ① 만든 사람 맥에서 새 방식으로 옮긴 뒤 며칠 동안 12시간 갱신이 사람 손 없이 이어진다 ② 동료 한 명이 도움 없이 버튼만으로 연결한다 ③ 옛 토큰 사용자는 아무것도 하지 않아도 그대로 돈다.

시안(확정): `design/슬랙-자동-연결-시안/index.html`. 하지 않는 것: 지라 OAuth, 중계 서버, 티로 자동 설치.

## 예외 상황

| 상황 | 동작 |
|---|---|
| 옛 설치(옛 토큰 한 줄 파일만 있음, `slack.auth` 없음) | `token`으로 읽고 지금과 똑같이 돈다. `⋯ › 새 방식으로 다시 연결 (자동 갱신)`으로만 옮긴다 |
| 옮긴 직후 | 옛 토큰 파일은 `.legacy`로 보관, 새 방식이 7일 정상이면 앱이 지운다. 7일 안에 풀리면 지우지 않는다 |
| 서버와 수집이 동시에 갱신하려 함 | 잠금(폴더 만들기)으로 한쪽만 갱신. 잠근 뒤 파일을 다시 읽어 이미 새 토큰이면 갱신하지 않는다(갱신 토큰은 한 번 쓰면 바뀐다) |
| 잠금을 쥔 프로세스가 죽음 | 잠금 안의 pid가 살아 있는지 보고, 죽었으면 잠금을 거둔다. 프로세스 목록을 훑지 않는다 |
| 갱신 중 네트워크·5xx 실패 | 이전 토큰 유지, 1 → 5 → 15분 뒤 다시. 점검하기에 `갱신이 잠시 안 돼요` |
| `invalid_refresh_token`·`token_revoked` | 다시 하지 않고 `다시 연결 필요`(빨강) |
| 갱신 토큰 30일 만료(앱을 오래 꺼 둠) | 위와 같이 `다시 연결` 한 번 |
| 파일 쓰다 죽음 | 임시 파일에 쓰고 이름 바꾸기로 교체해 반쪽 파일이 남지 않는다 |
| 허용 화면에서 취소 / 관리자 승인 대기 / 회사 슬랙이 앱을 막음 | 시안의 세 문구로 따로 말한다 |
| 허용 탭을 닫음·10분 넘김 | 기다림을 끝내고 처음 카드로. `다시 열기`·`취소` |
| 버튼을 여러 번 누름 | state는 1회용·10분·최대 3개, 넘으면 가장 오래된 것을 버린다 |
| state가 틀리거나 이미 쓴 콜백 | 거절하고 토큰을 바꾸지 않는다. 완료 탭에 값 없는 한 줄 |
| 서버 포트가 4321~4331 밖 | 버튼 대신 안내 한 줄(등록된 주소가 아니라 슬랙이 거절한다) |
| 다른 기기(Tailscale)에서 엶 | 버튼을 회색으로, `슬랙 연결은 앱을 설치한 맥에서 해 주세요.` |
| 다른 워크스페이스로 허용함 | 받은 팀이 기대한 팀과 다르면 저장하지 않고 알린다 |
| 받은 권한이 모자람 | 저장은 하되 점검하기 `받은 권한 목록` 줄에서 빠진 것을 말한다 |
| 채널 이름 바뀜·사라짐 | 지금 규칙 그대로(ID로 추적). 이 작업에서 바꾸지 않는다 |
| 팀 설치 묶음 | `slack.clientId`만 허용 목록에 더한다. 토큰·갱신 정보는 묶음에 넣지 않는다 |

## 정해진 것

- 화면(2026-10-01 사용자 결정): 큰 버튼 문구 `슬랙 연결`, 옛 방식은 카드 안 접힌 링크 `고급: 토큰 직접 붙여 넣기`(누르면 지금 화면이 그대로 펼쳐진다).
- Client ID는 코드 기본값 + 설정 `slack.clientId`로 덮어쓰기. Client Secret은 쓰지 않는다(PKCE).
- 권한(User Token Scopes) 6개: `channels:read` `channels:history` `groups:read` `groups:history` `users:read` `groups:write`. Bot 권한 없음.
- 받는 토큰은 12시간짜리 회전 토큰, 갱신 토큰은 30일이고 갱신할 때마다 바뀐다(실제 슬랙에서 확인).
- 아직 모르는 것: 협업자가 아닌 동료가 허용만으로 되는지·관리자 승인이 필요한지(동료 한 명 시험), 30일이 "발급 후 30일"인지.

## 설계

- **공용 모듈 `slack-auth.js`**(`getSlackToken()`): 서버와 수집 스크립트가 같이 쓴다. 잠금 → 다시 읽기 → 필요할 때만 갱신 → 임시 파일 + 이름 바꾸기. 서버는 15분마다 확인해 만료 60분 전에 미리 갱신, 수집은 실행 직전 만료 10분 전 기준. API가 `token_expired`·`invalid_auth`면 강제 갱신 한 번 뒤 한 번만 다시 부른다.
- **파일**: 갱신 정보는 새 `~/.config/workspace-slack-oauth.json`(0600). 기존 한 줄 `workspace-slack-token`에는 지금 쓸 토큰을 계속 복사해 둔다(형식을 깨지 않는다). 설정: `slack.auth: oauth|token`(없으면 `token`)·`slack.oauthFile`·`slack.clientId`.
- **서버 경로**: `GET /slack/callback`(정적 파일 처리보다 앞), `POST /api/integrations/slack-oauth/start`(로컬 루프백만, 출처 검사 그대로), `GET /api/integrations/slack-oauth/status`. state와 code_verifier는 서버 메모리에만. `redirect_uri`는 늘 `http://localhost:<서버 포트>/slack/callback`. 토큰 값을 돌려주는 응답·로그는 없다.
- **화면**: 처음 카드(버튼·설명 한 줄·접힌 고급), 기다리는 중(`다시 열기`·`취소`, 2초마다 상태 확인), 완료 탭(`✓ 연결됐어요 — 이 탭은 닫아도 돼요`), 연결된 카드 줄 끝 `자동 갱신 켜짐`, 풀림 카드 `다시 연결`, 점검하기 줄 넷. 문구는 시안 그대로.

## 묶음 (하나씩 순서대로, 각자 작은 버전)

| # | 내용 | 고치는 곳 | 모델·검토 |
|---|---|---|---|
| ① | 공용 갱신 모듈과 시험 | 새 `slack-auth.js`·`slack-auth.test.js`만 | Opus · Codex |
| ② | 서버 경로 셋 + 연결 버튼 화면 | `server.js`·`integrations.js`·설정 화면·`ui.css` | 서버 Opus · Codex, 화면은 디자인 검수 |
| ③ | 읽는 곳 연결 | `slack-collect.js`, `integrations.js` 읽는 곳, `SLACK_AUTH_RE`, `setup.sh`, `make-team-installer.sh`, 서버 15분 타이머 | Opus · Codex |
| ④ | 점검하기·README·`docs/연동.md`·DECISIONS·소식 | 문서와 selfcheck | Sonnet |

①은 아무 데서도 부르지 않는 새 파일이라 합쳐도 동작이 바뀌지 않는다. ②부터 서버 재시작이 필요하다. 자동화 복사본 갱신은 필요 없다(`slack-collect.js`는 저장소 코드).

배포 순서: 만든 사람 맥에서 먼저 옮겨 며칠 관찰 → 동료 한 명 시험 → v1.5.0. 옛 슬랙 앱은 안전망으로 한동안 둔다.
