## 할 일
1. **0은 적지 않는다**: 오늘 할 일 머리 개수, 오늘 미팅·확인 대기 카드 제목 옆 개수, 아이디어·결정 제목 옆 개수 — 0이면 숨김(hidden), 1 이상이면 지금 그대로. 머리줄(index.html:50 `결정 검토 N · 확인 대기 N` 같은 요약 줄)이 있으면 그 줄은 사용자 눈에 어떻게 보이는지 확인하고, 0·0이면 어떻게 할지 판단해 보고(시안에 없음 — 지금 그대로가 기본).
2. **`나중에 할 일 N` 버튼**: 나중에 할 일이 0이면 숨김. 1 이상이 되면 나타남. 서랍이 열린 상태에서 마지막 하나를 오늘로 옮겨 0이 되면 — 서랍은 열린 채 두고(닫기 버튼 있음) 버튼만 숨기되, 초점이 버튼에 있었다면 사라진 요소에 남지 않게. 서랍을 여는 다른 길(단축키·⋯ 메뉴 등)이 있으면 그대로.
3. **빈 목록 문장 짧게**: 오늘 할 일 `오늘 할 일이 비었어요.`, 아이디어 `아이디어가 아직 없어요.`, 결정 `정해진 내용이 아직 없어요.` — 뒤의 "맨 위 줄에서…" 문장 제거, 입력 칸 바로 아래라 여백도 줄임(시안 `.empty.s`: padding 4px 10px 14px, 14px, --dim). 다른 자리의 d-empty(검색 결과 등)는 그대로 — 이 세 자리에만.
4. **사용설명서 카드(오늘 탭만)**: 시안 `start2` 모양 — 넓게 2×2 격자, ≤520은 1열. 각 칸 한 줄 `이름 설명 ›`(버튼 줄만 › , 설치 줄은 앱 아이콘 22px 하나를 이름 앞에). 설치 줄 설명은 짧게(`크롬 ⋮ → 페이지를 앱으로 설치`, 설치 버튼이 뜨는 크롬이면 버튼 하나, 설치된 창이면 지금처럼 `Dock에 두기` 한 줄) — 긴 설명·`이미 설치했으면…`·Dock 그림은 **도움말(renderSettingsManual)에만** 남긴다. 좁은 폭 짧은 문구(시안의 `설정 ⚙ → 연동에서`, `전달로 채널에`)는 CSS만으로 안 되면 넓은 문구 그대로 두고 보고(새 분기 최소). usageGuideLine() 줄은 그대로 맨 아래에 붙인다(모양은 usage-ui.css 그대로 — 좁은 폭 짧은 문구도 하지 않음). 닫기·기억 규칙(DECISIONS 2026-09-24) 불변. 누르는 줄은 여전히 button, 초점 링·44px 누르는 자리 유지.
5. **결정 0개**: 미반영 결정 0 **이고** 반영 완료 0이면 `결정 찾기` 칸과 `반영 완료` 접힘을 숨김. 반영 완료가 1개라도 있으면 지금 그대로. 찾기 칸에 글자가 있는 상태에서 0이 되는 경우(마지막 결정 삭제)는 찾기를 비우고 숨기는지 판단해 보고.
6. **문서**: DESIGN.md(사용설명서 카드 모양, 개수는 1 이상일 때만), README 해당 절(현재 동작만).

## 예외 상황 (테스트로 고정)
1. 데이터 있음: 개수·버튼·찾기·접힘 전부 지금 그대로
2. 0 → 1: 개수와 `나중에 할 일` 버튼이 다시 그릴 때 나타남(1 → 0은 사라짐)
3. 서랍 열린 채 0이 됨: 서랍은 열림 유지, 초점이 사라진 버튼에 남지 않음
4. 사용설명서: 넓게 2×2 / 좁게 1열, 버튼 줄 3개는 여전히 button이고 같은 곳으로 데려감, 닫기 규칙 불변, 도움말(renderSettingsManual) 모양·문구 불변
5. 결정: 둘 다 0이면 찾기·접힘 숨김, 반영 완료만 있으면 보임
6. 빈 문장 세 자리만 짧아지고 다른 d-empty 불변
7. 안전장치 정의 불변(기존 해시 테스트 통과)
