# 새로 들어온 것 — 일정 정하기 — 구현 명세

- **왜 만드나**: `새로 들어온 것`에서 중요한 것은 "끝냈나, 언제 할 건가"인데 지금은 `오늘`·`나중에` 둘뿐이라 내일·다음 주로 정하려면 ⋯ 안으로 들어가야 한다. 프로젝트 정하기도 ⋯ 안에 숨어 있다.
- **어떤 사용자 행동이 달라지길 기대하나**: 들어온 항목마다 `일정 정하기`를 눌러 실행 날짜(오늘·내일·이번 주·다음 주·날짜·나중에)와 프로젝트를 그 자리에서 정한다.
- **무엇을 보면 성공인가**: ① 날짜 없이 `나중에`로만 쌓이는 업무가 줄고 실행 날짜가 붙은 업무가 는다 ② 프로젝트 없는 업무가 줄어든다 ③ 키보드로는 Enter 두 번(열기 → 오늘)이면 지금의 `오늘`과 같다.

시안(확정 2026-10-02): `design/일정-정하기-시안/index.html` — 안 A(줄 옆 팝오버), 버튼 이름 `일정 정하기`, 모션 쫀득.

## 정해진 것

- `새로 들어온 것` 줄의 `오늘`·`나중에` 두 버튼을 `일정 정하기 ⌄` 하나로 바꾼다. `완료`와 ⋯는 그대로.
- 누르면 버튼 바로 아래에 기존 더보기 메뉴 부품 모양의 판이 뜬다. 항목: `오늘` · `내일` · `이번 주` · `다음 주` · `날짜 고르기…` · (구분선) `나중에`(날짜 미정) · (구분선) `프로젝트`(누르면 판 안에서 목록이 펼쳐진다). 날짜 항목 오른쪽에 실제 날짜(`10/6 (화)`)와 숫자 키.
- 열리면 `오늘`에 초점. Enter = 오늘, 숫자 1~5·0(나중에), ↑↓, Esc로 닫고 누른 버튼에 초점을 돌려준다.
- `이번 주` = 이번 주 금요일, `다음 주` = 다음 주 월요일. 목·금·토·일에는 `이번 주`를 숨긴다(내일·오늘과 겹치거나 지난 날이라).
- 저장은 지금 있는 실행 날짜(`scheduled`) 길 그대로다 — 새 데이터 칸·새 API 없음. `나중에`는 지금의 `나중에` 버튼과 같은 동작(`scheduled:none`).
- 프로젝트는 지금 ⋯ 안의 프로젝트 칸과 같은 저장 길을 쓴다. 날짜를 고르기 전에 정할 수 있고, 프로젝트만 정하고 닫아도 된다.
- 모션(쫀득): 판 등장 240ms, scale .88 → 1.025(55%) → 1, 시작점은 누른 버튼 쪽, 항목은 18ms 간격으로 이어 뜸. 닫힘 140ms. 고른 뒤 줄 접힘 220ms, 오늘 목록의 새 줄 솟음 260ms + 연파랑 강조. `prefers-reduced-motion`이면 전부 즉시. DESIGN.md 모션 절의 "장식적인 움직임은 없다"에 이 판만의 예외 한 줄을 더한다.

## 예외 상황

| 상황 | 동작 |
|---|---|
| 판이 열린 동안 구역이 다시 그려짐(서버 갱신) | 판이 열려 있으면 그 구역 다시 그리기를 닫힐 때까지 미룬다(입력 중 다시 그리기 보류와 같은 장치) |
| 화면 맨 아래 줄 | 판을 위로 뒤집는다(기존 ⋯ 메뉴와 같이) |
| 390px | 판이 화면 밖으로 나가지 않게 폭·위치를 맞춘다 |
| 미래 날짜로 정함 | `나중에 할 일` 서랍으로 들어간다 — 서랍 줄에 실행 날짜가 보이는지 확인하고, 안 보이면 보이게 한다 |
| 기한(`due`)이 오늘이거나 지난 항목 | 지금 규칙 그대로 오늘 목록에 보인다(실행 날짜를 덮어쓰지 않는다) |
| 저장 실패 | 줄을 되돌리고 기존 알림 문구로 알린다. 판은 닫는다 |
| ⌘Z | 지금의 `오늘`·`나중에` 되돌리기와 같은 이름표로 되돌린다 |
| 프로젝트가 없는 설치 | 프로젝트 줄에 빈 목록 대신 한 줄 안내 |
| 프로젝트 이름 바뀜·사라짐 | 목록은 열 때마다 지금 프로젝트로 그린다. 사라진 프로젝트가 붙은 업무는 지금 규칙 그대로 |
| 여러 줄 선택(선택 막대) | 이번 범위 밖 — 선택 막대의 `오늘`·`나중에`는 그대로 둔다 |
| 반응 필요·확인 대기의 `할 일로` 입력칸의 `오늘`·`나중에` | 이번 범위 밖 — 그대로 둔다 |
| 옛 설치·옛 데이터 | 데이터 형식이 안 바뀌므로 해당 없음 |
