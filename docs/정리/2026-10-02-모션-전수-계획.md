# 모션 전수 조사와 "빠짐없이 적용" 계획

조사 기준: 가장 최신 가지(모션 기반·회의 적기·일정 되돌리기가 들어간 것)의 `tracker/inbox-app/`. 코드는 읽기만 했다. 화면을 띄우지 않고 코드로 조사했으므로 "실제로 어떻게 보이는지"가 걸린 곳은 **추정**이라고 적었다. 하루 빈도는 전부 추정이다.

- **왜 만드나**: 쫀득한 모션이 일정 정하기 판과 회의 종류 목록에만 있고 나머지는 옛 모션이거나 뚝 바뀐다. 어제 계획은 "순간" 15개를 골라 담아서, 목록에 없는 화면은 끝까지 빠진다.
- **어떤 사용자 행동이 달라지길 기대하나**: 어느 화면에서든 연 것은 누른 곳에서 열리고 짧게 닫히며, 줄은 미끄러져 자리 잡는다 — 화면마다 손맛이 달라 "여기는 왜 뚝 끊기지" 하고 멈칫하지 않는다.
- **무엇을 보면 성공인가**: 부록 전수 목록 263줄이 모두 `적용됨` 또는 `의도적으로 안 움직임(이유 있음)`이 된다. 새 화면 요소를 만들 때 시험이 빠짐을 잡는다. 일주일 써 본 뒤에도 거슬린다는 말이 없다.

## 1. 결론

1. **빠진 것이 맞다.** 화면에서 나타나고·사라지고·바뀌는 것 263가지 가운데 새 모션은 21가지(8%)뿐이다. 113가지는 아예 뚝 바뀌고, 74가지는 옛 값이며, 6가지는 열릴 때만 움직이고 닫힘은 즉시다.
2. **방향: "순간을 하나씩"이 아니라 "부품 8개를 한 번에".** 모든 항목을 부품 8개로 나누고 부품마다 공용 구현 하나를 둔다. 그 부품을 쓰는 화면은 따로 손대지 않아도 같은 모션을 갖는다.
3. **"전부 적용"은 "전부 움직인다"가 아니다.** 263줄 가운데 49줄은 움직이지 않는 것이 맞다(글자 입력 중, 자동 갱신, 키보드 연타, 경고). 이 줄들도 표에 이유와 함께 적혀 있어야 완료다 — 빈칸이 없는 것이 기준이다.
4. **묶음 7개(0, A~F), 각각 하루 안쪽.** 0에서 빠짐을 잡는 시험과 지도 문서를 먼저 세우고, A(누름·색) → B(뜨는 것) → C(줄) → D(펼침·값) → E(전환·기다림) → F(드문 순간·세기 조정) 순서다.
5. **가장 큰 구조 문제**: 목록·카드를 매번 통째로 다시 그리기 때문에, CSS에 이미 적혀 있는 전환(접기 꺾쇠 회전, 세그먼트 색, 고른 줄 배경) 여러 개가 **실제로는 재생되지 않는다**(추정 — 새 요소로 갈아 끼워지기 때문). 그래서 CSS만 고쳐서는 절반밖에 안 된다. 줄 이동 도우미처럼 "그리기 앞뒤를 잇는" 공용 도우미가 필요하다.

### ① 뜨는 것 (25줄: 41~43, 72, 80~82, 92~95, 99~100, 102~104, 132, 144~145, 151~152, 192, 197~198, 219)

- **지금 몇 벌인가 — 여닫는 코드가 8벌로 흩어져 있다.**
  1. 더보기 메뉴 `uiMenu`/`uiMenuClose` (app.js:159-246) — 한 벌. 부르는 곳은 직접 11곳 + `uiMoreButton` 경유 23곳. 열림 120ms 위 6px, 닫힘은 `list.remove()` 즉시.

  5. 검색 팔레트 `palOpen`/`palClose` (app.js:4389-4491) — 열림 140ms, 닫힘 `root.remove()` 즉시, 가림막 전환 없음.
  6. 알림 `showNotice` (app.js:1547-1599) — 열림 140ms, 닫힘 `hidden = true` 즉시. 부르는 곳 112곳 + `announce` 36곳.

- **공용으로 묶는 길**
  - CSS 부품 하나 `.m-float`(이름은 구현 때 정함): 2번의 값을 일반화 — 시작점 `--ox`/`--oy`, 등장 `--spring-1` 200~240ms, 닫힘 `.is-out` 100~140ms.
  - JS 도우미 둘: "누른 곳을 시작점으로 놓기"(2번·3번의 자리 잡기를 하나로)와 "닫힘 재생 뒤 치우기"(`is-out` + 시간으로 제거 — 끝남 신호를 기다리지 않는 기존 방식 그대로). 1·3·4·5번이 이것을 부른다.
  - **안전장치 정의를 안 고치는 길(알림·창·막대)**: `hidden` 토글과 `<dialog>` 여닫기는 CSS만으로 닫힘을 줄 수 있다 — `transition-behavior: allow-discrete`와 `@starting-style`(표시 여부가 바뀔 때도 전환을 재생하는 CSS 기능). `showNotice`·`settingsClose`·`wrapClose`를 한 글자도 안 고치고 `.d-toast`·`.d-modal`·`.d-selbar`의 CSS만 바꾼다. 덤으로 알림이 떠 있을 때 새 알림이 와도 다시 튀지 않는다(전환은 표시가 바뀔 때만 재생). **확인 필요(추정)**: 앱 창(크롬)에서는 되는 기능이지만 실제로 띄워 확인하지 않았다. 모르는 환경(구형 아이폰)은 지금처럼 즉시 닫힌다 — 깨지지 않는다.

- **지금**: 줄 이동 도우미 `uiRowsMove`에 걸린 목록은 **3개뿐**(새로 들어온 것·오늘·나중에 — app.js:2843, 5280, 5406). 통째로 다시 그리는 목록은 그 밖에 14개쯤 있다: 오늘 미팅, 리마인드, 확인 대기, 반응 필요, 아이디어, 결정, 주간요약 문장, 회의 목록, 회의에서 나온 것, 지난 회차, 프로젝트 목록, 프로젝트 상세, 삭제한 항목, 오늘 정리 줄.

### ⑥ 화면 전환 (23줄: 2, 71, 75, 107, 116, 119, 123, 131, 137, 139, 148, 153~154, 168, 171, 193, 196, 203, 207, 227, 231, 250~251)

- **지금**: 탭은 `hidden`을 바꿔 뚝 바뀌고 밑줄은 고른 탭에 새로 그려진다(app.js:6340-6343). 세그먼트(오늘 보기, 아이디어·결정, 설정 탭, 오늘 정리, 회의·프로젝트 보기, 내 일 기록 기간, 새 프로젝트)는 버튼마다 배경색만 바뀌고 손잡이가 없다 — 그나마도 다시 그려지는 곳은 색 전환이 안 보인다(추정). 회의·프로젝트·주차를 고르면 오른쪽 내용이 통째로 바뀐다.
- **공용으로 묶는 길**: ① 미끄러지는 손잡이 하나 — 탭 밑줄과 세그먼트가 같이 쓴다(고른 버튼의 자리로 `transform` 이동 200ms; 다시 그려지는 세그먼트는 "전에 고른 자리"를 기억해 거기서 출발). ② 내용 교체는 "100ms 나타남만" 클래스 하나(옆으로 밀지 않는다).

### ⑦ 기다림 (16줄: 6, 11, 150, 159, 161, 164, 174, 180~181, 200, 210, 242~243, 245, 255, 260)

- **지금**: 헤더 새로고침만 한 바퀴 돈다. `…하는 중` 글자만 바뀌는 곳이 10곳 넘고(가져오는 중, 확인하는 중, 보내는 중, 만드는 중, 찾는 중…), 맥 캘린더 확인은 최대 90초 동안 글자뿐이다. 저장 잠금 `fadeOutAndRun`은 이름과 달리 `aria-busy`만 걸고 보이는 것이 없다(14곳에서 부름). 지라 새로고침 버튼은 돌지 않는다. 업데이트 진행 ⟳은 2초마다 다시 그려져 0도에서 다시 시작한다.
- **공용으로 묶는 길**: CSS 규칙 하나 `[aria-busy="true"]` — 0.3초가 지나면 살짝 옅어진다(짧은 저장에는 아무것도 안 보임). **`fadeOutAndRun` 정의를 안 고치고** 14곳이 한 번에 표시를 얻는다. `…하는 중` 버튼들은 이미 `aria-busy`를 거는 곳(미팅 노트)과 같은 방식으로 맞춘다(부르는 쪽 한 줄씩).
- **값**: 표시가 나타나기까지 300ms 기다림, 회전 400ms 한 바퀴 또는 1s 반복(도는 동안만). 늘 도는 장식은 늘리지 않는다.

### ⑧ 드문 순간 (9줄: 76, 106, 124, 165, 173, 186, 188, 201, 256)

- **지금**: 오늘 다 끝냄 문장, 연결 완료 `✓`, 꾸미기 `✓ 바뀌었어요`, 체크인·새 프로젝트 완료 화면 — 전부 뚝. "밝히기"는 세 벌이 따로다(팔레트에서 연 줄 1.6s 테두리, 설정 카드 400ms 배경, 문답 400ms 배경+그림자) + 주간요약 `확인 필요`는 밝힘 전환이 없다.

### 어제 계획과 달라지는 점

어제 계획의 ②(체크·옮기기·누름)·③(열고 닫는 것)·④(다듬기)는 **화면의 순간**을 골라 담았다 — 오늘 탭의 체크, 오늘 탭의 메뉴, 설정 창 식으로. 이 계획은 같은 일을 **부품 단위**로 다시 묶는다: 어제의 ②는 A(누름)와 C(줄·완료 흐름)로, ③은 B(뜨는 것)와 D의 서랍으로, ④는 E(탭 밑줄)·D(접기)·F(다 끝냄·새 항목 점)로 간다. 달라지는 것은 셋이다. 첫째, 범위가 15개 순간에서 263줄로 넓어진다 — 확인 대기·반응 필요·회의·프로젝트·주간요약·설정 안쪽·기다림 표시처럼 어제 목록에 없던 곳이 들어온다. 둘째, 맨 앞에 묶음 0(시험·지도·고르기 표)이 생겨 빠짐을 사람이 아니라 시험이 잡는다. 셋째, 어제 계획에 없던 묶음 "기다림"과 "값 통일"이 생긴다. 어제 정한 원칙(세기 0~3, 토큰, transform·opacity만, 내 동작 뒤 0.5초, 안전장치 정의는 안 고침, View Transitions 안 씀)은 그대로다.

## 5. 반대 의견·위험

- **"전부"는 피로가 된다.** 종일 띄워 두는 도구에서 움직임이 4배로 늘면, 처음엔 좋아도 며칠 뒤 거슬릴 수 있다. 그래서 매번 하는 것(세기 1)은 넘침 0, 200ms 이하로 묶고, 쫀득(넘침)은 가끔 여는 것에만 둔다. 묶음 F에 "일주일 써 본 뒤 세기를 한 곳에서 내림"을 넣은 까닭이다 — 토큰으로 모아야 한 곳에서 내릴 수 있다.
- **통째로 다시 그리는 구조의 한계.** 줄 이동은 "그리기 앞뒤 자리를 재서 잇는" 방식이라 줄마다 열쇠가 있어야 하고, 잴 때마다 화면 계산이 든다. 목록 14개에 넓히면 재는 횟수가 는다. 상한(보이는 40줄, 전체 150줄)을 목록마다 지키고, 묶음 C에서 줄 200개로 먼저 잰다.
- **글자 입력 보호와의 충돌.** 입력 중에는 다시 그리기를 미루는 장치가 여러 벌 있다(오늘 탭의 보류, 회의·프로젝트의 보류, 주간요약의 글 보존, 설정의 폴링 건너뛰기). 움직임은 항상 이 장치 **뒤에** 서야 한다 — 미뤘다 푸는 그리기는 움직이지 않는다(이미 있는 규칙). 새 목록을 등록할 때마다 이 시험을 같이 넣는다.
- **CSS 새 기능에 기대는 부분.** 알림·창의 닫힘을 CSS만으로 주는 길과 접힌 설명의 내용 전환은 최근 브라우저 기능이다. 앱 창(크롬)에서는 될 것으로 보지만 **띄워서 확인하지 않았다(추정)**. 안 되는 환경에서는 지금처럼 즉시 닫힌다. 묶음 B·D의 첫 일은 이 확인이다 — 안 되면 "부르는 쪽에서 닫힘 재생 뒤 닫기"로 바꾸는데, 그러면 안전장치 정의를 건드리지 않는 선에서 창 3개의 닫기 함수를 고쳐야 해 B가 커진다.
- **접근성.** 움직임 줄이기 설정에서는 이동이 전부 꺼지고 120ms 흐려짐만 남아야 한다. 지금은 요소 이름을 하나씩 늘어놓는 방식이라 새 부품이 빠지기 쉽다 — 부품 클래스로 등록하게 바꾼다. 주간요약의 부드러운 스크롤 하나는 지금 줄이기 분기가 없다(126줄).
- **성능.** `transform`·`opacity`만 쓰는 원칙을 지키면 대부분 안전하다. 예외 둘(서랍의 본문 여백 전환, 진행 막대 폭)은 묶음 D에서 없앤다.

### 하지 않는 편이 나은 곳

| 곳 | 근거 |
|---|---|
| 검색 팔레트 결과 줄, 메뉴 항목의 가리킴 | 글자를 치는 중·화살표 연타 — 움직이면 느려진다(세기 0). 팔레트 자체도 지금보다 **줄인다** |

## 6. 사용자에게 물을 결정

1. **빠른 추가 뒤 새 줄을 움직일까?** 지금 오늘 할 일에 적고 Enter를 치면, 입력칸에 초점이 남아 있어 줄 이동 규칙이 꺼지므로 새 줄이 뚝 나타난다. 회의 정리의 같은 동작(Enter로 새 줄)은 140ms로 떠오른다 — 두 화면이 다르다. **추천: 회의와 같게 — 새 줄 "나타남"만 허용(다른 줄의 이동은 계속 끔).** 반대쪽 한 줄: 연달아 적을 때 줄이 매번 떠오르면 번잡할 수 있다.
2. **"전부"의 순서.** **추천: 0 → A → B → C 까지 먼저 내고 하루 이틀 써 본 뒤 D~F.** 체감이 가장 큰 것(누름·열고 닫힘·줄)이 앞 넷에 있다. 반대쪽 한 줄: 한 번에 다 내야 "일부만 적용" 느낌이 완전히 사라진다.

## 7. 발견했지만 안 건드린 것

- **버그 가능성**: 설정 › 연동의 20초 자동 다시 그리기가 "펼친 카드"만 보고 건너뛴다 — Claude 토큰 칸과 맨 아래 `요청하기` 칸은 카드 본문 밖이라, 거기 글을 치는 중에 화면이 다시 그려져 글이 날아갈 수 있다(코드로 확인, 실제 재현은 안 함).
- **버그 가능성**: 확인 대기의 `다음은?` 입력 줄을 연 채 목록이 다시 그려지면 입력 줄이 사라진다(목록에 입력 보호가 없음 — 추정).
- **구조**: 같은 일을 하는 코드가 두 벌 — 줄 이동(`uiRowsMove` ↔ 회의의 `meetingFlip`), 떠 있는 판 자리 잡기(`uiSchedPlace` ↔ `meetingTypePlace`). 묶음 B·C에서 합친다.
- **구조**: `fadeOutAndRun`은 이름과 달리 흐려짐이 없다(잠금만). 이름이 다음 사람을 헷갈리게 한다 — 정의는 안전장치라 그대로 두고 지도 문서에 적는다.
- **사용자 경험**: 지라 새로고침 버튼은 눌러도 돌지 않는다(헤더 새로고침과 다름). 업데이트 진행 ⟳은 2초마다 0도에서 다시 시작해 덜컥거린다. 맥 캘린더 확인은 최대 90초 동안 글자뿐이다.
- **사용자 경험**: 설정 창은 탭을 바꿀 때 창 높이가 뚝 바뀐다. 모션으로 풀 일이 아니라 창 높이를 고정할지의 화면 결정이다.
- **문서 어긋남**: DESIGN 모션 절은 `--spring-1`·`--spring-2`·`--t-press`를 "아직 쓰는 곳 없음"이라고 적는다 — 사실이다. 지금의 쫀득(일정 정하기 판·종류 목록)은 스프링 토큰이 아니라 손으로 적은 키프레임(.88 → 1.025 → 1)이다. 묶음 B에서 토큰으로 옮길지, 키프레임을 표준으로 삼을지 정해야 한다.
- **기회**: 알림이 148곳에서 불린다. 줄의 움직임이 결과를 알려 주게 되면(묶음 C) 옮기기 알림을 덜 수 있다 — 어제 명세의 원칙 6. 이번 계획에는 넣지 않았다(다음 버전).
