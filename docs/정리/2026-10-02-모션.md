# 앱 전체 모션 — 구현 명세 (단계 계획)

- **왜 만드나**: 지금은 목록이 바뀔 때 줄이 순간 이동하고, 닫힘은 전부 즉시이며, 결과를 알림 글자로만 알린다. 무엇이 어디로 갔는지 눈으로 따라갈 수 없다.
- **어떤 사용자 행동이 달라지길 기대하나**: 체크하거나 옮긴 뒤 알림 글을 읽지 않고도 줄의 움직임으로 결과를 안다. 판과 카드가 누른 곳에서 열려 "어느 것을 눌렀는지" 다시 찾지 않는다.
- **무엇을 보면 성공인가**: ① 정렬·옮기기·완료에서 줄이 미끄러져 자리 잡는다 ② 자동 갱신과 글자 입력 중에는 아무것도 움직이지 않는다 ③ 일주일 써 본 뒤에도 사용자가 "거슬린다"고 하지 않는다 ④ 긴 목록에서도 끊기지 않는다.

제안 전문(확정 2026-10-02, 사용자 "전부 동의"): `design/모션-제안/index.html` — 순간별 표 15개, 토큰 표, 움직이면 안 되는 곳, 눌러 보는 데모. 이 문서는 그 요약과 묶음 경계다.

## 원칙

1. 움직임은 "어디서 와서 어디로 갔는지"를 보여 주는 데만 쓴다.
2. 쫀득함(넘침)의 세기는 그 동작을 하루에 몇 번 하느냐로 정한다.

| 세기 | 어디 | 값 |
|---|---|---|
| 0 | 키보드로 연달아 하는 동작, 자동 갱신, 글자 입력 중 | 움직임 없음(나타남 0~80ms만) |
| 1 | 매번 하는 것 — 체크, 옮기기, 누름 | 넘침 0~0.5%, 100~200ms |
| 2 | 가끔 여는 것 — 메뉴, 판, 상세 카드, 서랍 | 넘침 0.5~2.5%, 등장 200~240ms, 퇴장 100~140ms |
| 3 | 드문 순간 — 오늘 다 끝냄 등 | 넘침 3~5%, 320~480ms |

3. 시작점은 누른 곳. 퇴장은 등장보다 짧게.
4. transform·opacity만 움직인다(레이아웃 속성 금지).
5. 맥의 "동작 줄이기"에서는 이동을 끄고 120ms 흐려짐만 남긴다.
6. 목적지가 화면에 보이면 옮기기 알림을 띄우지 않고 줄의 움직임으로 알린다. ⌘Z와 누르는 화면의 `되돌리기` 버튼은 그대로다.

토큰: 시간 4개(100·140·200·320ms) + 곡선 3개(`--ease` 그대로 + 스프링 근사 `linear()` 2개) — 값은 제안 페이지 표.

## 예외 상황·지키는 선

| 상황 | 동작 |
|---|---|
| 글자 입력 중·한글 조합 중 | 그 구역은 다시 그리지도, 움직이지도 않는다(기존 보류 장치가 먼저) |
| 자동 갱신으로 바뀐 순서·숫자 | 움직이지 않는다(내 동작 직후 0.5초 안의 변화만 움직인다) |
| 안전장치 함수(`showNotice`·`fadeOutAndRun` 등) | 정의를 고치지 않는다 — 부르는 쪽과 CSS에서 푼다 |
| 애니메이션 끝남 신호가 안 옴(탭이 가려짐 등) | 시간으로 정리해 유령 줄이 남지 않는다 |
| 긴 목록 | 보이는 줄만, 40줄 넘으면 움직임 없이 그린다 |
| `linear()`를 모르는 환경 | `--ease`로 떨어진다 |
| View Transitions API | 쓰지 않는다(화면을 찍는 동안 입력이 멈춘다) |
| 서랍의 `padding-right`, 진행 막대의 `width` 애니메이션 | ③에서 transform으로 바꾼다 |

성능 예산: 60fps. 재는 법은 가짜 데이터에 줄 200개를 넣고 크롬 Performance 녹화(CPU 4배 느리게).
