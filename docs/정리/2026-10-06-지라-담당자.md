# 지라 티켓 담당자 바꾸기 — 명세 초안

- **왜 만드나**: 새 프로젝트(`+`)로 에픽과 직군별 하위 티켓을 만들면 하위 티켓은 `담당 없음`으로 생긴다. 팀원에게 나눠 주려면 지금은 지라를 열어 티켓마다 따로 지정해야 한다.
- **어떤 사용자 행동이 달라지길 기대하나**: 프로젝트 탭의 띠 카드·하위 티켓 줄에서 `담당 없음`/`담당 ○○`을 눌러 이름으로 찾아 맡긴다 — 지라를 열지 않고.
- **무엇을 보면 성공인가**: ① 새 프로젝트를 만든 뒤 하위 티켓 담당 지정을 앱 안에서 끝낸다(사용 횟수 `jira_assign`이 `jira_create`를 따라 늘어난다) ② 잘못 맡긴 경우가 알림 `되돌리기`로 바로 풀린다 ③ 다른 사람이 바꾼 담당자를 덮어쓴 일이 0건이다.

> 배경(조율 추정 — **가정**): 새 프로젝트로 에픽·직군별 하위 티켓을 만든 뒤 팀원에게 나눠 주는 데 쓴다. 실제 사용 빈도는 아직 모른다.

시안: `design/지라-담당자-시안/index.html`(+ `captures/`). 데이터는 전부 가짜(테스터A~D).

## 동작

1. **누르는 자리**: 띠 카드 첫 줄 `종류 · 담당 ○○`의 `담당 ○○` 부분, 하위 티켓 줄의 담당 칸(`담당 없음`/이름). 둘 다 값 고르개(`.d-dpick` — 글자 + 작은 꺾쇠, hover `--hover`, 28px, `aria-haspopup="listbox"`)가 된다. 지라 연결이 없거나 `integrations.jira`가 꺼져 있으면 지금처럼 글자일 뿐이다.
2. **고르개**: 누르면 그 자리에 더보기 메뉴(`.d-menulist`) 안에 공용 고르개 `uiPickList`(찾기 칸 늘 켬, 안내글 `이름으로 찾기 — 두 글자부터`)가 뜬다.
   - 찾기 전: 소제목 `최근 고른 사람`(최대 5명) → 맨 아래 `담당 빼기`(지금 담당이 있을 때만, `.is-act`). 지금 담당자는 `--sel` 바탕(`aria-selected`).
   - 두 글자 이상 치면 250ms 쉬었다가 서버에 묻는다(그 사이 친 글자로 늦게 온 응답은 버린다). 묻는 동안 목록 자리에 `찾는 중…`(`role=status`). 결과는 소제목 `지라 사용자`, 최대 10명, 내 줄은 오른쪽 조용한 `나`.
   - 한 글자일 때는 최근 목록만 거른다(서버에 묻지 않는다).
3. **확인**: 고르면 고르개가 닫히고 띠 카드 안 **기존 지라 확인 줄**(`.d-jconfirm`)이 선다 — `지라의 이 티켓을 바꿀까요?` / 요약 + 조용한 키 / `담당: ~~없음~~ → 테스터B` / `[취소] [맡기기]`. `담당 빼기`면 `→ 없음`, 버튼 `빼기`.
   - 내가 맡고 있던 **띠 카드 티켓(에픽)** 을 남에게 넘길 때만 경고 한 줄(`--warn`): `내 담당에서 빠져요 — 왼쪽 목록에서 사라질 수 있어요.`(왼쪽 목록은 내 담당 지라 목록에서 오므로. 연결된 항목이 있으면 남는지 구현 때 확인)
4. **저장**: `맡기기` → `보내는 중…`, 세 값 고르개·새로고침·담당 고르개가 잠긴다. 지라가 받아 주면 카드를 `fresh`로 다시 읽어 담당 표시를 갱신하고(하위 줄 포함, 접힌 줄의 담당별 개수도), 알림 `테스터B에게 맡겼어요` + 3차 `되돌리기`(8초).
   - 실패는 전부 확인 줄을 닫고 **오류 알림**으로 말한다(기존 `jiraConfirmRow` 실패 처리와 같다).
   - **화면을 먼저 바꾸지 않는다**(지라가 받아 준 뒤에만 새 값) — 실패해도 원복할 것이 없다. 지라의 다른 쓰기와 같다.
5. **되돌리기**: 알림의 `되돌리기` = 직전 담당자로 다시 지정(원래 `담당 없음`이면 담당 해제). 한 번만, 서버 메모리의 되돌리기 표(10분)로. 확인 줄은 다시 띄우지 않는다(방금 한 일을 되돌리는 것이라). 되돌린 뒤 알림 `되돌렸어요 · 담당 없음`.
6. **사용 횟수**: `jira_assign`(맡기기·빼기가 지라에 반영된 횟수), `jira_assign_undo`(되돌리기 성공 횟수). 숫자만 센다 — 이름·키·accountId는 싣지 않는다. `기능별 전체 보기`의 `지라` 줄에 `만들기 N · 담당 N`.

## 결정 — 추천과 반대 의견

① **확인 단계: 기존 확인 줄을 거친다(추천).** 지라는 담당이 바뀌면 그 사람에게 메일·알림을 보낸다 — 되돌려도 이미 간 알림은 못 거둔다. 또 지라 쓰기는 전부 확인 줄을 거친다는 규칙(2026-09-22)과 같다.
  반대 의견: 이름으로 찾아 고르는 것 자체가 신중한 동작이고, 하위 티켓 6개를 나눠 줄 때 클릭이 6번 더 든다 — 고르기 = 확인 + 되돌리기만으로 충분할 수 있다.

② **되돌리기: 알림의 `되돌리기`만, ⌘Z는 안 쓴다(추천).** 지라 쓰기는 ⌘Z 대상이 아니라는 결정(2026-09-22)과 연결 해제·에픽 옮기기의 태도가 같고, ⌘Z가 앱 업무와 지라를 섞어 되돌리면 순서가 헷갈린다. 요청서에는 ⌘Z도 있었으나 이 결정과 부딪혀 뺐다.
  반대 의견: 알림이 8초 뒤 사라지면 되돌릴 길이 없다 — ⌘Z가 있으면 늦게 알아차려도 된다(대신 DECISIONS 줄을 바꿔야 한다).

③ **최근 고른 사람: 보여 준다(추천).** 최대 5명, 이 브라우저 `localStorage`에만(`jiraAssignRecent`, 값은 `{ name, accountId }` 배열 — 시각·티켓은 안 남김). 같은 팀원 몇 명에게 반복해 나눠 주는 쓰임이라 검색 없이 한 번에 고른다. 맡기기가 지라에 반영됐을 때만 맨 앞에 넣고, 여섯 번째부터는 오래된 순으로 밀려난다(지우는 버튼은 따로 두지 않는다 — 표시 최소). 저장소를 못 쓰는 창(사생활 보호 등)이면 최근 목록 없이 검색만.
  반대 의견: accountId가 브라우저 저장소에 남는다(지금은 어디에도 안 남김) — 이름만 남기고 고를 때 다시 검색하는 방법도 있다(한 번 더 기다림).

## 지라 API (jira-client.js 방식 그대로 — 8초 끊기, 토큰은 부를 때마다 파일에서, 지라 원문은 화면에 싣지 않음)

| 하는 일 | 지라 API | 받는 칸 |
|---|---|---|
| 사람 찾기 | `GET /rest/api/3/user/assignable/search?issueKey=KEY&query=<친 글자>&maxResults=20` — **그 티켓에 맡길 수 있는 사람만** 준다(프로젝트 권한 반영). 친 글자는 주소에 실리지만 사람이 친 이름일 뿐이다 | 지라는 이메일·아바타·시간대까지 주지만 **`accountId`·`displayName`·`active`·`accountType`만 꺼낸다**. `accountType !== 'atlassian'`(앱·봇)과 `active === false`는 버린다 |
| 지금 담당 다시 읽기 | `GET /rest/api/3/issue/KEY?fields=assignee` | `accountId`·`displayName`(서버 메모리에서만 비교, 응답에는 이름만) |
| 맡기기 / 빼기 | `PUT /rest/api/3/issue/KEY/assignee` 본문 `{ accountId }` / `{ accountId: null }` — accountId는 **본문에만**(기존 `assignIssue` 주석과 같다). `-1`(자동 배정)은 쓰지 않는다 | 204 |
| 같은 이름 구분(같은 이름이 둘 이상일 때만) | `POST /rest/api/3/search/jql` 본문 `{ jql: "assignee = <id> ORDER BY updated DESC", fields:["summary"], maxResults:1 }` — 사람마다 1번, 최대 3명. 본문이라 accountId가 주소에 안 실린다 | `summary` 하나 |

앱 서버 길(새 것 하나 + 기존 하나 넓힘):
- `GET /api/jira/assignable?key=KEY&q=글자` → `{ ok, users:[{ accountId, name, me?, hint? }] }`. 두 글자 미만은 400.
- `POST /api/jira/change` `{ key, kind:'assignee', to: accountId|null, expect: '테스터A'|null }` → `{ ok, assignee:'테스터B'|null, undoId }`. `{ kind:'assigneeUndo', undoId }` → `{ ok, assignee }`. 기존 `CHANGE_KINDS`에 둘을 더한다(옛 서버는 `value`로 거절 — 아래 옛 설치).

서버가 쓰기 전에 하는 일(순서대로, 하나라도 어긋나면 쓰지 않고 멈춤):
1. 지금 담당을 다시 읽어 **화면이 본 이름(`expect`)과 같은지** 본다(둘 다 없음도 같음). 다르면 `stale` + 지금 이름. 이름으로 비교하는 이유: 띠·하위 응답에 accountId를 싣지 않는 원칙(테스트로 고정)을 지키려고. 같은 이름인 다른 사람으로 바뀐 경우는 못 잡는다(드묾, 덮어써도 같은 이름).
2. `to`가 있으면 그 사람이 이 티켓에 맡길 수 있는지 다시 본다 — `assignable/search?issueKey=KEY&query=<그 사람 표시 이름>` 결과에 그 accountId가 있는지(주소에 accountId를 싣지 않으려고 이름으로 찾고 id로 대조). 없으면 `notAssignable`.
3. 지금 담당과 `to`가 같으면 쓰지 않고 `{ ok:true, same:true }`(알림 `이미 테스터B가 맡고 있어요`).
4. PUT. 성공하면 되돌리기 표(메모리, 10분, 한 번 쓰면 지움)에 `{ key, before: id|null, beforeName, after: id|null }`을 두고 `undoId`만 돌려준다.
5. 되돌리기도 1번과 같은 대조를 **accountId로**(서버가 둘 다 알므로) 한 뒤 PUT.

## accountId가 지나가는 범위 (이 밖으로는 안 나간다 — 테스트로 고정)

- `GET /api/jira/assignable` 응답(고르개가 쓸 값) · `POST /api/jira/change` 요청 본문 · 이 브라우저 `localStorage`의 최근 고른 사람.
- 나가지 않는 곳: 띠·하위 응답(지금 그대로), 지라·앱 서버로 가는 **주소**(querystring), 오류 문구, `tracker/`의 업무 파일·`.workflow.json`, 사용 횟수, 로그. 서버는 이 일로 **아무것도 기록하지 않는다**(jira-client의 "아무것도 기록하지 않는다" 그대로). 이메일·아바타·시간대는 받자마자 버린다.

## 예외 상황

| 상황 | 동작(문구) |
|---|---|
| 검색 결과 0명 | `이 티켓을 맡을 수 있는 사람 중에 '테스' 이름이 없어요`(13 `--dim`, `role=status`). 최근 목록·`담당 빼기`는 그대로 |
| 같은 이름 여러 명 | 이메일 없이 **그 사람이 최근 맡은 티켓 요약 한 줄**로 구분: 이름 오른쪽 조용한 글자 `최근 · 결제 리뉴얼 디자인`(말줄임, title 전체). 못 읽으면 `같은 이름 2명 중 1`·`2`. 최근 목록에 있는 쪽은 `최근 고름` |
| 비활성 사용자 | 검색 결과에서 뺀다. 지금 담당이 비활성이면 표시는 지라가 준 이름 그대로, 고르개 맨 위에 조용한 한 줄 `지금 담당자는 지라에서 비활성이에요` |
| 권한 없음(지라 403) | 확인 줄을 닫고 오류 알림(기존 지라 쓰기 실패와 같은 자리 — 빨간 테두리, 스스로 안 사라짐): `지라에서 이 티켓의 담당을 바꿀 권한이 없어요.` + `지라에서 열기`. 값은 그대로 |
| 맡길 수 없는 사람(최근 목록의 다른 프로젝트 사람 등) | `테스터B는 이 티켓을 맡을 수 없어요(지라 권한). 다른 사람을 골라 주세요.` |
| 그 사이 다른 사람이 바꿈(충돌) | 쓰지 않음. 카드를 새로 읽고 `그 사이 지라에서 담당이 테스터C로 바뀌었어요. 확인하고 다시 골라 주세요.` |
| 네트워크 끊김·지라 느림(8초) | 검색: 목록 자리에 `지라에 연결하지 못했어요 · 다시 시도`. 맡기기: 반영됐는지 모르므로 **카드를 새로 읽어** 실제 값을 보이고 `지라에 반영됐는지 확인하지 못했어요 — 카드를 새로 읽었어요.` |
| 지라 연결 안 됨 | 담당 글자가 고르개가 아니다(지금처럼 글자). 띠 카드 자체가 `지라 연결이 필요해요` 한 줄이라 누를 자리도 없다 |
| 토큰 만료(401) | `지라 토큰을 확인해 주세요.` + `설정 열기`. 기존 쓰기 표(`writeKind`)는 401·403을 합쳐 `권한이 없어요`로 말하므로, 담당 바꾸기만은 401을 `auth`로 가른다 |
| 하위 티켓이 다른 지라 프로젝트 소속 | 검색을 티켓 키마다(`issueKey`) 하므로 그 티켓의 프로젝트 권한대로 나온다. 따로 할 일 없음 |
| 내가 나를 고름 | 그대로 맡긴다(줄 오른쪽 `나`). 하위 티켓을 나에게 맡기면 내 담당 지라 목록에 들어온다 — 왼쪽 프로젝트 목록에 하위 티켓이 따로 서는지 구현 때 확인 |
| 이미 그 사람이 담당 | 지라에 쓰지 않고 `이미 테스터B가 맡고 있어요` |
| 되돌리기 중 실패 | 오류 알림(빨간 테두리, 안 사라짐): `되돌리지 못했어요 — 담당은 테스터B 그대로예요.` + `지라에서 열기 ↗`. 충돌이면 `그 사이 지라에서 다시 바뀌어 되돌리지 않았어요.` 되돌리기 표가 사라졌으면(10분·서버 재시작) `되돌릴 수 있는 시간이 지났어요.` |
| 띠 카드 하위 목록이 옛 길(`subtasks`)로 와서 담당이 비어 보임 | 실제 담당이 있으면 1번 대조가 `stale`로 막고 카드를 새로 읽는다(덮어쓰지 않음) |
| 확인 줄이 열린 채 다른 프로젝트로 옮김·새로고침 | 확인 줄은 닫히고 아무것도 보내지 않는다(기존 확인 줄과 같다) |
| 연타·두 번 누름 | 보내는 동안 잠금. 서버도 같은 `key+to`가 3초 안에 두 번 오면 두 번째는 `same`으로 끝난다(1번 대조가 막음) |
| 옛 설치(이 기능 없는 앱) | 옛 앱에는 고르개가 없어 아무 일도 없다. 데이터 형식은 안 바뀐다. 화면 파일만 새것이고 서버가 아직 옛것인 잠깐(재시작 전)에는 검색이 404·맡기기가 `value`로 거절된다 → 고르개 자리에 `앱을 다시 시작하면 쓸 수 있어요` 한 줄(지라에는 아무것도 안 감) |
| 써 보기 서버·브라우저 픽스처 | 가짜 지라만(테스터A~D). 실제 지라 주소를 가리키면 지금처럼 시작하지 않는다 |

## 안전장치

- 지라 쓰기는 **앱 서버만**(토큰은 서버만 읽는다). 화면은 지라를 부르지 않는다.
- **요청 하나 = 티켓 하나의 담당자 한 명 변경.** 여러 키·여러 사람을 받는 모양을 만들지 않는다(`key`는 문자열 하나, `to`는 id 하나 또는 null).
- 쓰기 직전 다시 읽어 대조(위 1·2번), 어긋나면 멈추고 알린다. 화면은 성공한 뒤에만 바뀐다.
- 로그·파일 기록 없음. 사용 횟수는 숫자만.
- 시험이 고정할 것: 띠·하위 응답에 accountId·이메일 없음(기존 시험 그대로) / 검색 응답에 이메일·아바타 없음 / 지라로 가는 주소에 accountId 없음 / 대조 실패 시 PUT 0번 / 요청 하나에 PUT 1번 / 401·403 문구 갈림 / 되돌리기 한 번만.

## 하지 않는 것

- 지라 티켓 만들기·상태 바꾸기(이미 있는 길 그대로), 하위 티켓의 상태·요약·버전 바꾸기.
- 여러 티켓 한 번에 담당 바꾸기(다음 버전 후보 — 새 프로젝트 만들기 결과 화면에서 직군별로 한 번에 나눠 주기).
- 앱 업무의 담당자 칸(업무에는 담당 칸이 없다).
- ⌘Z(결정 ② 추천대로라면).
- 지라 프로필 사진·이메일 보여 주기.

## 바뀌는 파일(구현 뒤 실제)

- `jira-client.js`: `searchAssignable(key, query)`, `getAssignee(key)`, `assignIssue`가 `null`(빼기)도 받게, `latestSummaryOf`(같은 이름 구분), `assignable`, `change`에 `assignee`·`assigneeUndo`, 되돌리기 표·3초 기억·티켓별 처리 중 표시(메모리), 401 갈림·쓰는 중 5xx는 `assignUnsure`. 띠·하위 응답에는 지금 담당이 비활성일 때만 `assigneeInactive: true`(계정 id 없음).
- `routes-jira.js`: `GET /api/jira/assignable`.
- `jira-ui.js`: 띠 `담당 ○○`·하위 줄 담당 칸을 값 고르개로, 확인 줄 문구·경고, 알림·되돌리기, 최근 고른 사람(`localStorage`, try/catch).
- `app.js`: `uiPickList`에 **찾는 말이 바뀔 때 부르는 갈래**(`onQuery` → 목록 바꾸기, `찾는 중…`) — 지금은 받은 목록을 화면에서 거르기만 한다. 다른 고르개 동작은 그대로.
- `ui.css`: 하위 줄 담당 칸 버튼(96px 칸 안 `.d-dpick`), 고르개 줄의 조용한 구분 글자 말줄임 — 새 색·새 부품 없음.
- `usage.js`·`usage-ui.js`(아는 키 목록): `jira_assign`·`jira_assign_undo` — `기능별 전체 보기`에는 `지라 담당 바꾸기`·`지라 담당 되돌리기` 두 줄로 따로 선다(표가 기능마다 한 줄이라 `지라` 한 줄로 합치지 않았다).
- `server.js`: 지라 요청을 가짜로 끼우는 `setJiraFetchForTests`(픽스처 전용).
- `browser-fixture.js` + 새 `jira-fixture.js`: `WORKSPACE_FIXTURE_JIRA=1`이면 가짜 지라(검색·담당 바꾸기). 맡기기 요청 본문에는 `toName`(고른 사람 표시 이름)이 더 실린다 — 서버가 이름으로 찾아 id로 대조하려고. **`tryout-server.js`는 바꾸지 않았다** — 써 보기는 지라를 일부러 꺼 두고 시험(tryout.test.js)이 그것을 고정하므로, 켤지는 따로 정한다.
- 시험: `server.jira.test.js`(위 고정 목록), `usage.test.js`(사용 횟수), `client.test.js`(고르개·확인 줄·되돌리기).
- 문서: README 프로젝트 탭 지라 절(띠 첫 줄 설명 + `하위 티켓 보기` 절의 "보기만 합니다" → "담당자만 바꿀 수 있습니다"), DESIGN.md 지라 띠 카드·하위 티켓·확인 줄 행, DECISIONS.md(위 표의 세 줄 뒤에 새 줄 하나), `docs/지도/프로젝트.md`.
