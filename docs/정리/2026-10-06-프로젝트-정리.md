# 프로젝트 정리 — 같은 이름 감지 · 합치기 · 지우기 (명세)

- **왜 만드나**: 같은 일이 이름만 조금 다른 프로젝트 둘로 갈라져도 지금은 합칠 길이 없고(이름 바꾸기는 겹치는 이름을 거절), `+`로 만들 때 기존 지라 에픽과 같은 이름인지 몰라 지라에 같은 이름 에픽이 하나 더 생긴다.
- **달라질 행동**: 사람이 갈라진 프로젝트를 ⋯ 한 번으로 합치거나 지우고, 새로 만들기 전에 "이미 있는 ○○ 열기"로 가게 된다. 손으로 항목을 하나씩 옮기는 일이 없어진다.
- **성공의 모습**: 같은 이름(대소문자·공백·밑줄만 다른 이름 포함) 프로젝트가 목록에 둘 서는 일이 새로 생기지 않는다. 합치기·지우기 뒤 ⌘Z 한 번이면 그 전과 같은 화면이다.

> 안전장치에 닿는다: 한 요청이 업무 파일 넷(`tasks.md`·`checks.md`·`decisions.md`·`ideas.md`)·`.workflow.json`(회의 프로젝트·지라 연결·기록)·`.meeting_links.json`·`.report-drafts.json`을 한 번에 쓴다. **구현은 무거운 모델, 합치기 전 Codex 검토(읽기 전용)** 를 받는다.

이름과 지라 번호는 모두 가짜다(`결제 리뉴얼`, `PAY-12` 등).

## 1. 정해진 것 (사용자 결정 2026-10-06)

1. **만들기 전 감지 확대** — 새 프로젝트 화면이 직접 만든 프로젝트 이름만이 아니라 **지라 에픽 요약·별칭**과도 견준다. 비교 규칙은 공용 `uiPickByName`·서버 `findProject`와 같다(밑줄→공백·연속 공백 하나·대소문자 무시, 순서: 직접 만든 이름 → 별칭 → 지라 요약·`KEY · 요약`).
2. **⋯ › `다른 프로젝트로 합치기…`** — 직접 만든 프로젝트를 다른 직접 만든 프로젝트나 지라 에픽으로 합친다. 한 번의 ⌘Z·알림 `되돌리기`로 원복.
3. **⋯ › `프로젝트 지우기`** — 직접 만든 프로젝트만. 그 프로젝트의 항목을 `프로젝트 없음`으로 돌린다(그 순간 프로젝트는 사라진다). 확인창 없이 실행, 알림 `되돌리기`·⌘Z로 되돌림. 항목 자체는 휴지통으로 가지 않는다.

### 감지: 막기 vs 경고 — 추천은 **막기**

- 이름이 **지라 프로젝트(에픽 요약·별칭)** 와 같으면 `새 에픽 만들기`·`지라 없이` 모두 **만들기 버튼을 막고** `이미 있는 ○○ 열기`만 준다. 지라에 만드는 일은 되돌릴 수 없어서 경고만으로는 실수가 남는다. 화면은 서버가 받은 이름을 프로젝트 하나로 다루므로(같은 이름 = 같은 프로젝트) 둘이 생기면 어차피 앱 안에서 구분할 수 없다.
- 이름이 **직접 만든 프로젝트**와 같으면 막지 않는다(지금처럼 "만든 뒤 옮기기"를 안내한다).
- **반대 의견 한 줄**: 다른 팀 보드에 일부러 같은 이름 에픽을 두는 경우 앱에서 만들 수 없다. 이때는 이름에 팀 표기를 붙이거나 지라에서 직접 만들면 된다. 막힘을 푸는 버튼은 두지 않는다.

## 2. 화면

### 2-1. 새 프로젝트 화면(`+`)의 감지 줄

이름 칸 아래 감지 줄(`.d-pnewmove`) 하나가 상황에 따라 바뀐다. 비교할 이름은 지금과 같다(`있는 에픽에 붙이기`는 고른 에픽의 요약).

| 모드 | 같은 이름 | 감지 줄 | 주 버튼 |
|---|---|---|---|
| 새 에픽 만들기 | 직접 만든 프로젝트 | 지금 그대로: `결제 리뉴얼 프로젝트가 이미 있어요(항목 12) · ☑ 만든 뒤 이 에픽으로 옮기기` | 그대로 |
| 새 에픽 만들기 | 지라 프로젝트 | `결제 리뉴얼은 이미 지라에 있어요(PAY-12) · 열기` | 막힘. 아래 이유 줄 `같은 이름의 지라 프로젝트가 있어요 — 이름을 바꾸거나 '있는 에픽에 붙이기'로 붙여 주세요.` |
| 있는 에픽에 붙이기 | 직접 만든 프로젝트 | 지금 그대로(옮기기 체크) | 그대로 |
| 지라 없이 | 직접 만든 프로젝트 | `결제 리뉴얼 프로젝트가 이미 있어요(항목 12) — 첫 할 일이 거기에 들어가요 · 열기` (**체크 없음** — 지금 뜨는 `만든 뒤 이 에픽으로 옮기기`는 틀린 안내라 뺀다) | `결제 리뉴얼에 넣기` |
| 지라 없이 | 지라 프로젝트 | `결제 리뉴얼은 이미 지라에 있어요(PAY-12) · 열기` | 막힘. 이유 줄 `같은 이름의 지라 프로젝트가 있어요 — 이름을 바꿔 주세요.` |

- `열기`는 조용한 글자 버튼. 누르면 새 프로젝트 화면을 닫고(`projectNewLeave`) 그 프로젝트를 연다(`openProjectTab`). 지난 프로젝트면 그 구역이 펼쳐진다(기존 규칙).
- 감지에 쓰는 목록은 화면이 이미 가진 값만이다(`customGroupsCache`·`projectAliasesCache`·`jiraIssuesCache`). 내 목록에 없는 남의 에픽은 감지하지 못한다 — 그 한계는 서버 막기(3-3)도 같다.
- **밑줄 고치기**: 새 에픽 제목·하위 티켓 제목(`접두어 + 공백 + 이름`)·`지라 없이`의 그룹 이름에 보내는 이름은 `_`를 공백으로 바꾸고 연속 공백을 하나로 줄인 값이다(서버 `renameProject`의 `to`와 같은 규칙). 미리 보기도 바뀐 값을 보여 준다. 이름 칸 예시 `가입 개선_이메일 인증`에서 밑줄을 뺀다.

### 2-2. 프로젝트 제목 ⋯ 메뉴

직접 만든 프로젝트만 바뀐다. 지라 프로젝트의 ⋯은 그대로다(`이름 바꾸기`·`지라 이름으로 되돌리기`·묶기).

```
이름 바꾸기
다른 프로젝트로 합치기…
─────────
프로젝트 지우기          (빨간 글자 — DESIGN.md '삭제' 부품)
```

### 2-3. 합치기 대상 고르개

- 공용 프로젝트 고르개를 그대로 쓴다: `projectPickEntries` + `uiPickList`(찾기 칸은 프로젝트가 `PROJECT_FIND_MIN`개 이상일 때만, 묶음은 묶음 한 줄 + 들여쓴 티켓, 끝에 `지난 프로젝트` 소제목). ⋯ 자리에 이어서 연다(묶기 고르기와 같은 자리).
- 목록 머리 글자: `합칠 곳 고르기 · 항목 12`(조사가 필요 없는 문장 — 이름 끝 받침을 알 수 없어서, 묶기 확인 줄과 같은 이유).
- 빼는 것: 자기 자신, `__clear__`(프로젝트 없음)·`__custom__`(직접 입력) 동작 줄. 지라를 쓰지 않는 설치(`USES.jira` 꺼짐)나 지라가 연결되지 않았으면 지라 프로젝트를 빼고 직접 만든 프로젝트만 보인다.
- 고르면 **바로 실행**한다(확인 줄 없음 — 고르는 동작이 이미 의도이고 ⌘Z로 되돌린다. DESIGN.md "확인창을 되살리지 않는다").
- 합칠 수 있는 곳이 하나도 없으면 `합칠 수 있는 프로젝트가 없어요` 한 줄(누를 수 없음).

### 2-4. 알림 문구 (해요체, 되돌리기 버튼은 `되돌리기`)

| 때 | 문구 |
|---|---|
| 합침(직접 만든 프로젝트로) | `가입 개편으로 합쳤어요 · 항목 12` |
| 합침(지라 에픽으로) | `PAY-12로 합쳤어요 · 항목 12` (지금 옮기기 알림과 같은 꼴) |
| 지움 | `결제 리뉴얼 프로젝트를 지웠어요 · 항목 12는 프로젝트 없음으로` |
| 되돌림 | `결제 리뉴얼 프로젝트로 되돌렸어요` + (건너뛴 게 있으면) ` · 그 사이 바뀐 3개는 그대로 두었어요` |
| 되돌릴 기록이 없음 | `되돌릴 기록이 없어요` (서버 메시지 그대로) |
| 이름 바꾸기가 겹침으로 거절 | `같은 이름의 프로젝트가 이미 있어요 — 합치려면 ⋯ › 다른 프로젝트로 합치기를 써요` |

- 합친 뒤에는 **대상 프로젝트**를 연 채로 다시 그린다(옮기기와 같은 순서: `load()` → `openProjectTab`). 지운 뒤에는 목록 첫 프로젝트(지금 프로젝트가 사라졌을 때의 기존 동작)를 연다.
- ⌘Z(앱의 `pushUndo`)와 알림 `되돌리기`는 같은 기록을 쓴다. 다시 하기(⇧⌘Z)는 같은 합치기·지우기를 새 요청으로 한 번 더 보낸다(서버가 다시 검사한다).

## 3. 서버 동작

### 3-1. 새 동작 하나 + 그 되돌리기

`workflowActions`에 둘을 더한다(`idempotent → mutations.run` 한 트랜잭션, 하나라도 실패하면 저널이 전부 되돌림 — **한 요청 = 한 저장 = 되돌리기 하나**). 쓰기는 지금 `renameProject`·`moveProject`가 쓰는 길만 쓴다.

- `POST /api/project/merge` `{ project: 'group:결제 리뉴얼', to: 'group:가입 개편' | null }`
  - `to`가 `group:…`이면 **합치기**, `null`이면 **지우기**(프로젝트 없음으로 합치기와 같은 뜻).
  - `to`가 `jira:…`이면 거절 `지라 에픽으로 합칠 때는 옮기기를 써요` — 화면은 지라 대상일 때 **기존 `/api/project/move` 그대로** 부른다(에픽 검사가 그 라우트에 있다).
  - 응답 `{ ok, project, from, to, mergeId, changed: { items, meetings, links, report } }`.
- `POST /api/project/merge-undo` `{ mergeId }` — 기록에 남은 id만 되돌린다. 응답 `{ ok, project, restored: {...}, skipped }`.
- 기록은 `.workflow.json`의 **새 칸 `projectMerges`**(최근 20개, 화면에 내려보내지 않음, 한 번 되돌리면 지움). 기존 `projectMoves`와 **섞지 않는다** — 옛 앱의 `move-undo`가 합치기 기록을 옮기기로 잘못 되돌리는 일을 막으려고.

### 3-2. 무엇을 바꾸나 (자리 여섯 — `renameProject`의 ①~⑥ 그대로)

| 자리 | 합치기 (A → B) | 지우기 (A → 없음) |
|---|---|---|
| ① 업무 파일 `group:`·`project:`(아이디어) — 끝낸 항목 포함, 지라 걸린 줄은 건너뜀 | 값을 B로. 바꾼 줄 id 기록 | 칸을 지움. 바꾼 줄 id 기록 |
| ② `.workflow.json` 회의 프로젝트(`type: 'group'`) | B로. 회의 id 기록 | `project` 비움. 회의 id + 옛 값 기록 |
| ③ `projectLinks`(수동 지라 연결) | A만 있으면 B로 옮김. 둘 다 있으면 **B 것을 남기고** A 것은 기록만 하고 지움 | A 것을 지우고 기록 |
| ④ `projectArchive`(옛 기록, 읽는 화면 없음) | `renameGroup`처럼 열쇠만 B로 | 그대로 둠 |
| ⑤ `.meeting_links.json` `group:A` 값 | `group:B`로. 제목 기록 | 그 줄을 지우고 제목·옛 값 기록(남기면 다음 정기 회의가 A를 되살린다) |
| ⑥ `.report-drafts.json` | `renameGroup`과 같은 자리(소제목·묶음 열쇠·근거 이름표, 모든 주)를 B로. 행 id·옮긴 소제목 이름 열쇠 기록 | **건드리지 않는다**(아래 예외 9) |

- 지라에는 아무것도 묻지도 쓰지도 않는다.
- 겹침 검사(`projectNamesTaken`)는 쓰지 않는다 — 합치기는 이미 있는 이름으로 가는 것이 목적이다.
- `moveProject`(지라 에픽 대상)는 **코드 그대로** 재사용한다. 바뀌는 것은 화면이 그 결과를 ⌘Z에도 올리는 것뿐이다(3-4).

### 3-3. 만들기 전 감지의 서버 막기

`POST /api/jira/create`에서 **새 에픽**(`plan.epic.summary`)을 만들 때 `findProject(summary)`가 `jira:`를 돌려주면 아무것도 만들지 않고 409 `같은 이름의 지라 프로젝트가 이미 있어요.`로 거절한다(`group:`이면 통과 — 만든 뒤 옮기기 흐름). 지라에 만드는 일은 되돌릴 수 없어서 화면 막기 하나로 끝내지 않는다. 요약에 쓰는 이름의 밑줄→공백 정리도 서버에서 한 번 더 한다. `지라 없이`(`/api/later-task/create`)는 서버를 바꾸지 않는다(앱 안 일이라 ⌘Z·삭제로 되돌릴 수 있다).

### 3-4. ⌘Z

- 합치기·지우기는 ⌘Z 대상이다. `undo` = `merge-undo`(또는 지라 대상이면 기존 `move-undo`), `redo` = 같은 요청을 다시.
- 지라 프로젝트 띠 카드에서 하는 기존 옮기기(`wfProjectMoveFinish`)도 같은 기록으로 ⌘Z에 올린다 — 같은 동작이 자리에 따라 ⌘Z가 되고 안 되면 헷갈린다.
- ⌘Z 기록은 브라우저 메모리라 새로고침 뒤에는 없다(기존과 같다). 서버 기록은 남지만 화면이 다시 부를 길은 만들지 않는다.

## 4. 예외 상황

| # | 상황 | 동작 |
|---|---|---|
| 1 | 합칠 대상이 그 사이 사라짐(다른 창에서 지움·합침) | 서버가 `groupList()`에 B가 없으면 거절 `합칠 프로젝트를 찾을 수 없어요` → 화면은 `load()` 후 알림. 아무 파일도 안 바뀜 |
| 2 | 합칠 대상·원래 프로젝트의 이름이 그 사이 바뀜 | 원래 프로젝트가 없으면 `프로젝트를 찾을 수 없어요`, 대상이 없으면 1번. 이름을 추측해 따라가지 않는다 |
| 3 | 자기 자신으로 합치기 | 고르개에서 빠짐. 서버도 `groupNameKey`가 같으면 거절 `같은 프로젝트예요` |
| 4 | 이미 같은 이름(대소문자·공백·밑줄만 다른 둘, 예 `Pay Renewal` / `pay renewal`) | 바로 이 기능이 푸는 경우다 — 고르개에 둘 다 서고 합치기가 된다. 단 `uiPickByName`·`findProject`는 앞의 것 하나만 돌려주므로 직접 입력 칸은 계속 첫 번째로 간다(지금과 같음) |
| 5 | 회의 제목 연결표(`.meeting_links.json`)에만 있는 이름 | 프로젝트가 아니다(`groupNames`는 업무·회의만 센다) — 원래 프로젝트로도 대상으로도 고를 수 없다. 원래 프로젝트를 합치거나 지울 때 그 이름을 가리키는 줄은 함께 바뀐다(3-2 ⑤) |
| 6 | 원래 프로젝트에 수동 지라 연결이 있고 대상에도 있음 | 대상 것을 남긴다. 되돌리면 원래 프로젝트에 다시 붙는다 |
| 7 | 대상이 지라 묶음(BBUNDLE) 안의 티켓 | 고른 티켓으로 옮긴다(`moveProject` 그대로). 묶음은 그 티켓을 이미 대표 그룹으로 보므로 화면에서는 묶음 안으로 들어간다 |
| 8 | 대상이 지라 티켓인데 에픽이 아님 | 기존 라우트가 거절 `에픽에만 옮길 수 있어요`. 고르개는 미리 거르지 않는다(지라 계층은 서버가 읽어야 안다) |
| 9 | 주간요약 — 합치기 | 이름 바꾸기·옮기기와 같이 **모든 주**(확정한 주·지난 주 포함)의 소제목이 B로 바뀐다. 같은 주에 A·B 소제목이 다 있으면 한 소제목 아래 두 무리가 된다. 사람이 고친 소제목 이름은 B에 이미 있으면 **B 것을 남긴다**(`moveNames` 기존 규칙), A의 이름은 옛 열쇠에 남아 쓰이지 않는다 |
| 10 | 주간요약 — 지우기 | 저장본을 건드리지 않는다. 지난 주·확정한 주는 그때 쓴 기록 그대로 A 소제목으로 남는다. 이번 주 확정 전 문장 중 **사람이 손대지 않은 줄**은 다음 모으기에서 업무를 따라 `프로젝트 없음`으로 가고, 사람이 고친 줄은 A 소제목에 남는다(정리 막대 `프로젝트 옮기기`로 옮긴다). 되돌리기가 단순하고 지난 보고를 바꾸지 않으려는 선택 |
| 11 | 되돌리기 전에 다른 변경(그 항목을 다른 프로젝트로 옮김·지움·회의 연결 바꿈) | 기록된 id가 **지금도 합친 뒤 모양일 때만** 되돌리고 나머지는 건너뛰어 `skipped`로 센다(옮기기 되돌리기와 같다). 알림에 `그 사이 바뀐 N개는 그대로 두었어요` |
| 12 | 지운 뒤 같은 이름으로 새 프로젝트를 만들고 되돌림 | 되돌린 항목이 새 프로젝트에 합류한다(같은 이름 = 같은 프로젝트). 막지 않는다 |
| 13 | 지운 프로젝트의 항목이 휴지통(`.trash.json`)에 있음 | 휴지통은 바꾸지 않는다. 되살리면 옛 이름을 달고 돌아와 그 프로젝트가 다시 선다(지금 이름 바꾸기와 같은 한계) |
| 14 | 되돌리기를 두 번(알림 버튼 + ⌘Z) | 기록은 한 번 쓰면 지워져 두 번째는 `되돌릴 기록이 없어요`. 화면은 둘 중 하나가 끝나면 다른 쪽을 막는다 |
| 15 | 기록 20개를 넘김 | 오래된 기록부터 지워져 그 되돌리기는 `되돌릴 기록이 없어요` |
| 16 | 서버 꺼짐·요청 실패 | 아무것도 바뀌지 않는다. 기존 `request()` 실패 알림. 파일을 직접 고쳐 우회하지 않는다 |
| 17 | 복구 필요 상태 | 다른 쓰기와 같이 503 |
| 18 | 옛 설치(`.workflow.json`에 `projectMerges` 칸 없음) | 처음 합칠 때 칸을 만든다. 데이터 형식 번호는 올리지 않는다. 옛 앱으로 되돌아가도 그 칸은 쓰지 않을 뿐이라(옮기기 기록과 섞지 않음) 데이터가 상하지 않는다 — 되돌리기만 못 한다 |
| 19 | 같은 요청이 두 번 감(빠른 두 번 누름·재전송) | `idempotent` 요청 id로 한 번만 실행 |
| 20 | 업무 줄에 id가 없음(아주 옛 줄) | 되돌릴 수 없으므로 합치기·지우기 전에 서버가 거절 `id가 없는 항목이 있어 되돌릴 수 없어요` — 그런 줄이 실제로 있는지 구현 전에 한 번 확인한다(없으면 이 검사는 안전장치로만 남긴다) |
| 21 | 새 프로젝트 화면에서 지라 캐시가 아직 비어 있음(첫 읽기 전) | 감지 못 하고 지나간다. 서버 막기(3-3)도 같은 캐시라 같은 한계 |

## 5. 하지 않는 것

- 지라 에픽 지우기·숨기기(DECISIONS 164 "사람이 영구히 숨기는 길은 없다"는 지라 쪽 그대로).
- 지라끼리 합치기(같은 요약 에픽 둘) — 기존 `다른 티켓과 묶기…`로 안내.
- 여러 프로젝트를 한 번에 합치기·지우기.
- 지라 에픽을 직접 만든 프로젝트로 합치기(지라 → 그룹 방향).
- 이름 바꾸기를 ⌘Z 대상으로 만드는 일(지금처럼 알림 되돌리기만 — 다음 버전 후보).
- 휴지통 항목의 프로젝트 이름 바꾸기.

## 7. 시험 목록

서버(`server.core.test.js`·`server.jira.test.js`, 임시 폴더 데이터만):

1. 그룹 → 그룹 합치기: 업무 넷(끝낸 항목 포함)·아이디어 `project:`·회의·`.meeting_links.json`·주간요약이 한 요청에 바뀌고 원래 프로젝트가 `groupList`에서 사라진다.
2. 합치기 되돌리기: 기록된 것만 원래대로, 그 사이 다른 프로젝트로 옮긴 항목은 건너뛰고 `skipped`에 센다.
3. 지우기: 항목 칸이 비고 회의 프로젝트가 비고 연결표 줄이 지워지며 `.report-drafts.json`은 바이트 그대로. 되돌리면 모두 돌아온다.
4. 수동 지라 연결이 둘 다 있을 때 대상 것을 남기고, 되돌리면 원래 것이 다시 붙는다.
5. 거절: 지라 프로젝트를 원래로, 자기 자신, 없는 대상, `to`가 `jira:`, 모르는 프로젝트 — 모두 어떤 파일도 바꾸지 않는다(파일 지문 비교).
6. 중간 실패(예: 주간요약 쓰기에서 throw) 때 업무 파일까지 전부 원래대로(저널).
7. 같은 요청 id 두 번 → 한 번만.
8. 되돌리기 두 번 → 두 번째는 `되돌릴 기록이 없어요`.
9. `projectMerges` 칸이 없는 옛 `.workflow.json`에서 시작해도 된다. `projectMoves`와 섞이지 않는다(`move-undo`에 합치기 id를 주면 거절).
10. 주간요약: 같은 주에 A·B 소제목이 다 있을 때 B 소제목 이름을 남긴다. 확정한 주도 바뀐다.
11. `/api/jira/create`: 새 에픽 요약이 지라 요약·별칭과 같으면 409이고 지라 가짜 서버에 요청이 하나도 가지 않는다. 그룹 이름과 같으면 통과. 밑줄은 공백으로 나간다.

화면(`client.test.js`, 필요하면 `browser-fixture.js`):

12. ⋯: 그룹 프로젝트에 `다른 프로젝트로 합치기…`·`프로젝트 지우기`가 있고 지라 프로젝트에는 없다.
13. 고르개에 자기 자신·`프로젝트 없음`·`직접 입력`이 없고, 지라를 안 쓰는 설치에서는 지라 프로젝트가 없다.
14. 합치기·지우기 뒤 ⌘Z가 되돌리기 요청을 보내고, ⇧⌘Z가 같은 요청을 다시 보낸다. 기존 옮기기도 ⌘Z에 오른다.
15. 새 프로젝트 화면 표 2-1의 다섯 줄 — 특히 `지라 없이`에 `만든 뒤 이 에픽으로 옮기기`가 다시는 뜨지 않는다, 지라와 같은 이름이면 만들기 버튼이 막히고 `열기`가 그 프로젝트를 연다.

17. 미리 보기·보낸 계획의 에픽·하위 제목에 밑줄이 없다.

## 8. README · DECISIONS 고칠 곳

| 기존 결정 | 바뀌는 점 |
|---|---|
| DECISIONS 157 (그룹 이름 바꾸기, 한 트랜잭션) | 그대로. 겹치는 이름은 계속 거절하고, 대신 **합치기**가 같은 여섯 자리를 한 트랜잭션으로 바꾸는 길이 생김 |
| DECISIONS 164 (사람이 영구히 숨기는 길은 없다) | 지라 쪽은 그대로. 직접 만든 프로젝트는 `프로젝트 지우기`로 항목을 `프로젝트 없음`으로 돌려 없앨 수 있음(숨기기가 아니라 소속을 푸는 것, 되돌리기 있음) |
| DECISIONS 170 (그룹 → 에픽 옮기기, 알림의 되돌리기로만, 같은 이름일 때만 묻기) | ⌘Z로도 되돌림. 같은 이름 감지가 지라 에픽 요약·별칭까지 넓어지고, 지라와 같은 이름의 새 에픽·`지라 없이` 프로젝트는 만들지 않음 |
| DECISIONS 158 (새 프로젝트 → 지라 에픽 만들기, ⌘Z 대상 아님) | 그대로. 서버가 같은 이름 새 에픽을 거절하는 막기가 더해짐 |
| DECISIONS 196 (묶기는 지라끼리만) | 그대로. 그룹끼리는 묶기가 아니라 합치기 |
