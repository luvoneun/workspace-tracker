# 동료 맥에서 나온 버그 2건 (1.1.1에 포함)

## 세 줄
- **왜**: v1.1.0을 받은 동료 맥에서 ① Dock 아이콘이 흐릿한 기본 모양으로 보이고 ② 슬랙 카드가 "Failed to authenticate: OAuth session expired…" 영어 오류를 띄우면서 동시에 "Claude Code … 이 맥에는 설치 안 됨"이라고 모순되게 말한다.
- **기대 변화**: 동료 맥에서도 토끼 아이콘이 보이고, Claude 로그인이 만료되면 무엇을 하면 되는지 한국어 한 줄로 안다.
- **성공 기준**: Pillow 없는 맥(가짜 PATH·가짜 python3로 재현)에서도 아이콘 파일이 들어감 · Claude가 `~/.local/bin` 등 흔한 자리에 있으면 "설치됨"으로 읽힘 · 로그인 만료 로그 줄이 한국어 안내로 바뀜 · 테스트 전부 통과(개수 늘어남).

## 시작 전 (필수)
- `git rev-parse --show-toplevel`이 `/Users/luvon/personal` 그 자체면 멈춤. 아니면 `git merge --ff-only 9fb662b`(정리 묶음 2까지 포함된 가지 끝 — main보다 앞서 있다; 실패하면 멈추고 보고). 커밋 금지.
- 이 명세를 worktree의 `docs/정리/2026-09-28-동료-맥-버그-2건.md`로 복사해 둔다.
- 먼저 읽기: `AGENTS.md`(만드는 방식), `DECISIONS.md`, `tracker/inbox-app/automation/app-refresh.sh`, `integrations.js`의 `claudeInstalled`, `server.js`의 `claudeReady`와 자동화 로그 요약(`summary`) 만드는 곳, `automation/run-task.sh`·`slack-capture.sh`가 claude를 찾는 방식(`command -v claude || $HOME/.local/bin/claude` 등), 연동 카드의 슬랙 실패 줄을 그리는 `settings-ui.js`.

## 원인 (조율 세션이 확인)
1. **아이콘**: `app-refresh.sh`가 아이콘 크기별 그림을 만들 때 `python3`의 Pillow(PIL)를 쓰고 실패하면 조용히 넘어간다. 맥 기본 `python3`에는 Pillow가 없다(개발자 맥에만 설치돼 있었음) → icns가 안 만들어져 osacompile 기본 아이콘이 남는다.
2. **"설치 안 됨" 오판**: 서버의 `claudeInstalled()`는 서버 프로세스의 PATH만 본다. launchd로 뜬 서버의 PATH엔 `~/.local/bin`이 없는데, 자동화 스크립트는 `$HOME/.local/bin/claude`까지 찾아 실제로 실행한다 → 스크립트는 claude를 돌리는데 화면은 "설치 안 됨".
3. **영어 오류**: 동료 맥의 Claude Code 로그인이 만료돼 `claude`가 "Failed to authenticate: OAuth session expired and could not be refreshed"를 내고, 그 줄이 그대로 카드에 뜬다.

## 할 일
1. **아이콘 — Pillow 없이도**: 
   - 기본 토끼 아이콘은 **미리 만든 `icons/app.icns`를 저장소에 둔다**(지금 PIL 방식과 같은 둥근 모양으로 만들어 커밋 — 만들 때 이 worktree의 python3에 PIL이 없으면 `sips`+`iconutil`로 만들되, 둥근 모서리는 `icons/icon-512.png`가 이미 가진 모양을 그대로 쓴다). `local/icon.png`(사용자 그림)가 없으면 이 파일을 그대로 복사한다 — python3를 부르지 않는다.
   - 사용자 그림이 있으면: Pillow가 있으면 지금처럼(둥근 모서리), **없으면 맥 기본 `sips`로 크기만 바꿔** iconset을 만든다(둥근 모서리 없음 — 한 줄 안내를 로그에). 어느 쪽도 실패하면 조용히 넘어가지 말고 로그에 `! 아이콘을 만들지 못했어요 — 기본 아이콘으로 둬요` 한 줄.
   - `app-refresh.sh`의 기존 안전장치(스크립트 앱만 교체, 임시 위치에 다 만든 뒤 교체, `rm -rf`는 검사한 정확한 경로만)는 그대로.
2. **Claude 찾기 한 기준**: `claudeInstalled()`가 PATH에 더해 자동화 스크립트와 **같은 자리들**(`$HOME/.local/bin/claude`, nvm 최신 bin, `/opt/homebrew/bin`, `/usr/local/bin` — 스크립트가 실제로 보는 목록과 일치시킬 것)을 본다. 스크립트 쪽 목록과 어긋나지 않게 한곳에 적고(주석으로 서로 가리키기) 테스트로 고정.
3. **Claude 로그인 만료 안내**: 자동화 로그의 실패 줄 중 Claude 인증 실패(예: `Failed to authenticate`, `OAuth session expired`, `Invalid API key`, `Please run /login` 등 — 실제 문구 여러 개를 정규식으로)를 알아보면 카드의 실패 이유를 `이 맥의 Claude Code 로그인이 풀렸어요 — 터미널에서 claude를 열고 /login 해 주세요`로 바꾼다(원문은 `⋯ › 최근 기록`에 그대로). 이 경우 버튼은 `다시 시도` 그대로(토큰 문제가 아니므로 `다시 연결`로 바꾸지 않는다). 슬랙·캘린더(Claude)·회의록 카드 공통.
4. 도움말 FAQ 한 줄: "Claude Code 로그인이 풀렸다고 나와요" → 터미널에서 `claude` → `/login`.

## 예외 상황
- Pillow도 `sips`도 없는 경우(가짜 PATH) → 기본 icns 복사는 되고, 사용자 그림일 때만 로그 한 줄.
- 사용자 그림이 JPEG → sips로 PNG 변환 후 진행.
- 로그인 만료 문구가 다른 오류와 섞인 줄 → 인증 실패로 판단되는 줄이 **가장 최근 실패**일 때만 안내로 바꾼다.
- claude가 여러 자리에 있을 때 → 하나라도 있으면 설치됨.
