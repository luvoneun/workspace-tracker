## 배운 것
1. **개발자 맥에서만 시험하면 문제가 가려진다.** 만드는 사람의 맥은 nvm·개발 도구·관리자 권한·크롬 위치가 다 맞아 있었다. 배포 전 **새 사용자 계정(보통 맥)** 에서 설치 → 연동 → 수집까지 한 번 돈다.
2. **추정으로 큰 변경을 시작하지 않는다.** 먼저 1분짜리 구분 테스트(이 결과면 A, 저 결과면 B)로 자른다. 에이전트·Claude가 스스로 말한 원인은 특히 의심한다.
3. **말없는 실패가 시간을 가장 많이 먹는다.** `set -e` 스크립트의 조용한 종료, "성공"으로 찍히는 실패. 실패는 크게, 기록에는 버전을.
4. **안내 문구는 지금 실제 화면 기준으로.** 기억한 화면(버튼 이름, macOS 동작)은 바뀐다. 동료가 막힌 문장이 곧 고칠 문장이다.
5. **작게 자주 배포.** 문제 하나에 패치 하나면 동료는 업데이트 버튼만 누르면 된다.
6. **세션이 둘이면 합치는 쪽은 하나.** 겹치는 파일은 미리 알린다.
